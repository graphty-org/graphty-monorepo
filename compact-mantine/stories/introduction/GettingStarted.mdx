# compact-mantine

Compact components and a compact theme for [Mantine 8](https://mantine.dev), for interfaces
where screen space is the scarce resource: property panels, inspectors, sidebars, editors and
dashboards. The look is measured from the Figma editor's own interface, in its light and its
dark theme: 24px controls, 11px Inter, Figma's colors, radii, shadows and timing.

The package gives you two things, and you can take either one on its own.

**A theme.** Put `compactTheme` into your `MantineProvider` and the Mantine components render
dense and Figma-accurate, with no `size` prop anywhere in your code. The theme ships its own
typeface and stylesheet.

**A component library.** Components built for a narrow column and the editor around it: rows
that fit a value and its label on one 32px line, charts the height of a line of text, a
virtualized data table, a floating-panel system, a layer tree, and the editor shell -- a
floating toolbar with tool flyouts, a navigation rail, a quick actions palette and a keyboard
shortcuts sheet.

## Install

```bash
npm install @graphty/compact-mantine @mantine/core @mantine/hooks
```

`@mantine/core`, `@mantine/hooks`, `react` and `react-dom` are peer dependencies, so you choose
their versions: React 18 or later, Mantine 8 or later.

## Switch it on

Import Mantine's stylesheet and hand `MantineProvider` the compact theme. That is the whole
setup: the theme puts its own stylesheet (the Inter typeface, the color tokens and the component
rules) into `document.head` when it is created, so there is no second CSS import.

```tsx
import "@mantine/core/styles.css";

import { Button, MantineProvider, TextInput } from "@mantine/core";
import { compactTheme, ControlSection, FieldRow, PanelField, ToggleRow } from "@graphty/compact-mantine";

export function App() {
    return (
        <MantineProvider theme={compactTheme}>
            {/* Ordinary Mantine components, now rendered compact. */}
            <TextInput label="Project name" />
            <Button>Save</Button>

            {/* This package's own components, for a 240px panel. */}
            <div style={{ width: 240 }}>
                <ControlSection label="Node size">
                    <FieldRow>
                        <PanelField label="Smallest" glyph="sizeSmallest" defaultValue="1.0" />
                        <PanelField label="Largest" glyph="sizeLargest" defaultValue="4.0" />
                    </FieldRow>
                    <ToggleRow label="Scale with zoom" defaultChecked />
                </ControlSection>
            </div>
        </MantineProvider>
    );
}
```

## Light and dark

Light and dark are Mantine's own color scheme: `defaultColorScheme`, `forceColorScheme` and
`useMantineColorScheme` work as they always do, and one theme object serves both.

```tsx
<MantineProvider theme={compactTheme} defaultColorScheme="auto">  {/* follow the OS */}
<MantineProvider theme={compactTheme} forceColorScheme="dark">    {/* always dark */}
```

Every color is a CSS custom property (`--cm-bg`, `--cm-text-secondary`, `--cm-bg-brand`, ...)
written with `light-dark()`, so it follows the `color-scheme` of whatever element uses it.
Menus, list boxes, tooltips and the toast render dark in both schemes, as Figma's do. The
[Color](?path=/docs/foundations-color--docs) page shows every token in both schemes.

## Exact Figma, or WCAG 2.2 AA

`compactTheme` is exact Figma, and a few of Figma's own colors fall short of WCAG 2.2 AA:
secondary text, placeholder text, field and checkbox edges, the focus ring on white, and white
text on the blue, red and green fills. Create the theme with `highContrast` to move exactly those
tokens to the next darker color in Figma's palette. Nothing moves or resizes.

```tsx
import { createCompactTheme } from "@graphty/compact-mantine";

<MantineProvider theme={createCompactTheme({ highContrast: true })}>
    <App />
</MantineProvider>;
```

`createCompactTheme()` with no options is the same as `compactThemeOverride`, and the options it
was built with are on `theme.other.compact`. One page renders one contrast mode: two providers
with different settings on the same page are not supported.

## The bundled typeface

The theme sets Inter (the variable font, latin subset) and ships it inlined into its stylesheet,
so Figma's 450, 550 and 600 weights render exactly with no font setup and no network request.
Inter is licensed under the SIL Open Font License 1.1; the license text is in
`dist/fonts/LICENSE-Inter.txt`. To use another face, set `fontFamily` in a theme merged over this
one (see [Customizing the theme](?path=/docs/introduction-customizing-the-theme--docs)).

## Three optional wrappers

Nothing is required beyond the theme. Three wrappers exist, each needed only for what it names:

| Wrapper | Put it | Needed when |
|---|---|---|
| `Tooltip.Group` (Mantine's) | once, around the whole app, no props | you want Figma's tooltip timing: the first tooltip opens after 1000ms, and for 300ms after one closes the next opens at once. Do not nest a second group inside. |
| `PopoutManager` | once, near the root, above anything that opens a pop-out | you use `Popout` or `PopoutButton`, or `CompactColorInput` (its picker is a pop-out). Without it those throw on first render. `InfoCircle` supplies its own if there is none. |
| `LabelsProvider` | anywhere; providers nest | you translate the library's strings or format numbers for a locale. See [Languages and direction](?path=/docs/introduction-languages-and-direction--docs). |

```tsx
import { MantineProvider, Tooltip } from "@mantine/core";
import { compactTheme, LabelsProvider, PopoutManager } from "@graphty/compact-mantine";

<MantineProvider theme={compactTheme}>
    <Tooltip.Group>
        <PopoutManager>
            <LabelsProvider locale="de-DE">
                <App />
            </LabelsProvider>
        </PopoutManager>
    </Tooltip.Group>
</MantineProvider>;
```

## How this Storybook is organized

The sidebar has five sections, in the order a new reader needs them:

- **Introduction** -- these pages: setup, [choosing a component](?path=/docs/introduction-choosing-a-component--docs),
  [customizing the theme](?path=/docs/introduction-customizing-the-theme--docs), languages and direction, the event and
  prop conventions, accessibility, and [upgrading to 0.9](?path=/docs/introduction-upgrading-to-0-9--docs).
- **Foundations** -- what the theme sets: color, type, spacing and the panel grid, elevation,
  focus and motion, and the glyphs.
- **Components** -- this package's own components, grouped by the job you are doing: panels and
  rows, inputs, selection, color, actions, overlays, lists and trees, data display, and the app
  shell. Each group opens with an Overview page that says when to reach for which.
- **Patterns** -- whole settings panels assembled from the components.
- **Themed Mantine** -- Mantine components the theme restyles but does not wrap, so you can see
  that they fit. Their props are Mantine's; each page links to mantine.dev.

Every component has one page. It opens with what the component is for and when to use it
instead of its nearest alternative, then a `Default` example whose props you can edit in the
Controls table, then a `States` story showing every state in light and dark side by side, then
the feature stories, the keyboard, and the key measurements.

The toolbar above every story has three switches, and every component is built for all of them:

| Toolbar | What it switches |
|---|---|
| **Theme** | light or dark (a `States` story always shows both) |
| **Contrast** | exact Figma, or the WCAG AA token set (`createCompactTheme({ highContrast: true })`) |
| **Direction** | left to right, or right to left (Mantine's `DirectionProvider`) |

Storybook runs axe-core against every story; the **Accessibility** panel under a story lists any
violation.
