# What graphty's built-in agent could do: a brainstorm of use cases

graphty is a graph (network) visualization and analysis product: a web app around a web
component that loads node and edge data from many file formats, draws it in 2D, 3D and VR/AR,
runs about 60 graph algorithms and about 20 layouts, styles nodes and edges through layers,
filters, selects, annotates, saves projects and exports images and files. It has a built-in AI
agent that can already operate every function of the UI.

This document is a blind brainstorm of what that agent could do once it also has the tools
agents generally have: web search and fetch, reading and writing files, calling APIs and MCP
servers with the user's consent, running code, writing documents, seeing screenshots, speaking
and listening, scheduling, remembering, and coordinating sub-agents. Nothing here is a
commitment, a plan or a priority order. Ideas were not filtered for cost, feasibility or the
current implementation, and none were dropped for their risks; the risks are noted instead.

The seven starting examples are all in here: cleaning data by iterating over it (section 3),
searching the web for datasets and joining them (section 4), turning web pages and personal
exports into graphs such as a friend-of-a-friend map or a purchases graph (sections 5 and 6),
exporting results as artifacts and converting them into a paper or a presentation (section 12),
filing a bug report (section 14), and answering questions from the help files (section 14).

How to read an entry: the **title**, then who it is for and what they get, then how the agent
does it, naming the outside capabilities it needs. _Concerns_ are privacy, consent, safety or
accuracy risks in a few words. _(speculative)_ marks ideas that depend on capabilities that are
unproven, unreliable today or far beyond the current product. In section 17, _(misuse to name)_
marks harms the agent must refuse; they are listed so the product can be designed against them.

## 1. Finding and fetching data

Getting a graph when the user has a topic, a site, a database or an API, but no file.

- **Find me a graph about X** -- A student, journalist or curious reader with a topic gets two or three candidate datasets loaded side by side, each with a card for source, license, size and what the nodes and edges mean. The agent searches dataset portals (Kaggle, Zenodo, data.gov, SNAP, KONECT, Hugging Face), downloads the small ones, sniffs the format and runs quick counts for the cards. _Concerns:_ license terms, download size, stale mirrors.
- **Wikipedia list or category to graph** -- A hobbyist or teacher gets a graph from a Wikipedia list, such as Nobel physics laureates and who advised whom, with photos and dates. The agent follows each entry to Wikidata, extracts the chosen relation and styles nodes by decade. _Concerns:_ Wikidata gaps make the graph look sparser than reality.
- **Plain-English SPARQL pulls** -- A researcher who does not know SPARQL asks for "EU acquisitions since 2000" and gets the graph plus the query that made it. The agent writes SPARQL for Wikidata or DBpedia, shows the row count first and pages through public endpoints. _Concerns:_ timeouts, incomplete coverage.
- **Scrape a site's link structure** -- An SEO specialist or site owner gets a graph of pages and internal links with orphans, dead links and redirect chains flagged. The agent crawls the domain with a headless browser, within robots.txt and a page cap, then runs PageRank and components. _Concerns:_ crawl only sites you may crawl.
- **Pull a graph from a database, warehouse or graph store in plain language** -- An analyst asks for "suppliers two hops from our top five customers" and gets a drawn, refreshable graph without writing a query. The agent connects with the user's read-only credentials, reads the schema, writes SQL, Cypher or Gremlin for approval, samples first and stores the query on the project. _Concerns:_ credentials; expensive scans on production; writes off by default.
- **Stakeholder map from a brief** -- Advocates, consultants and campaign planners get the players on an issue with influence and alignment, allies and opponents styled apart. The agent researches the issue on the web, extracts people and organizations, and asks the user to confirm alignment. _Concerns:_ labeling real people as opponents; cite sources.
- **Build a data-source connector** -- Someone whose data lives in Zotero, Jira, a SQL database or another unsupported API gets a reusable connector that loads and refreshes it. The agent reads the API docs, writes a data-source plugin against graphty's extension API and tests it with the user's own token. _Concerns:_ the token must never land in a shared project.

## 2. Turning documents, media and conversation into graphs

Extracting nodes and edges from unstructured material: PDFs, document piles, photos, transcripts, interviews and the agent's own conversations.

- **PDF or scanned document to graph** -- A historian, lawyer or auditor gets an org chart from an annual report or an ownership chart from a filing. The agent runs OCR and a vision model over tables and box-and-arrow diagrams, attaches the page and an image snippet to every edge, and asks about low-confidence ones. _Concerns:_ OCR errors become false edges.
- **Document pile to sourced entity graph** -- A journalist or paralegal with a leak or discovery production gets people, companies, addresses and accounts linked by paid, director-of or wrote-to relations, every edge tied to its source sentence. Parallel sub-agents run OCR, entity and relation extraction and resolve entities across documents; the reporter verifies key edges. _Concerns:_ defamation from wrong links; sensitive material stays offline.
- **Schema-guided extraction** -- An analyst building a knowledge graph from text gets extraction held to node and edge types they approved, so relation types do not sprawl. The agent proposes a schema from a sample, accepts edits and runs constrained extraction.
- **Community summaries of a corpus** -- A policy analyst with thousands of documents asks "what are the main themes?" and gets an answer built from the graph. The agent runs community detection on the document graph, has a language model summarize each community and stores the summaries as notes.
- **Text network of a document** -- A writer or student sees an essay or transcript as a concept co-occurrence network with its central ideas and clusters. The agent tokenizes, links words that appear near each other and runs centrality and community detection.
- **Structural-gap research questions** -- A researcher gets pairs of distant clusters with few bridges and proposed questions that would connect them. The agent measures cluster distances in a concept or literature graph and writes candidate questions as notes.
- **Whiteboard, sticky-note or photo to graph** -- A workshop team, teacher or parent with a hand-drawn family tree gets an editable, clustered graph from a phone photo in a minute. A vision model reads boxes, handwriting and arrows, overlays its reconstruction on the photo for spoken corrections and suggests groupings the board missed. _Concerns:_ handwriting misreads; always show the photo beside the result.
- **Printable workshop cards that become a graph** -- A facilitator lays QR-coded cards and strings on a table and turns them into a graph with one photo. The agent prints the cards from a list, reads the photo with vision and asks about ambiguous strings. _Concerns:_ crop faces out of photos.
- **Interview mode graph building** -- Anyone mapping what is in their head (a family, a team, a plot) builds a graph by answering questions in voice or text. The agent asks structured questions, adds nodes as answers arrive, probes for gaps and keeps the transcript as provenance. _Concerns:_ recording facts about third parties.
- **Causal loop diagram from a conversation** -- A systems thinker or manager gets a causal loop diagram with polarities and labeled reinforcing and balancing loops. The agent turns statements into signed causal edges and runs cycle detection.
- **Meeting transcript graphs** -- A team sees who-mentioned-what and who-replied-to-whom across a series of meetings. The agent parses transcripts and links people and topics over time. _Concerns:_ workplace surveillance; aggregate by default.
- **The conversation itself as a graph** -- A user in a long chat with the agent gets a live map of topics, decisions, open questions and tangents; clicking a node jumps back to that moment. The agent segments the transcript into topics and links them by reference and time. _Concerns:_ stores the conversation; allow deletion.
- **Argument maps and claim graphs** -- A policy analyst, lawyer, debate coach or moderator gets the claims, evidence and rebuttals of a hearing or thread as a graph, with load-bearing, single-source and circular claims flagged. The agent fetches the documents, mines claims and support or attack relations, and links every node to its quote. _Concerns:_ misrepresenting speakers.
- **Research team of sub-agents building a knowledge graph** -- A research team mapping a field gets a large, sourced graph in hours with a confidence value on every edge. A lead agent splits the topic, sub-agents research slices on the web in parallel, a reviewer agent deduplicates, and low-confidence areas get another pass. _Concerns:_ hallucinated relations; show sources.
- **Field data collection** _(speculative)_ -- An ecologist building a pollinator network or a contact tracer builds a graph from field photos, voice notes and GPS. The agent identifies species from photos, transcribes notes, attaches place and time and asks for confirmation at the end of the day. _Concerns:_ contact data is highly sensitive.
- **Reconstruct a graph from a figure** _(speculative)_ -- A researcher with only a figure from an old paper gets its nodes, edges and labels back as data. A vision model detects the elements, overlays them on the figure and marks each as "from figure". _Concerns:_ dense figures cannot be recovered.
- **Networks traced from images and terrain** _(partly speculative)_ -- A biologist, geologist or urban researcher gets graphs of blood vessels, neurons, rivers, cracks or roads with branching statistics. The agent runs segmentation and skeletonization in code on images, elevation models or satellite tiles and converts the skeletons to nodes and edges. _Concerns:_ segmentation errors propagate; show overlays.
- **Voice interviews to collect network survey data at scale** -- A researcher or health worker studying who trusts whom gets a network built from short phone interviews in each respondent's language. The agent schedules calls, reads the consent script, asks name-generator questions, resolves spoken names against a roster and shows where coverage is thin. _Concerns:_ consent, voice recordings, minors; disclose that an AI is calling.
- **Screen recording to a map of how work actually flows** -- An operations team hunting for automation gets a process graph of apps, screens and hand-offs, with slow loops and copy-paste paths highlighted. The agent watches recordings with vision, labels each step, merges steps across recordings and runs bottleneck analysis. _Concerns:_ recordings show private data; employee surveillance.

## 3. Cleaning and repairing data

Making messy or broken data usable, with the user approving every change that matters.

- **Schema inference for unknown files** -- Anyone with a CSV of unknown shape learns whether it is an edge list, node list, matrix or wide table and what each column means. The agent samples the file, guesses roles, explains its guess in one sentence before loading and accepts corrections.
- **Bipartite to one-mode projection** -- A sociologist or marketer turns a people-by-events table into a person-to-person graph weighted by shared events. The agent recognizes the two-mode shape, asks which side to keep and offers a threshold. _Concerns:_ projection inflates density.
- **Fix types column by column** -- Anyone whose numbers loaded as text gets currency, "1.2k" and "n/a" parsed, zip codes kept as strings and booleans unified. The agent profiles each column, proposes a rule, shows the failing rows and keeps originals recoverable. _Concerns:_ decimal-comma locales.
- **Date and time normalization** -- A historian or log analyst gets one date format and time zone so the time slider works. The agent resolves day/month order from unambiguous rows, handles epochs and "circa 1850s", and flags impossible dates while keeping originals.
- **Unit and currency normalization** -- A supply-chain or energy analyst gets edge weights in one unit and currencies converted at each transaction date's rate. The agent fetches historical rates from an exchange-rate API and records the source.
- **Format conversion with a loss report** -- A researcher moving data between graphty, Gephi, Cytoscape, NetworkX and Neo4j gets the converted file plus a list of what did not survive. The agent round-trips each candidate format, diffs it against the original and recommends the least lossy one.
- **Repair a file that will not load** -- Anyone with a broken import gets a loaded graph and a list of fixes: bad quotes, mixed delimiters, invalid XML, mojibake, duplicate ids, edges to missing nodes. The agent reads the parser's error, repairs a copy in a scripting sandbox, re-imports and offers to file a bug if graphty is at fault. _Concerns:_ never modify the original or drop rows silently.
- **Duplicate node detection and merging** -- Anyone combining sources gets "J. Smith", "John Smith" and "Smith, John" merged with their edges. The agent clusters candidates by name similarity and shared neighbors, ranks them and keeps an undoable merge log. _Concerns:_ merging real namesakes.
- **Edge cleanup** -- Self-loops, duplicates, reversed duplicates and dangling edges handled by one policy the user picks (drop, sum weights, keep a multigraph). The agent counts each kind and explains it before asking.
- **Data quality report before analysis** -- An analyst about to present gets one page on missing values, isolates, the giant component, junk hubs and outliers, and how each skews the planned algorithms. The agent profiles the data and writes the report into the project notes.
- **Placeholder, junk-hub and artifact detection** -- Anyone with CRM, email or transaction exports is warned that "your top hub is Unknown" before it becomes a finding. The agent checks hubs against placeholder patterns and impossible values and removes them only on approval. _Concerns:_ a real hub is not junk; always ask.
- **Domain-rule consistency checks** -- A genealogist or engineer states rules in plain English ("no one is their own ancestor", "no arrival before departure") and gets the violators selected. The agent turns each rule into a cycle, degree or date check.
- **Validate against a schema or standard** -- A team with a data contract or a scientist using a community format gets every violation listed and selectable. The agent turns a JSON Schema, ontology, SHACL shapes or a plain description into checks.
- **Knowledge-graph consistency and curation** -- A data steward gets duplicates, orphan classes, contradictions and missing inverse relations with suggested fixes. The agent queries the graph database or triple store, runs the checks and writes back only approved fixes. _Concerns:_ write-back must be reviewable and reversible.
- **Iterative cleaning loop with a human** -- Anyone with a large messy dataset cleans it problem by problem, with similar decisions batched (140 country names to ISO codes) and previewed on samples. The agent queues issues from the quality report and records the session as a replayable recipe.
- **Replayable cleaning recipe** -- A team that gets the same messy export every month applies last month's cleaning in one click or on a schedule. The agent stores the steps as data, reruns them and reports new unmatched values.
- **Translate and transliterate labels** -- A researcher with multilingual sources gets labels in one language with originals kept and cross-script duplicates merged. The agent detects script and language, uses a translation service and prefers Wikidata labels when an id exists.
- **Standing graph steward and dataset curator** _(partly speculative)_ -- A team sharing a living graph gets ongoing hygiene; an open-data community gets a public graph rebuilt weekly with a changelog. The agent runs scheduled checks, fixes safe issues, asks owners about the rest in chat and versions every change; for publishing, one sub-agent per source and quality gates that hold bad releases. _Concerns:_ automated edits to shared data.
- **Cleaning in VR by voice and pointing** _(speculative)_ -- An analyst in a headset points at two nodes and says "these look like the same company"; the agent checks the evidence and merges them on a spoken yes, using speech recognition and synthesis.
- **Tag taxonomy from a messy folksonomy** -- A blogger, librarian or archive curator sees every tag linked by co-occurrence, with synonyms, misspellings and orphans, and a proposed clean hierarchy. The agent exports tags through a CMS or library API, clusters them, proposes merges and broader terms, and writes approved changes back. _Concerns:_ bulk rewrite of a live site; keep a rollback.

## 4. Enriching, joining and tracking where data came from

Adding facts from outside, linking to authorities, and keeping a trustworthy record of origin, license and privacy.

- **Fuzzy-key join of graph and spreadsheet** -- An analyst attaches a spreadsheet's columns to the right nodes despite name mismatches. The agent normalizes names ("Inc.", "Ltd"), matches exactly then fuzzily and shows the unmatched rows on both sides.
- **Search the web for a dataset to join** -- A policy analyst with a country trade graph gets population, GDP and income group for the right year. The agent maps names to ISO codes, fetches World Bank, UN or OECD data and records the source and version of every attribute. _Concerns:_ disputed territories.
- **Entity resolution against an authority** -- A librarian, scientist or compliance officer gets every node linked to a stable id (Wikidata, ORCID, ROR, LEI, UniProt, GeoNames). The agent queries the authority APIs, auto-accepts clear matches and queues ambiguous ones. _Concerns:_ wrong matches look authoritative.
- **Geocode places** -- Anyone with addresses gets coordinates, country and region on every node for a geographic layout. The agent uses a geocoding API, disambiguates by neighbor context (Paris, Texas) and flags low confidence. _Concerns:_ home addresses are sensitive.
- **Enrich companies and organizations** -- A due-diligence analyst gets parents, subsidiaries, sector and officers, with related companies added and tagged. The agent queries OpenCorporates, EDGAR, Companies House and GLEIF. _Concerns:_ officer data is personal.
- **Snowball expansion from a selection** -- A researcher grows the graph one or two hops from the selected nodes through an outside source, within a budget. The agent ranks candidates by their links to existing nodes and records each node's hop count. _Concerns:_ explosive growth.
- **Fill missing attributes from the web with citations** -- Blank founding years or birth dates get filled, each with a citation. The agent searches the web and accepts a value only when two sources agree, leaving the rest blank with a reason. _Concerns:_ hallucinated values.
- **Proposed missing edges as a separate layer** -- An analyst with an incomplete network sees likely missing edges drawn dashed, never merged into the data until accepted. The agent runs link prediction, checks top candidates against outside evidence and tags each with it. _Concerns:_ inferred edges presented as fact.
- **Provenance on every node and edge** -- A journalist or scientist who must defend a graph clicks any element to see its source row or URL, the cleaning applied, who made it and who approved it. The agent writes provenance at every import and fix, archives fetched pages and generates a provenance appendix for exports.
- **Source conflict resolution** -- Anyone merging sources that disagree gets a list of conflicts per attribute and a chosen policy (trust A, newest wins, majority, keep both), with losing values kept.
- **Licensing, attribution and citation credits** -- Anyone publishing a graph built from others' data gets each source's license, flagged conflicts, an attribution paragraph and a CITATION.cff file. The agent records licenses at import and looks up dataset pages on the web. _Concerns:_ not legal advice.
- **Privacy scrub and policy guardrail before sharing** -- A researcher or HR analyst about to share personal data gets a safer copy offered: pseudonyms, contacts removed, rare combinations generalized, a re-identification warning. The agent classifies personal columns, checks the destination against policy and runs k-anonymity and structural-uniqueness checks. _Concerns:_ structural re-identification is hard to rule out.
- **Data dictionary and datasheet** -- Anyone handing over or publishing a dataset gets a document describing every type and attribute plus a datasheet on collection, biases and intended use. The agent profiles the data, asks only about unclear columns and can upload to a data repository.
- **Data access broker that negotiates for a dataset** -- A researcher who found a gated or paid dataset gets access on acceptable terms, with license and cost recorded on the project. The agent drafts the request or talks to the provider's agent by email or API, compares terms against the user's budget and rules, and escalates the rest. _Concerns:_ spending money or agreeing to terms needs hard caps and confirmation.
- **Ask the people in the graph to confirm it** -- Anyone with an inferred org chart, supplier map or family tree gets edges marked confirmed, corrected or disputed by the people they describe. The agent drafts short questions by email, form, chat or phone, sends them on approval, parses replies and shows which conclusions changed. _Concerns:_ contacting people about data they did not know existed; disclose it is an agent.
- **Send corrections back to the open data the graph came from** -- A user who found errors in Wikidata, OpenStreetMap, MusicBrainz or OpenAlex while building a graph sends them back as proposed edits with evidence. The agent turns accepted fixes into each project's edit format, shows the batch for approval and submits under the user's account. _Concerns:_ community bot policies; wrong mass edits harm a shared resource.

## 5. Your own life as a graph

Personal data the user already owns (exports, mail, calendar, photos, notes, family records) turned into graphs of their own relationships and history. Almost everything here involves other people's data, so keeping it on the device is the default.

- **Your own accounts as graphs** -- Anyone curious about their digital life gets a contacts graph from email headers, a purchases graph, a listening graph or a travel graph. The agent walks the user through downloading their own export (Google Takeout, Facebook, Amazon, Spotify) instead of logging in for them, then parses the mixed JSON, CSV and HTML. _Concerns:_ third parties never consented; keep it local.
- **Friend-of-a-friend map from social media exports** -- Anyone curious about the shape of their social life gets a 3D map of friends colored by community (school, work, family, hobby) with bridging friends highlighted. The agent parses a Facebook, LinkedIn or Instagram data download, runs community detection and names the clusters by asking about a few members. _Concerns:_ other people's data.
- **Who have I lost touch with?** -- A busy professional sees the groups they bridge, people they once wrote to often but not in a year, and drafts of reconnect notes. The agent reads mail and calendar headers only, through a mail connector, and compares tie strength year over year. _Concerns:_ highly sensitive; never auto-sent.
- **Calendar time map** -- A manager, freelancer or parent sees who they spend meeting time with and which recurring meetings connect them to no one new. The agent reads the calendar API and writes a one-page review proposing meetings to drop. _Concerns:_ company policy on work calendars.
- **Group chat dynamics** -- A friend group or club sees who replies to whom, who starts threads and who goes unanswered, month by month. The agent parses a WhatsApp, Signal or Discord export and writes a gentle summary. _Concerns:_ other members did not consent; results can hurt feelings.
- **Gift and favor ledger** -- Someone with a big family tracks who gave what to whom, upcoming birthdays and uneven reciprocity. The agent builds the ledger from notes and past orders, remembers interests across sessions and suggests gifts through shopping search.
- **Job search warm-intro paths** -- A job seeker gets the shortest paths through their contacts to people at target companies, ranked by tie strength, with intro requests drafted. The agent imports LinkedIn and email contacts and looks up public role information. _Concerns:_ prefer exports over scraping.
- **Wedding or party seating planner** -- A couple gets table assignments that keep friend groups together and feuding relatives apart, plus a printable chart and place cards. The agent runs community detection constrained to table sizes with must-not-sit-together edges.
- **Family tree from scattered sources** -- A family historian gets one tree merged from GEDCOM files, letters, obituaries, public records and a recorded talk with grandma, with conflicting records flagged. The agent transcribes audio, searches public records, proposes merges with evidence and writes an updated GEDCOM. _Concerns:_ living relatives' privacy.
- **DNA match clustering** -- An adoptee or relative-seeker sees DNA matches grouped into ancestral lines with a guess at which grandparent each belongs to. The agent weights edges by shared centimorgans from testing-service exports and clusters them. _Concerns:_ reveals non-consenting relatives; parentage surprises.
- **Photo co-occurrence graph** -- A family sees who appears with whom across decades, with the best photo for each relationship, ready for a slideshow. The agent reads existing face tags from the photo library. _Concerns:_ biometric data stays on the device.
- **Memoir and life-story graph** -- A retiree writing a memoir gets a graph of events, places and people from journals and letters, and a chapter outline that follows the strongest threads. The agent extracts entities from documents and drafts a sample chapter. _Concerns:_ other people's secrets.
- **Care team map for an aging parent** -- Siblings in different cities get a shareable map of doctors, pharmacies, insurers and neighbors with roles, single points of failure and an emergency sheet. The agent interviews the user and reads letters and bills with OCR. _Concerns:_ health data; family-only sharing.
- **Notes vault, knowledge-base sync and browsing rabbit holes** -- An Obsidian, Notion or Logseq user sees topic hubs, orphan notes, suggested missing links and a replay of how one question led to another. The agent reads the vault or browser history and writes accepted links back after showing a diff. _Concerns:_ private notes and history.
- **Dream and voice-memo journal graph** _(speculative)_ -- Someone who records daily voice memos sees recurring people, places and symbols linked over months, transcribed and analyzed on the device. _Concerns:_ deeply personal; no therapy claims.
- **Life decision what-if** _(speculative)_ -- Someone considering a move sees which friendships, routines and commitments would break or strengthen. The agent combines contacts, calendar and place graphs, removes location-bound ties and writes a balanced memo. _Concerns:_ reduces life choices to metrics.
- **Lifelong personal graph walked in VR** _(speculative)_ -- One continuously updated graph of a person's life, walkable in VR one time slice at a time, with spoken questions. Background connectors feed mail, calendar, photos and location through cross-source entity resolution. _Concerns:_ total self-surveillance; a breach would be catastrophic.
- **Skills and career transition graph** -- A career changer sees occupations linked by shared skills and real job moves, with realistic paths to a target job and courses for the gaps. The agent fetches O*NET or ESCO taxonomies and job-transition statistics. _Concerns:_ projections are not guarantees.
- **What do I call this relative? Kinship beyond the Western family tree** -- Children of immigrants and genealogists working with clan books get a family graph in their own kinship system that answers "what do I call my father's elder brother's wife in Tamil?". The agent reads clan books in the original script, types relations (elder, maternal, co-wife) and translates paths into kin terms. _Concerns:_ caste and clan data can enable discrimination.
- **Live conversation whisperer from your relationship graph** _(partly speculative)_ -- During a call or meeting, an earpiece or glasses prompt says "you met Priya at the 2025 summit; you promised her the dataset". The agent listens with consent, recognizes names, looks them up in the user's contact graph and adds new facts afterward. _Concerns:_ recording laws; never face-recognize strangers.
- **Donate my graph to research** -- Someone who wants to give their network data to science finds studies that accept donations, strips what they choose, and submits with a consent receipt they can later withdraw. The agent reads study consent terms and builds the redacted export. _Concerns:_ friends in the graph never consented.
- **Polycule map and shared calendar** -- People in nonmonogamous relationships see their network with agreements and availability, and can quickly and privately notify the right partners after a health result. The agent links calendars and computes who is within the relevant hops. _Concerns:_ outing risk; each member controls their data.
- **Briefing before each meeting from my relationship graph** -- A founder or fundraiser gets a short brief an hour before each event: who is coming, mutual contacts, last conversation, open promises, one suggested question. The agent reads the calendar on a schedule, pulls memory and sends the brief by email, chat or phone notification. _Concerns:_ detailed data about third parties.
- **Disclosure forms filled from your own graph** -- Someone applying for a security clearance, visa or board seat gets the long relatives, contacts and addresses questionnaire filled from their personal graph, with gaps and contradictions flagged. The agent maps form sections to graph queries and fills the official PDF or web form for the user to submit. _Concerns:_ legal penalties for errors; the user submits personally.
- **Thank-you notes, acknowledgments and toasts from a relationship graph** -- An author, couple or eulogist gets drafts that name the right people for the right reasons and forget no one. The agent finds everyone with a qualifying tie, groups them by community and writes in the user's voice. _Concerns:_ private details in public speeches.

## 6. Everyday life: money, home, health, travel and hobbies

Graphs as a tool for ordinary chores and pastimes.

- **Purchase graph and forgotten subscriptions** -- Anyone wondering where their money goes sees merchants, categories and payment methods as a graph, with unused subscriptions and how to cancel them. The agent imports bank, card and Amazon exports, cleans merchant names and detects recurrence. _Concerns:_ never store credentials.
- **Money flow between my own accounts** -- Someone with many accounts sees transfers among accounts and people, circular movement, fees and idle balances. The agent matches transfer pairs in statements and runs flow and cycle detection. _Concerns:_ no investment advice.
- **Shared expenses settle-up** -- Roommates or a trip group get the fewest payments that settle all debts, with drafted payment requests. The agent reads a shared sheet or receipt photos with OCR and simplifies the debt graph.

## 7. Asking the graph questions: guided analysis and explanation

The agent as an analysis partner: it picks the right method, explains what came back and keeps the user from misreading it.

- **Explain this graph in 60 seconds** -- Anyone opening an unfamiliar dataset gets a spoken or written tour of its size, components, hubs, communities and gaps, each finding one click away, ending with three follow-up questions. The agent runs a fixed descriptive battery, picks the standouts and narrates while moving the camera, with text-to-speech when spoken. _Concerns:_ overclaiming meaning from metrics.
- **Who matters most here, with the right kind of matters** -- A newcomer, such as a journalist with a leaked email graph, gets ranked nodes and a paragraph on which kind of importance was used and why. The agent asks one clarifying question, maps it to degree, betweenness, closeness or PageRank, and shows two measures side by side when they disagree. _Concerns:_ a high score is not proof of wrongdoing.
- **Natural-language queries into selections and filters** -- "Asian single-source suppliers two hops from our top customers" becomes a highlighted subgraph, a saved filter and a table. The agent parses the sentence into attribute filters and hop traversals and echoes the query back in plain words for editing. _Concerns:_ misread queries fail silently.
- **Multi-step analysis from one prompt** -- An analyst's single request chains import, algorithms, labeling and a summary, with every step inspectable and undoable in the history.
- **Algorithm advisor and pre-flight check** -- A data scientist who knows the goal but not the method gets a recommendation (Louvain, Leiden, label propagation) with cost and caveats, and a warning before any run that does not fit the graph. The agent checks the graph's properties against each algorithm's assumptions and can search the web for method comparisons.
- **Why is this node ranked so high?** -- A fraud investigator or auditor gets a plain, path-based explanation of a score with the evidence highlighted and exportable. The agent decomposes the score into its contributing paths, tests how ranks change without the node and finds a minimal explaining subgraph. _Concerns:_ decisions about real people must stay auditable.
- **Name the communities** -- A marketer or historian gets a human label for each community with the evidence behind it. The agent computes which attributes are overrepresented, reads sample node text and can enrich from the web. _Concerns:_ labels can stereotype.
- **Compare two network versions** -- A team tracking an org chart, supply network or merger sees added, removed and rewired nodes, the biggest movers and split or merged communities in one diff view with a written report. The agent matches nodes across versions with entity resolution and paints a diff style layer. _Concerns:_ name mismatches create fake changes.
- **Compare two algorithms' answers** -- A researcher choosing between methods gets an agreement score, a map of the disagreements (often bridges) and a reasoned verdict.
- **Compare my network against references** -- A biologist or organization sees where its statistics fall among random and published networks fetched from SNAP, ICON, Network Repository or STRING.
- **Find the odd nodes** -- A security analyst or auditor gets ranked anomalies, each with a plain reason ("money passes straight through"). The agent computes per-node features and scores outliers in code. _Concerns:_ human review before any action.
- **Ego network on demand** -- Anyone focuses on one node at an adjustable depth, with its own layout.
- **Group by attributes** -- A social scientist gets a nested layout by country, state and city instead of by links.
- **Self-correcting analysis** -- When an algorithm fails, a novice hears why, and the agent repairs the input (for example, takes the largest component) and re-runs.
- **One caveat and one next question after every result** -- Each result in a chat-style analysis comes with one limitation and one suggested follow-up, matched to the graph's properties. _Concerns:_ can nag; let the user dial it down.
- **Say when the graph cannot answer, and what would** -- An honest refusal with a path forward: "without timestamps there is no direction of influence; add dates", with where that data might come from.
- **Curiosity companion that watches you explore** -- A newcomer gets occasional hints about notable things they have not looked at yet. The agent compares local camera and selection history with what the algorithms find notable. _Concerns:_ opt-in; telemetry stays on the device.
- **Any table as a similarity network** -- An analyst with customers, songs, survey answers or documents but no links gets a nearest-neighbor network revealing clusters, bridges and outliers. The agent computes features or embeddings, builds the graph with a stated k and metric and shows how the picture changes with k. _Concerns:_ the network is an artifact of the metric.
- **Correlation networks from time series** -- An investor, climate scientist or plant engineer sees stocks, stations or sensors linked by correlated or lead-lag behavior, and how the structure tightens in a crisis. The agent fetches series from market or sensor APIs, filters with a minimum spanning tree and animates windows. _Concerns:_ spurious correlation; not investment advice.
- **Rankings from who beat whom** -- A league organizer or ethologist gets a ranking from match results or pairwise preferences, with upsets, rock-paper-scissors cycles and confidence per position from resampling.

## 8. Rigor, simulation and what-if

Checking whether a finding is real, and asking what would happen if the network changed.

- **Is my graph the right graph? Modeling check** -- Someone who built a graph from a table without thinking about what an edge means gets a critique (generic keywords making cliques) and a fixed graph. The agent finds edges explained by a few frequent attributes and proposes weighting or backbone extraction.
- **Parameter sweep and sensitivity report** -- A researcher whose result depends on a resolution or damping parameter sees how the result changes across it, with the stable range highlighted. The agent runs a grid and charts similarity between neighboring results. _Concerns:_ compute cost; sample first.
- **Null-model significance testing** -- A social scientist claiming strong clustering gets a z-score against a fitting null model, with the null histogram. The agent generates hundreds of rewired graphs in code and explains what the null controls for.
- **Homophily and assortativity checks** -- A school counselor or political scientist gets effect sizes such as "same-grade friendships occur 4.2 times more than chance", with confidence intervals and a mixing heatmap. _Concerns:_ minors' and political data.
- **Hypothesis notebook with pre-registration** -- A careful researcher records timestamped hypotheses before seeing metrics, runs the planned tests, labels exploratory findings and exports a methods section.
- **Multiple-comparison and data-dredging guard** -- Anyone who asked for "anything interesting" is warned when many tests yielded few hits, and sees corrected values. The agent counts every test in the session.
- **Robustness to missing data** -- A researcher with survey nonresponse learns which conclusions survive 10 to 30 percent missing nodes or edges, from repeated random perturbation.
- **Red-team my analysis** -- A researcher before submission or an analyst before a board meeting gets a critique of sampling, thresholds, layout-driven impressions and seed sensitivity, and a list of which conclusions survive. A skeptical second agent reruns with other seeds, parameters, algorithms and dropped edges.
- **Two agents debate over a graph** -- A policy analyst or student jury watches a pro and a con agent argue a contested question with evidence overlaid on the graph, then a judge scores what survives. _Concerns:_ every claim must be re-runnable.
- **Parallel hypothesis exploration with helper agents** -- An analyst asking why engagement dropped gets competing explanations investigated in parallel by sub-agents and a verdict on which one the data supports.
- **Careful causal sketch from correlations** -- An epidemiologist or economist gets a causal diagram with each arrow labeled by its source (data, literature or assumption) and adjustment sets. The agent runs causal-discovery code and checks arrows against a literature search. _Concerns:_ never present it as proof.
- **Resilience: what breaks if we lose this?** -- A utility planner or site reliability engineer sees single points of failure, removal curves and an interactive remove-a-node mode. _Concerns:_ a dual-use map of weak points; control sharing.
- **Spread simulation: disease, rumors, adoption** -- A public-health student or marketer sees an animated epidemic or cascade model on their network with uncertainty bands and a comparison of seeding strategies. _Concerns:_ a toy model is not a forecast.
- **Cascading failure and systemic risk** -- A grid engineer or financial-stability analyst sees the cascade each node would trigger and a ranking of systemically important institutions, with failure rounds animated. The agent writes and runs a load-redistribution or DebtRank-style model and a stress memo. _Concerns:_ confidential exposures; assumptions dominate.
- **Intervention planner: where to add one edge** -- A community organizer, transit planner or HR lead gets ranked candidate links with their effect on connectivity, previewed as dashed edges. _Concerns:_ employee analysis needs consent.
- **Traffic and routing what-ifs** -- A city planner sees "if this bridge closes, these areas add 12 minutes to the hospital" on a before/after map. The agent imports OpenStreetMap roads, weights by travel time and recomputes. _Concerns:_ not for emergency decisions.
- **Link prediction with a backtest** -- A research librarian or recommender engineer gets likely future links, each with a reason, and an honest accuracy figure from held-out edges. _Concerns:_ predicting personal ties is invasive.
- **Network growth forecast** -- A startup with a referral network gets projected growth with uncertainty bands and a verdict on preferential attachment, fitted in code. _Concerns:_ short histories are fragile.
- **LLM-persona agent-based simulation** _(speculative)_ -- A policy researcher sees opinion spread where each node is a small language-model persona, compared with a classic threshold model. _Concerns:_ simulated people are not real people; cost.
- **Stakeholder panel of simulated personas** _(speculative)_ -- A planner presenting a network plan gets simulated stakeholders who walk the graph and pin objections to nodes and edges. _Concerns:_ no substitute for consulting real people.
- **Counterfactual history** _(speculative)_ -- A history teacher asks which letters and ideas would likely not have spread had one correspondent vanished, answered with time-respecting reachability and a cautious, sourced narrative.
- **Group interactions as hypergraphs** -- A researcher studying meetings, author teams or reactions keeps groups as groups instead of flattening them into pairs, and sees what flattening would have changed.
- **Multi-agent annotation with agreement scoring** -- A social scientist extracting relations from text gets edges coded by several independent sub-agents, an agreement statistic, and disagreements escalated rather than silently resolved. _Concerns:_ correlated model errors look like agreement; keep a human-coded sample.
- **Independent recomputation audit** -- A researcher or journalist about to publish a number gets every headline result recomputed with other graph libraries in code, with differences traced to conventions, and a bug filed if graphty is wrong.
- **Forecast ledger that grades itself later** -- An analyst's predictions from a graph ("these firms will partner") are logged with a date and confidence; months later the agent refetches the sources, checks what happened and reports calibration per method. The agent uses scheduling, memory and scoring code. _Concerns:_ resolution rules must be fixed in advance.
- **Network-aware field experiment designer and runner** -- A public-health team or NGO runs a real experiment assigned so spillover through friendships does not spoil the comparison, with measurement waves and an analysis of direct and spillover effects. The agent designs cluster randomization, runs power calculations, exports assignments to messaging tools and schedules surveys. _Concerns:_ ethics review and consent.
- **Paid human verification of uncertain edges** -- A curator or journalist sends the weakest edges to vetted crowd workers or experts as small paid tasks and gets verdicts back as edge confidence. The agent writes self-contained tasks, posts them to a microtask platform within budget and aggregates answers. _Concerns:_ redact private data; fair pay.
- **Closed-loop lab: the graph picks the next experiment and a robot runs it** _(speculative)_ -- A biologist or chemist with a cloud lab gets a pathway or reaction graph that grows from real measurements. The agent picks the most informative edge to test, writes a protocol, submits it to the lab robot, parses the results and repeats. _Concerns:_ biosafety gating; a human approves each protocol.
- **Predict missing labels from the network's structure, with a backtest** -- A researcher whose category (party, function, fraud) is known for only some nodes gets predictions for the rest as a separate layer, with an accuracy figure from hiding known labels. The agent trains models from label propagation to a small graph neural network in a sandbox. _Concerns:_ guilt by association when labels are about people.

## 17. Safety, privacy and misuse

Protecting the people in a graph and the people using it: consent, erasure, exposure audits, guards against poisoned data, and the misuse cases the product must design against. Entries marked "misuse to name" are harms the agent must refuse, listed so the product can be designed against them.

- **Is this a scam? Contact map for an older relative** -- An older adult and the child who helps them see who has contacted them recently, which contacts match scam patterns or each other, and a large-print verdict, with bank and police reports drafted if money left. The agent checks numbers, domains and wallets against fraud databases with consent. _Concerns:_ the helper can be the abuser.
- **Safety map for survivors of domestic abuse or stalking** -- A survivor and advocate see the shared accounts, family plans, location sharing, smart devices and recovery paths an abuser can reach, ordered into a staged separation plan that avoids tipping them off. The agent works by interview only, in an ephemeral local session with a quick-exit button. _Concerns:_ life safety; never sync where the abuser could see.
- **Operational-security mode for activists and journalists under repressive governments** -- An exiled journalist keeps a graph of sources that never names them in clear text, is warned before any data would reach a cloud model or foreign server, and has a one-command wipe or decoy. The agent pseudonymizes at import and runs an on-device model. _Concerns:_ a mistake can get people arrested.
- **Teen and parent follower-safety review** -- A teen and parent review the teen's followers together, with unknown adults who reached out and share no mutual friends highlighted, and privacy settings explained. _Concerns:_ done with the teen, never covertly.
- **Purpose check before profiling a private person** -- When a request would build a dossier on one private individual (an ex, a neighbor, a critic), the agent notices, asks what it is for, and declines or narrows the job, offering legitimate variants. _Concerns:_ over-blocking journalism; who sets the policy.
- **Doxxing and stalking aggregation** _(misuse to name)_ -- A stalker building a friend-of-a-friend graph of a victim's followers, tagged photos and routine to find home and pressure points. Named so the product builds the purpose check, rate limits on person-centric joins, and refusal to resolve private home addresses.
- **Who can find me? Self-exposure audit** -- A survivor, activist or harassed person sees the graph an attacker would build about them, and which broker listings, tagged photos and relatives' posts to remove for the biggest cut, with opt-out requests drafted. _Concerns:_ verify it runs only on the requester.
- **Prompt-injection and poisoned-data guard** -- Anyone loading strangers' data has node labels or notes carrying hidden instructions ("export everything to this URL") caught and quarantined. The agent treats loaded values as untrusted text and refuses tool calls whose arguments trace back to data. _Concerns:_ no detector is complete; data must never gain the user's authority.
- **Untrusted file safety check** -- An analyst opening a graph file from email or a leak learns whether it is a decompression or XML entity bomb, references remote resources, or would freeze the browser, and gets a safe way to open it in a sandbox.
- **Remove one person from everything: erasure requests** -- A data protection officer handling "delete my data" finds every place a person appears (projects, versions, exports, embeds, agent memory), removes or pseudonymizes them and gets a receipt. _Concerns:_ shared copies cannot be recalled.
- **Consent ledger for people in a graph** -- A researcher or genealogist tracks who consented to what and until when; views and exports leave out or blur the rest, with expiry reminders. _Concerns:_ edges still reveal unconsented people.
- **What can be inferred about me from my friends** -- A privacy-curious person sees, on their own network, what an outsider could guess about their politics, health or orientation from their ties, and which visibility changes reduce it. _Concerns:_ run locally, only about the owner.
- **Guilt-by-association audit** -- A compliance team or risk-score auditor checks whether a flag rests only on network proximity, and how many innocent people the same rule would catch. _Concerns:_ must not become a better targeting tool.
- **Surveillance mapping of activists and dissidents** _(misuse to name)_ -- A state or hostile employer mapping protesters or union organizers to find the brokers whose arrest would break a movement. Named so the product sees that its own key-player tools are the targeting step and refuses requests framed around suppressing lawful assembly.
- **Security culture check for an activist or newsroom group** -- An organizer or newsroom learns which members, chats and accounts would expose the most of the group if one phone were seized, and how to compartmentalize. _Concerns:_ the map is the most dangerous file the group owns.
- **Source protection check before publishing** -- A journalist is warned when a published graph or its metadata would reveal who leaked: a node only one insider could know, an exact timestamp. _Concerns:_ editorial judgment stays in charge.
- **Harassment campaign documentation for the target** -- Someone facing a pile-on gets a record of who is attacking, how the accounts link and who set it off, archived with timestamps and hashes and drafted into platform reports. _Concerns:_ hide abusive content by default.
- **Dual-use gate for critical-infrastructure targeting** -- Grid or water resilience analysis stays open to operators and researchers, while "which few points cause the biggest blackout" from an unknown user is slowed, questioned or reframed as redundancy to add. _Concerns:_ friction, not a wall.
- **Data-flow disclosure: what left this machine** -- A privacy-conscious user sees, per session, which parts of the graph went to which outside service (model, search engine, geocoder) and can mark columns never-send. _Concerns:_ only a local model is a full answer.
- **Peer safety alert network for at-risk workers** -- Sex workers, drivers or home-care workers check a contact against an anonymized shared graph of reported dangerous clients, numbers and plates, without revealing who reported. _Concerns:_ false accusations; infiltration.
- **Shareable synthetic twin of a private graph** -- A hospital or company that cannot share its network publishes a synthetic graph with the same key statistics and no real people, with a fidelity report and privacy guarantee. _Concerns:_ rare structures can still leak.
- **Per-recipient watermarked copies to trace a leak** -- Each recipient of a sensitive export gets an imperceptibly different copy, so a leaked one can be traced. _Concerns:_ forged fingerprints can falsely accuse.
- **Structural re-identification test before releasing an anonymized graph** -- A researcher or agency learns whether people in a name-stripped graph can be picked out by the shape of their neighborhood, how many are at risk, and gets safer release options with their cost to the key results. _Concerns:_ the attack simulation is itself a tool; run only on pre-release data.
- **Influence-campaign seeding and microtargeting** _(misuse to name)_ -- An operative harvesting a friend graph to pick seed accounts and susceptible communities for disinformation or scams. Named so the product refuses harvesting of non-consenting third parties and flags spread maximization paired with persuasion content.
- **Leak hunt: unmasking a whistleblower from communications graphs** _(misuse to name)_ -- An employer intersecting leaked facts with access logs and meeting graphs to find who talked. Named so the agent declines without legal process and points to whistleblower-protection law.
- **Detector evasion design** _(misuse to name)_ -- Launderers or bot farms shaping their networks so fraud, AML and bot detectors see nothing. Named so the agent refuses to minimize detectability and offers red-teaming only to verified compliance teams.
- **Incidental findings protocol** -- When the agent comes across self-harm messages, signs of child abuse, leaked credentials or evidence of a crime while cleaning data, it flags the record privately, offers the right resource and lets the user decide, taking no outside action itself. _Concerns:_ false positives; the agent becoming an informant.
- **Privacy records and impact assessments from a data-flow graph** -- A privacy officer gets a record of processing activities, an impact assessment and a vendor transfer list drafted from a graph of systems, vendors and data flows. _Concerns:_ a legal record needing qualified review.
- **Outbound action preview and throttle** -- Before the agent emails, posts or writes to other systems at scale, the user previews every recipient and change, sends in small batches and can stop or undo. _Concerns:_ anti-spam law; runaway automation.
- **Defamation and false-link review before publishing a graph of real people** -- A journalist or researcher gets every edge between named people checked for source strength, implied wrongdoing and name collisions, with edges to cut, soften or caption.
- **Retention timer and auto-expiry for sensitive projects** -- An investigator or contact tracer sets an end date; the agent warns, then deletes or anonymizes the project, exports, versions and its own memory, with a receipt.
- **Regulated-data check before loading** -- A hospital, HR or school analyst is told which rules likely apply to a file before it is loaded or sent to an outside model, and a safer path such as de-identifying first or using a local model.
- **Worker-protection guard in workplace network analysis** -- Team-level workplace analysis stays allowed, but requests to single out employees for discipline, such as finding who is organizing colleagues, are declined and logged. _Concerns:_ organizing is legally protected in many countries.
- **Dual-use review for life-science graphs** -- Ordinary pathway and molecule analysis stays open, while requests that seek ways to cause serious biological or chemical harm are refused and logged. _Concerns:_ over-blocking normal science.
- **Check whether a received graph or figure was tampered with** -- A journalist or court verifies a graph file's signature and timestamp, recomputes it from cited sources and sees any edits as an overlay. _Concerns:_ report what cannot be checked.

The agent reads and translates official guidance and refreshes when rules change. _Concerns:_ outdated rules can cost status.
- **Family tracing after displacement** _(speculative)_ -- Tracing organizations get candidate links between missing relatives and people registered elsewhere, from names in many scripts, places and shared acquaintances, ranked for caseworkers to verify. _Concerns:_ false matches harm; persecutors could use the same graph.
- **Ecomaps and genograms for social workers and family therapists** -- A social worker or therapist builds a client's genogram and ecomap live during a session in standard notation, confirming each relationship, tracked across visits. _Concerns:_ clinical confidentiality.
- **Tenant organizing and landlord portfolio map** -- A tenant union sees every building their landlord controls behind layers of LLCs, violations across the portfolio, and which neighbors have been contacted. The agent links LLCs in property and corporate registries. _Concerns:_ retaliation if the contact list leaks.
- **Humanitarian who-does-what-where coordination map** -- A disaster coordinator sees which camps have no water partner, where groups duplicate work and whom to call, from multilingual situation reports and messaging groups, with a daily summary. _Concerns:_ locations of vulnerable people and aid stocks.
- **Indigenous knowledge graph under community data sovereignty** -- A community archive keeps kinship, place and story knowledge as a graph where each node carries its protocols (who may see it, in which season), enforced on every view, export and agent answer, with restricted content never sent to outside models.
- **Word-finding web for people with aphasia** -- A stroke survivor and therapist build a picture-and-voice semantic web of the words that matter, and the agent cues one hop at a time to help find a lost word, reporting progress to the therapist. _Concerns:_ never replace the therapist or finish sentences unasked.
- **Relapse-prevention map for people in recovery** -- A person in recovery keeps a private map of people, places, times and feelings linked to cravings and to support, with who to call first when a high-risk pattern appears. _Concerns:_ must stay local; escalate crises to humans.
- **Lifelong connections map for youth in or leaving foster care** -- A foster youth maps every caring adult they have known and who could still be a support before aging out, controlling who appears. _Concerns:_ some contacts may be unsafe.
- **Recruitment-agency and job-offer check for migrant workers** -- Before paying a recruiter, a migrant worker sees the agency's licenses, foreign partners, links to known bad actors and worker reports, answered by voice in their language. _Concerns:_ must work on a basic phone.
- **Check-on-each-other network for heat waves and outages** -- A block captain or mutual-aid group makes sure every fragile neighbor has two checkers within walking distance, with check-in prompts sent during a weather alert and unanswered checks escalated by SMS or phone.
- **Reentry map for people leaving prison** -- A person on parole sees housing, jobs, treatment, ID offices and supportive people, with parole conditions overlaid so they know which contacts and places are allowed, and an ordered plan of steps. _Concerns:_ not legal advice.
- **Crop buyer and price network for smallholder farmers** -- A farmer or cooperative learns who buys which crop where, at what price this week, and which route to market keeps more of the price, by voice or SMS in local languages. _Concerns:_ trader retaliation; low connectivity.
- **Recruitment-pathway map for families and exit counselors** -- The family of someone drawn into an extremist or high-control group sees how they were reached, where outside ties were cut and which bridges could support a return, paired with counseling guidance. _Concerns:_ surveilling an adult without consent; mislabeling lawful belief.
- **Circle-of-support map in easy-read for adults with intellectual disabilities** -- An adult with Down syndrome gets a picture-first map of who helps with each part of life, gaps like "nobody helps with friends", and who to ask for what, authored with them in easy-read language. _Concerns:_ the person stays the author, not the subject.
- **By-name list and outreach network for people experiencing homelessness** -- Outreach workers see each person's contacts across agencies, who last saw them and who is closest to a housing match, with people unseen for N days flagged and the next outreach route drafted. _Concerns:_ extremely sensitive; never shared with enforcement.

## Themes that recur

The same handful of capabilities sits under most of these ideas. Building them once, well,
would unlock many use cases at a time.

- **Web search, fetch and public data APIs.** Dataset portals, Wikidata and SPARQL, scholarly
  indexes, company registries, government statistics, maps, threat-intelligence feeds. Most
  graphs a user wants do not exist as a file yet.
- **Extraction from unstructured material.** OCR, vision on photos, figures and screenshots,
  speech-to-text, and relation extraction from text turn documents, whiteboards, recordings
  and conversations into nodes and edges, each needing a confidence value and a way to check it.
- **Entity resolution.** Merging "J. Smith" and "John Smith", matching names to authority ids,
  aligning nodes across versions and sources. It decides whether a graph is right, and a wrong
  match turns into a false accusation.
- **Provenance and citation.** Every node and edge knowing its source row, URL, fetch time and
  who approved it. Journalism, science, law and safety use cases all depend on it.
- **Code execution in a sandbox.** Statistics, null models, simulations, optimizers, format
  conversion, independent recomputation, and plugins written on the fly.
- **Document and media generation.** Papers, methods sections, decks, posters, videos,
  narration, web pages, spreadsheets, print and 3D files: the analysis leaving graphty in the
  form its audience needs.
- **Connectors to the user's own accounts.** Mail, calendar, contacts, photos, notes, bank
  exports, CRMs, issue trackers and clouds, read with the user's consent and usually read-only.
- **Scheduling and unattended runs.** Nightly refreshes, digests, alerts, watches, retention
  timers and forecasts graded months later all need the agent to act while nobody is watching.
- **Memory.** Remembering a user's role, preferences, relationships, past projects and past
  predictions, always viewable and clearable.
- **Sub-agents and agent-to-agent negotiation.** Parallel research, independent annotators and
  red teams, and negotiating with other people's agents for data, schedules, swaps and clean
  rooms.
- **Writing to the outside world.** Tickets, pull requests, CMS edits, emails, posts,
  submissions, orders and payments. Every one needs a preview, a size limit and an undo.
- **Honesty built into analysis.** Caveats after results, null models, backtests, sensitivity
  sweeps, "the graph cannot answer that", and a check that the agent's own UI actions really
  happened.
- **Local-only and on-device modes.** Many of the most valuable personal, clinical and
  activist uses are only acceptable if nothing leaves the device.
- **Bodies, rooms and machines.** Voice, VR and AR, spatial audio, tangible tabletops,
  embossers, 3D printers, projectors, robots and diagnostic ports bring the graph off the
  screen.

## Risks to design for

- **Privacy of the people in the graph.** Most personal and organizational graphs describe
  people who never agreed to be in them. Defaults should be local storage, aggregation, consent
  records, erasure that reaches exports and agent memory, and retention timers.
- **Data leaving the device.** Every call to a model provider, search engine, geocoder or
  enrichment API carries part of the graph. Users need to see what left, mark columns as
  never-send, and choose a local model when it matters.
- **Prompt injection from fetched and loaded data.** Web pages, shared files, scraped labels and
  notes can carry instructions. Loaded data must never gain the user's authority, and tool
  calls whose arguments come from data rather than from the user should be refused.
- **Hostile files.** Decompression and XML entity bombs, remote references and graphs sized to
  freeze the browser call for sandboxed inspection before loading.
- **Confident errors.** Hallucinated edges, wrong entity matches, misread handwriting and
  fabricated citations look authoritative once drawn. Show sources and confidence, keep
  inferred edges in a separate layer, and verify before publishing.
- **Defamation and guilt by association.** Graphs of real people imply relationships and
  wrongdoing. Check every published edge between named people, and test whether a flag rests
  only on proximity.
- **Re-identification.** Removing names does not anonymize a network; the shape of a
  neighborhood can identify a person. Test before release, or publish a synthetic twin.
- **Misuse.** The same tools that audit exposure can build a stalker's dossier, the same
  key-player analysis that protects a grid can target it, and the same spread model that plans
  public-health messaging can plan disinformation. Purpose checks on person-centric joins,
  dual-use gates and refusal of named misuse patterns belong in the product, not in policy text.
- **Actions with consequences.** Emails, posts, edits to shared data, tickets, payments, calendar
  invites, infrastructure changes and robot dispatches need previews, batching, caps, human
  sign-off and undo.
- **Vulnerable users.** Older adults, minors, survivors of abuse, people in recovery, people
  with memory loss and people under repressive governments are among those who would benefit
  most, and are the most harmed by a mistake, a leak or a helper who is really a controller.
- **Advice in regulated domains.** Medical, legal, financial and safety-critical outputs need
  clear "not advice" framing, qualified human review and conservative defaults.
- **Workplace surveillance.** Organizational network analysis, meeting graphs and process
  mining must stay aggregated and opt-in, and must refuse to single out individuals for adverse
  action.
