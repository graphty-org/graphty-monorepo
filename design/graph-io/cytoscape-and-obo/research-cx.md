# CX version 1 (Cytoscape Exchange, NDEx): research for a graph-io reader

CX version 1 is the JSON exchange format of NDEx (the Network Data Exchange, ndexbio.org) and of
Cytoscape's CX support. A CX document is a JSON array of "aspect fragments"; each fragment is an
object with one key (the aspect name) whose value is a list of "aspect elements". Nodes, edges,
attributes, coordinates and Cytoscape's styles, subnetworks and groups are separate aspects that
refer to each other by integer ids. This note collects what a comprehensive graph-io importer
(and exporter) for CX version 1 must handle, how each construct maps onto the graph-format
snapshot, the errors to anticipate, the candidate sample files, and the independent reader the
conformance suite should take its expectations from.

CX version 2 (CX2, `.cx2`) is a different document shape and is out of scope here except for
telling the two apart (section 5.1). Cytoscape.js JSON (`.cyjs`) is already read by graph-io's
JSON importer.

Everything below was checked against the sources in section 1 on 2026-10-02. Facts about real
files come from a survey script run over 133 CX files from the reference readers' test suites
and five NDEx networks (scratch: `tmp/samples-cx/tools/survey.py`, `values.py`).

## 2. The document structure

```json
[
  { "numberVerification": [ { "longNumber": 281474976710655 } ] },
  { "metaData": [ { "name": "nodes", "version": "1.0", "idCounter": 2, "elementCount": 2, "consistencyGroup": 1 }, ... ] },
  { "nodes": [ { "@id": 1, "n": "node1", "r": "HGNC:AKT1" }, { "@id": 2 } ] },
  { "edges": [ { "@id": 1, "s": 1, "t": 2, "i": "binds" } ] },
  { "nodeAttributes": [ { "po": 1, "n": "weight", "v": ["2", "0.34"], "d": "list_of_double" } ] },
  { "metaData": [ { "name": "nodes", "elementCount": 2 } ] },
  { "status": [ { "error": "", "success": true } ] }
]
```

- Top level: a JSON array. Each member is an aspect fragment: an object with exactly one key.
- Order: optional `numberVerification`, then the pre-metadata (`metaData`), then any number of
  aspect fragments in any order, then optional post-metadata (a second `metaData`), then
  `status` last.
- An aspect may be split into any number of fragments, interleaved with other aspects
  ("the fragments can be transmitted in any order"). The spec suggests fewer than 100 elements
  per fragment; NDEx server output uses one fragment per aspect; Cytoscape output splits
  freely. 56 of the 133 surveyed files split at least one aspect; `cx2js/.../UD-219.cx` sends
  `edges` in two fragments, the first one BEFORE `nodes` (a forward reference).
- References may precede their definitions: "it is not necessary that a referenced element be
  defined before its reference". A reader must resolve references after the whole stream (or
  hold unresolved references until the end).

## 3. Feature inventory

"Era" says where a construct comes from; CX1 has no per-feature version numbers. "cxio" means
the original 2015 specification and library; "NDEx 2.x" the NDEx server releases (2.0 in 2017,
2.4.0 deprecated `ndexStatus`); "Cytoscape" the cx-support app (CyNDEx-2 era, 2016 onward).

### 3.1 Stream-level aspects

### 3.3 Attribute data types (`d`)

The spec's section 7 lists ten types; values are "always encoded as JSON strings". The Java
reader adds two aliases.

| `d`                                                                                                                    | Meaning          | Lexical forms met in the wild                                                                                                      | graph-format dtype                                                                                                 |
| ---------------------------------------------------------------------------------------------------------------------- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| absent / `string`                                                                                                      | string           | any JSON string; `""`                                                                                                              | `string` (or `dict` by the cardinality heuristic)                                                                  |
| `boolean`                                                                                                              | boolean          | `"true"`, `"false"`, native `true`/`false`; case: Java `Boolean.valueOf` and ndex2 `.lower()` are case-insensitive                 | `bool`                                                                                                             |
| `double`                                                                                                               | 64-bit float     | `"3.4"`, `"1.4599107187941883E-4"`, `"NaN"`, `"null"`, `""`, native numbers                                                        | `f64`                                                                                                              |
| `float` (alias, Java reader only)                                                                                      | double           | --                                                                                                                                 | `f64`                                                                                                              |
| `integer`                                                                                                              | 32-bit int       | `"1"`, native `1`, `""`, `"NaN"`                                                                                                   | `i32`                                                                                                              |
| `long`                                                                                                                 | 64-bit int       | `"2"`, values beyond 2^53 possible                                                                                                 | `f64` (design 5.1: declared long never widens; above 2^53 is a precision issue) or `string` under `long: "string"` |
| `list_of_boolean` / `list_of_double` / `list_of_float` (alias) / `list_of_integer` / `list_of_long` / `list_of_string` | homogeneous list | `["a","b"]`, `[]` (48 empty `citation` lists in `Direct-p53-effectors.cx`), `["8.0","null","","NaN"]` (`cx/.../gal_filtered_3.cx`) | `list` with the element dtype as child                                                                             |

Any other `d` is an error in the Java reader ("data type X is not supported in this version of
CX") and accepted untyped by ndex2.

### 3.6 NDEx and Cytoscape conventions that affect mapping

- Node `n` and node attribute `name` mean the same thing; old Cytoscape exports wrote both, and
  NDEx warns "Attribute 'name' on node X is not allowed in CX specification" (same for
  `represents` and for the edge attribute `interaction` versus `i`). CX2 conversion in ndex2
  declares `name` with alias `n`, `represents` with `r`, `interaction` with `i`.
- Cytoscape writes `shared name`, `shared interaction` and `selected` columns; they are ordinary
  attributes to a reader.
- Identifiers should be `prefix:id`, a string without a colon, or a URI.

## 4. Errors and edge cases

Severity column: what a graph-io reader should do, following graph-io's rules (fatal ->
`ImportError` at once; error -> `ImportIssue`, skip the element, continue to `errorLimit`;
warning -> `ImportIssue`, keep going). "Ref" says which reference reader behaves how.

## 5. Recognizing CX

### 5.1 Sniffing

- Cytoscape's file filter (`CytoscapeCxFileFilter`) reads the first 400 characters and matches
  `\s*\{\s*"\s*metaData"\s*:` (anywhere) or `\s*\[\s*\{\s*"\s*numberVerification"\s*:`.
- A CX1 document starts with `[` then an object whose single key is `numberVerification` or
  `metaData`, or (lenient files) any known aspect name (`nodes`, `edges`, `networkAttributes`,
  `@context`, ...).
- A CX2 document starts with `[{"CXVersion":"2.0"` (with `hasFragments`): never CX1.
- Conflict with graph-io's JSON importer: its `sniff()` returns 0.9 for any JSON head containing
  `"nodes"` or `"edges"`, and a CX head always contains them (as aspect keys and as
  `"name": "nodes"` in metadata). `sniffJsonDialect` returns null for a CX array (its first
  object has no `data` key), so JSON would then fail. The CX importer's sniff must therefore
  score above 0.9 on the CX1 shapes, and the JSON importer should score a top-level array whose
  first object has a single key from the CX aspect list at most 0.5.
- Extensions: `.cx` (Cytoscape, NDEx downloads). MIME: NDEx serves `application/json`; no
  registered CX type. Cytoscape's filter declares `application/json`.

### 5.2 Writers seen in the wild and their fingerprints

| Writer                                    | Fingerprint                                                                                                                                                                                                          |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NDEx v2 server (`GET /v2/network/{uuid}`) | One fragment per aspect, no post-metadata, every metadata entry has `version`, `consistencyGroup`, `properties: []`; all `v` are strings; `status` last.                                                             |
| Cytoscape cx-support                      | Pre-metadata with names and versions only, counts in post-metadata; `cyTableColumn`, `cySubNetworks`, `cyNetworkRelations`, `cyViews`; `s` on local attributes; `shared name` columns; aspects split into fragments. |

What CX cannot hold (exporter loss notes): non-integer node ids (CX needs integer `@id`; write a
generated id and keep the original as the `name` or a `cx:id` attribute: a LossNote), json and

(written as double / integer / long), multi-component columns other than position (no type),
undirected or mixed edges (CX has no undirected flag: `W_MUTUAL_EXPANDED`-style notes),
dictionary columns (written as strings), nulls inside list values, values of `-0`, Infinity
(written as strings "Infinity", which Java parses but the spec forbids for raw JSON numbers).

## 7. The oracle

### 7.1 Recommendation

Take expectations from **ndex2-client** (Python, BSD-3-Clause, PyPI `ndex2` 3.12.0, which
pulls `ndex2cx`, networkx 3.4.2, numpy, pandas), the NDEx project's own client and the most
widely used CX reader outside Java. It is independent of graph-io (different language, different
authors) and it is the reader whose element inventory the NDEx web site and its Jupyter users
see.

Install (Python 3.10 on this machine; no venv module, so a target directory):

```bash
python3 -m pip install --target tmp/cx-oracle/pylib ndex2==3.12.0
PYTHONPATH=tmp/cx-oracle/pylib python3 -c "import ndex2; print(ndex2.__version__)"
```

Use the NiceCX model, not `to_networkx()` and not the CX2 converter:

```python
import json, ndex2
nice = ndex2.create_nice_cx_from_raw_cx(json.load(open(path, encoding="utf-8")))
nice.nodes            # {node_id: {"@id", "n", "r"}}
nice.edges            # {edge_id: {"@id", "s", "t", "i"}}
nice.nodeAttributes   # {node_id: [{"po", "n", "v", "d", "s"}, ...]}
nice.edgeAttributes   # {edge_id: [...]}
nice.networkAttributes          # [{"n", "v", "d", "s"}]
nice.opaqueAspects["cartesianLayout"], ["cySubNetworks"], ["cyGroups"], ...
```

`oracle_cx.py` (one more module beside `oracle_<format>.py`) computes `nodes`, `edges`,
`directed: true`, `nodeIds`, `edgeChecks` (s, t, interaction), `nodeAttrs` (typed: CX data model
section 7 table; the empty / null / NaN rule from Cytoscape's `CxUtil.parseValue`), raw
positions per view from `opaqueAspects["cartesianLayout"]`, and the subnetwork count. A
prototype ran successfully over all 20 downloaded candidates
(`tmp/samples-cx/tools/oracle_cx_prototype.py`).

### 7.2 Why not the others

- `to_networkx(mode="default")` negates y (`g.pos[id] = (x, -y)`), drops `z`, keeps the last
  of several views, and leaves values as raw strings. The default `mode="legacy"` keys nodes by
  name and crashes on a nameless node ("None cannot be a node", seen on `5views1network.cx`).
- `NoStyleCXToCX2NetworkFactory` pairs nodes with layout elements by list position
  (`zip_longest(nodes, cartesianLayout)`), not by node id: wrong whenever the orders differ.
- The Java readers (ndex-object-model, cx-support) are the most faithful but need a JVM and
  Cytoscape's OSGi runtime; neither is installed here. They are the right SECOND opinion for
  the error cases (section 4 quotes their messages) and should be cited per expectation.
- RCX needs R (not installed); cx2js is JavaScript like graph-io and targets rendering.

### 7.3 Known ndex2 disagreements with the specification (mark them in the manifest)

| ndex2 behavior                                                                                                                               | Spec / Cytoscape                                                             | Manifest handling                   |
| -------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | ----------------------------------- |
| Reads only aspects named in `metaData`; a file with `nodes` but no metadata entry for it yields no nodes; a CX2 file yields an empty network | Metadata is optional for the reader's purposes; Cytoscape reads every aspect | `oracle: "spec"` for those fixtures |
| Duplicate `@id`: the last element wins silently                                                                                              | NDEx rejects                                                                 | hand-written error expectation      |
| Dangling edges kept                                                                                                                          | NDEx rejects                                                                 | hand-written                        |
| No typing of values                                                                                                                          | spec section 7                                                               | typed in `oracle_cx.py`             |
| A collection is one root network                                                                                                             | Cytoscape: one network per subnetwork                                        | hand-written `graphs` expectation   |
| `status` errors ignored                                                                                                                      | Java: fatal                                                                  | hand-written                        |
