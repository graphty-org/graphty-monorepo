# Style import: prototype results

This document records what a prototype of `style-import-design.md` measured: whether importing
the styles of graph files into graphty-element layers can be done without errors, exactly, and with
a small number of layers. The prototype (a "spike") implements the whole design outside the
packages: style readers for every format, the planner that turns per-element values into a few
rules, the translation into graphty-element layers, and a verifier. No package source was changed.
The format research it rests on is in `style-import-research.md`.

The spike was held to three requirements, the same three the design states:

1. **No errors.** Every valid input imports without an error, whatever styles it holds, and no
   input makes the import hang.
2. **Exact, or a precise loss note.** The layers draw each node and edge the way the tool that
   wrote the file draws it, for every property graphty can draw. Anything approximated or dropped
   is reported by a note that names the element.
3. **Few layers.** The number of layers does not grow with the graph: at most 16 per element kind
   (nodes, edges), label layers included.

The spike, its inputs and its raw outputs are kept outside the repository (several downloaded
files may not be redistributed). Every real file is listed with its URL and license in the
appendix of `style-import-research.md`.

## The verdict

A final skeptical re-check reran everything from a clean state and added 80 new hostile files.

| Requirement                      | Verdict                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. No errors                     | **Passes for the style pipeline**: 0 exceptions on 5,808 inputs, and every hostile file exits normally when run in its own process under a time limit. **Not yet met end to end**, because of two import defects outside the style pipeline: graph-io throws a bare `RangeError` on a deeply nested XGMML file, and graphty-element's own import path refuses 89 inputs, including every Cytoscape.js file (`E_EMPTY_LOAD`). Both are listed in the design as prerequisites. |
| 2. Exact, or a precise loss note | **Fails in the spike.** The check found a layer-ordering bug in the spike's translation to graphty-element layers that draws ordinary Cytoscape.js stylesheets wrongly, and five smaller losses that carry no note (details under "Defects the final check found"). Each has a known fix; none needs a change to the design's format or algorithms, and the design now states the rules the spike broke.                                                                     |
| 3. Few layers                    | **Passes.** At most 16 node and 15 edge layers over all 5,808 inputs; the count does not grow with graph size; a 1,000,000-node file needs 2 layers.                                                                                                                                                                                                                                                                                                                         |

Everything else held: on every corpus the layers reproduce the reader's values with 0 mismatches,
paint nothing the file left unstyled, and hide exactly the elements the file hides; the readers
agree with Graphviz, Cytoscape.js and an independent implementation of Cytoscape's styles, with
every difference explained.

Medians are 4 node and 2 edge layers; the maximum is 15 node layers (a CX2 network whose author
built 10 mappings, plus label typography) and 11 edge layers. Of the varying style values, 3.7% come
from an opaque layer and 0.8% from the exceptions layer. Before style classes, degree tables and

100%, Pajek 100%, XGMML 85%, JSON 69%, GraphML 67%, GEXF 58%).

What the planner recovers on these files, in the words a person would use:

- **Partitions and rankings** (Gephi GEXF, GraphML and graphology): "fill by Modularity Class",
  "fill by country", "size by degree, 27 entries" (a degree table where a ramp would need 28 exact
  pieces), and ramps within Gephi's rounding ("fill by degree", noted per element).
- **Style classes** (yEd, GML, Pajek, DOT tool output): files with a handful of distinct styles and
  no column that names them get "style 1" to "style k" (one layer per class up to 4, one table up to
  64), editable as groups, instead of one copied value per element.
- **Clusters** (DOT): "fill by cluster", one layer however many clusters.
- **The file's own rules** (CX, CX2, Cytoscape sessions, Cytoscape.js): defaults, mappings and
  selector rules translated one to one; Cytoscape desktop's one-rule-per-value exports and runs of
  class rules collapsed into one mapping each.
- The opaque values left are mostly what nothing explains: GraphML node sizes fitted to labels,
  Pajek per-vertex size factors, DOT pen widths drawn as data, and per-element bypasses.

The final check added its own XML parse of GEXF and yEd files, sharing no code with graph-io or the
spike's readers: 648,524 GEXF fills, 40,136 GEXF edge colors, 160,394 size ratios, 24,144 yEd fills
and 23,833 yEd edge colors agree. Every GEXF difference is covered by a note (a ramp within the
tool's rounding) or a graph-io warning.

These checks found the following reader errors, all fixed in the spike and written into the design:

- Graphviz substitutes `\N` and the other object escapes BEFORE it reads `\n`, so a node named
  `a\nb` breaks its label line; style tokens keep trailing blanks (`"filled "` is not filled);
  `striped` fills only boxes and `wedged` only ellipses; a record label drops its port tags even
  without fields; `shape=plain` has no size; a circle with one dimension takes it for both; a node
  named by an HTML string shows the HTML text; Graphviz 2.43 draws a quoted string as HTML when an
  identical HTML string exists elsewhere in the file (a string-pool quirk).
- Cytoscape.js: an invalid selector matches every element, nodes and edges; `[a]` matches an
  explicit `null`; `!=` negates even for a missing field.
- Cytoscape: a discrete mapping over a list attribute matches the list's first item that has an
  entry (Cytoscape's `DiscreteMappingImpl`); the reader had treated it as no match, and 497 SIGNOR
  edges drew the default arrow.
- A raw color column is reused by a passthrough only when it already holds `#rrggbb`: the element
  parses `hsl(400,200%,50%)` to a different color than the canonical parser.

Still open: a comparison against Cytoscape desktop's own XGMML export of the same session. The
corpus holds no session and export of one style, and Cytoscape desktop was not available.

## The real graphty-element

Two checks loaded the spike's output into graphty-element's headless session. Both compare the
element with the spike's own prediction, not with the file, so they catch a translation the element
draws differently, not a translation that is wrong (the ordering bug under "Defects the final check
found" passed both).

**Layers loaded directly.** The emitted records and layers of every input with styles went into
the session with `addNodes`, `addEdges` and `applyTemplate`. Every layer was accepted and bound.
For every node and edge, `explain()` gave exactly the spike's value per channel, every channel it
attributed to an imported layer was predicted, and label styles were merged field by field in stack
order, as the repaint does. Final check: 4,436 files, 11,749,977 values and 2,812,265 label styles,
0 mismatches. 3 inputs are over the element's own 100,000-node limit (`E_TOO_LARGE`).

**Through the element's import path.** The same inputs loaded with `session.data.import` from the
original file, as the graphty app loads them; the style columns written onto the element's records
with `updateNodes` and `updateEdges`; the layers applied; `explain()` compared both ways.

defects. Element reader defects this exposes, which block the import path for the affected files:

- **Cytoscape.js JSON**: every file with a stylesheet fails with `E_EMPTY_LOAD`; the element's JSON
  source never builds graph-io's snapshot of these documents.
- **Counts**: graphology `eurosis-400.json` loads 311 of 400 nodes; `apt-families.gexf` 159 nodes
  instead of 155; the Pajek `b98.net` keeps 132 of 207 edges; Cytoscape 2.x sessions and a
  multi-network session load a different network than graph-io (`layout-v1.cys`: 331 nodes instead
  of 26); a GEXF node attribute titled `id` replaces node ids (117 nodes load as 234).
- **Columns**: GraphML `yfiles.*` columns and `parent` do not arrive under graph-io's names, so the
  layers that read them are unbound; GEXF `label` and suffixed attributes (`label#att1`) and CX2
  attributes named `type` or `color` arrive differently.
- **Ids only**: 498 inputs reach the element with records holding only ids, mostly yEd GraphML (its
  attributes are all `yfiles.*` keys the reader renames) and graphology JSON. For graphology,
  `updateNodes` on such records writes nothing, which is what the 1,922 mismatching values are.
- `cytoscape-tutorials-PSPG_Homework.cys` fails with `E_PARSE_FAILED` (CR-separated list cells), as
  it does in graph-io without a retry; the 7 yFiles 3 files and Gephi's diseasome fail with
  `E_PARSE_FAILED`; two Graphviz gallery files lose nodes (28 become 24; 2 become 1).

## Adversarial reviews

Four adversarial reviews attacked the design and the spike, each from one angle: correctness of the
exact round trip; robustness (make it throw, hang or corrupt state on input a writing tool
accepts); layer count and layer meaning (can an input make the layers explode, and do the layers
mean something to a person editing them); and architecture and public API. Every finding was
reproduced, then fixed in the spike and in the design:

| Review                                               | Finding                                                                                                                                                                                                                                                  | Change                                                                                                                                                                                                                                                                                                                                                         |

## The final check

The final check reran the whole spike from a clean state (every corpus, both real graphty-element
checks, and the three external checks against Graphviz, Cytoscape.js and cytoscape-cx2js), wrote 80
new hostile files, and added its own XML parse of GEXF and yEd files.

**The published results reproduced exactly**: 5,728 inputs over every corpus with 0 errors, 0 rule
mismatches, 0 layer mismatches, 0 painted unstyled and 0 invalid layers; Graphviz 142,760
comparisons with the same 9 explained differences; Cytoscape.js 146,763 comparisons with 0
differences; cytoscape-cx2js the same 683 differences and 6 missed values, all explained.

**Robustness**: 0 exceptions on 5,808 inputs, the 80 new files included. Each new file and each
hostile review file also ran in its own process under a time limit: 62 processes, all exited
normally, the slowest in 2.8 s. A 1,000,000-node file took 15.4 s.

**Layer count**: the count does not grow with graph size.

| ------------------------------------ | -------------------------- | ----------------------------- |
| GEXF, every property random          | 60 / 600 / 6,000 nodes     | 2 node + 2 edge at every size |
| yEd                                  | 50 / 500 / 5,000 nodes     | 11 / 6 / 5 node layers        |

### Defects the final check found

These break requirement 2 in the spike. Each needs a fix in the implementation; the design now
states the rule each one broke.

1. **Layers come out in the wrong order (the most serious).** The spike's translation adds a
   graphty-element layer when a rule is first touched, and handles size (width and height) and
   opacity in a second pass. A rule that sets only those properties therefore gets its layer above
   later rules. Minimal case: `node {width:20; height:20}` followed by
   `.big {width:50; height:50; background-color:red}` draws the `.big` nodes at the default size;
   the same happens with opacity and background opacity. Over the final check's adjacent-rule,
   bisection and overlap stress files: 357 wrong values in 6 files of the first set, 10 of 16 files
   of the second, and more in the third, none with a note. Real Cytoscape.js agrees with the
   reader's values, so the layers are what is wrong. Fix: emit layers in rule order (sorted by rule
   index, whichever pass makes them), and keep these files as regression inputs.
2. **yEd labels.** The yEd reader takes only the first `NodeLabel`. Icon nodes put an empty label
   (`hasText="false"`) first, so the real label is lost: in real files, 15 nodes in 2 files lose
   their only visible label (for example `svanoort__pyresttest__contexts.graphml`), and 54 elements
   in 9 files have further visible labels whose text is dropped, none with a note. Fix: take the
   first visible label with text, and note the others per element.
3. **Cytoscape.js degree selectors.** `[[degree > 2]]` and `[[indegree = 0]]` are treated as
   invalid, so they match every element; Cytoscape.js evaluates them. In the final check's selector
   file, 223 node shapes come out wrong and the note wrongly calls the selector invalid. No real
   file uses them. Fix: support the metadata selectors (`degree`, `indegree`, `outdegree`) over the
   degree features the planner already computes.
4. **A Cytoscape.js stylesheet given as a string.** A `.cyjs` file whose `"style"` is a CSS-like
   string imports with no styles and no note, while Cytoscape.js applies it through both `cy.json`
   and its constructor. Fix: parse the string form, which Cytoscape.js documents.
5. **DOT colors.** `none` and `invis` are read as unknown colors and drawn black, where Graphviz
   draws them transparent; a color list in `color` or `fontcolor` is read as its first color,
   where Graphviz draws black. Graphviz shows 8 differences in the final check's file. One real
   file uses `color="none"`, only on plaintext shapes, where it makes no difference.
6. **Minor.** Cytoscape.js `mapData` with a zero or reversed range, and `width: 50%`, are dropped
   with one note for the whole property instead of per element, and that note says the mapping is
   bad, yet Cytoscape.js draws these (691 values it draws are missing). A note's sample prints
   Infinity as `null`.

Also open from the reviews: the comparison against Cytoscape desktop's own export; the readers do
not yet count their work against one shared budget; graph-io's `RangeError` on deep XML; and the
element import path defects above.

51,534 values over all inputs are drawn approximately, each noted per element: label typography
beyond the label budget, and ramps within the writing tool's rounding. The requirement allows these.

## What is still approximate

Every case has a note naming its elements.

- **Label typography beyond the label budget**: graphty-element cannot bind label styles to data,
  so each distinct value costs a layer. 12,800 label values over all corpora (1,230 in the real
  files, mostly Cytoscape label sizes from continuous mappings) are drawn at the nearest kept value.
  Bindable label sub-channels in the element remove this.
- **Ramps within the tool's rounding**: 14,860 values over all corpora (980 real) are drawn within
  2/255 per color channel of the file's value, instead of an exact but opaque copy.
- **2D shapes and width-and-height sizing**: drawn as the nearest 3D shape and one size.
- **DOT sizes without `fixedsize`**: carried as the minimum the file states; Graphviz may draw them
  larger to fit the label (checked: never smaller).
- **Not drawn**: border width and style, italic labels, edge tooltips, images, gradients beyond the
  first color, node styles with no 3D counterpart (tables, BPMN symbols).

Judgment calls a reviewer may still challenge: which alias each foreign arrow or line name maps to
(the cx2js check challenges one: Cytoscape `ARROW` as `vee`), and when a recovered mapping is real
rather than a coincidence (the planner's guards removed every coincidence found in 1,936 real and
fixture files, and cannot prove none remain).
