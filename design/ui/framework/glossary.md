# Glossary

This document names every concept in `conceptual-model.md` and every operation a user can see. For
each term it gives its tier, a one-sentence definition, the synonyms that were rejected and why, the
evidence behind the choice, and the name graphty-element publishes today. It is the one authority
for names: `element-contract.md` owns shapes and behavior and quotes its names from here. Where a
published name must change in a way consumers or saved files would feel, the entry is marked
**ONE-WAY DOOR**; those are collected for the owner in section 17.

Every concept belongs to graphty-element, so every word here is graphty-element's word first. The
graphty app shows these words; it never invents its own.

## 1. Tiers, and how the screen stays small

Every entry carries one tier, the most visible place the word may appear:

| Tier       | Where the word may appear                                                      | Cost of changing it                  |
| ---------- | ------------------------------------------------------------------------------ | ------------------------------------ |
| **Screen** | the interface (label, menu item, tooltip, state line, (i) text), and also docs | an edit                              |
| **Docs**   | documentation and API names only; never the interface                          | an edit, unless it is also published |
| **Design** | the framework documents only                                                   | an edit                              |

Whether a word is **published** (in graphty-element's API, catalogue data or project file) is a
separate column, because a Screen word can be published too ("run", `Run`). A published name
changes only through section 17. A screen word and a published name for one concept may differ
only when the published name is a developer's name no screen shows (the scope value `"visible"`
behind "filtered graph"); every such pair is mapped once, in section 17.

**The screen-word rule**, which a reviewer can check line by line:

1. Every word on screen is in this glossary with tier Screen, or is a field term from section 12,
   or an interface word from section 13.
2. Nouns come in three lists that never mix. **Primary object nouns** name the graph objects the
   analyst selects: graph, node, edge, set, path (found path; its kinds trail, walk, cycle), group
   (community, component, k-shell, cluster, category). **Secondary object nouns** name what
   is applied to, written about or captured from them: attribute, result, run, pair, comparison,
   style layer, note, view; and the file nouns project, recipe and style file. **Working-state nouns** name things that are not objects: selection,
   filter, working set, scope, time window, layout, camera, view mode. A new object noun needs a
   new object type in `conceptual-model.md` 1.
3. **State words** are only those in section 10, and **verbs** only those in section 9 and
   Figma's standard commands in section 13.
4. The rejected-synonym columns are a word list: before a framework document is reviewed, each
   rejected screen word is searched for across `design/ui/framework/*.md`, and every hit outside
   a "Rejected" cell or an alias list is fixed.
5. **A proposed published name is checked against section 14 and against graphty-element's
   existing identifiers before it is proposed.** Published names are the one-way doors, so a
   collision caught after release costs a major version.

## 2. How a word is chosen

Applied in order; the first rule that answers wins.

1. **A graph or statistics concept takes the field's word**, spelled as NetworkX, igraph, Gephi,
   Cytoscape and Newman's "Networks" spell it. No friendly substitute ever reaches a label.
2. **An interface concept takes Figma's word**, unless that word already means a graph concept or a
   different published graphty-element concept. Then the graph or published meaning wins, and
   Figma's word is used for nothing.
3. **A concept only graphty has takes a short plain word**, or no word at all if no user ever needs
   to name it.
4. **A published name that is correct is kept**, even when a different word was tempting. A
   published name is renamed only when it makes the published documentation false or collides with
   a word the screen needs.
5. **Every rejected synonym becomes a command palette alias**, so typing it finds the right thing,
   but it never appears as a label (section 15).

## 3. UI-copy conventions

- **American spelling everywhere**: UI text, (i) text, API names, catalogue data, docs and these
  documents: neighbor, neighborhood, color, behavior, canceled, normalize, honor. Most published
  identifiers already use it (`neighborsOf`, `color`, "The batch was canceled." in
  `graphty-element/src/session/runs/RunsApi.ts`), and so do Figma, NetworkX and Gephi. The
  exceptions are catalogue content ("Eight Distinct Colours", "Node Colour", "Coloured output")
  and one event name (`animation-cancelled`); section 17 fixes both. Two spellings of one word
  break search in the docs and the command palette.
- **Sentence case** for every label, menu item, heading, button and tooltip: "Create set", "Out of
  date". Only the first word and proper nouns are capitalized, as in Figma ("Create component",
  "Show version history"). Catalogue content in Title Case ("Spread Out, Flat") is fixed in
  section 17.
- **Proper nouns keep their spelling**: PageRank, HITS, Louvain, Leiden, ForceAtlas2,
  Fruchterman-Reingold, Kamada-Kawai, Barnes-Hut, Jaccard, Adamic-Adar, Spearman, Kendall,
  Benjamini-Hochberg, Dijkstra, Katz.
- **Acronyms** appear on screen only where the field uses the acronym as the name (HITS, BFS,
  NMI, AMI, ARI, AUC), and the (i) spells it out.
- **Metric names are lower case in running text** unless proper nouns (betweenness, closeness,
  k-core) and take sentence case in a label ("Betweenness").
- **Hyphenation follows the field**: in-degree, out-degree, k-core, k-shell, k-hop, self-loop, ego
  network (no hyphen).
- **Commands are verb plus object** and stand alone in the command palette ("Create set", "Filter
  to selection", "Add note"); no command is a pronoun ("these", "them"). A row button may use the
  short verb its row gives context to ("Revert", "Correct"); its palette command carries the
  object ("Revert view", "Correct values"). A command that needs more input ends in "..."
  ("Compare with...").
- **Three creating verbs, one job each.** **Create <object>** makes a primary object (Create set,
  Create path). **Save <thing>** captures transient working state as a secondary object (Save view,
  Save comparison). **Add <thing>** attaches a child, an annotation or more data (Add
  note, Add style layer, Add data); a "+" button's tooltip reads "Add <thing>".
- **Inspector sections are nouns**: Statistics, Members, Memberships, Attributes, Appearance,
  Layout, Notes, Used by, Export.
- **Counts carry their unit and, for a part, their whole**: "1,204 of 5,310 nodes", "rank 3 of
  5,310", "212 communities". Thousands take a comma.
- **A missing value names why it is missing**, never 0 or a dash: "not computed" for a result or
  expression attribute on an element outside its scope; "no value" for an imported, joined or
  authored attribute; "(none)" as the name of a categorical attribute's group of missing values.
- **Automatic names are the kind plus a counter** ("Set 1", "View 2"), as Figma's "Frame 1".
  Results are named by algorithm and the parameter or scope that distinguishes them: "PageRank",
  "Louvain (resolution 1.0)", "Betweenness, without Supplier X"; a sampled method's result is
  always a separate result named with "(sampled)" ("Betweenness (sampled)").
- **Chrome is barely named.** Panel names appear in tooltips, docs and the command palette, not as
  headings. The view-mode button shows only its value ("3D").
- **(i) explains a term and does nothing else.** At most two sentences: what the term means and,
  where it matters, what the analyst would otherwise get wrong ("Betweenness: how often a node lies
  on shortest paths between others."). A former friendly name survives only here. A run's record,
  the import report and caveats open from a **Details** link at the end of the state line (or the result's menu when no state applies),
  never from (i), so an (i) beside "Betweenness" always defines betweenness. An (i) defines; it
  never recommends or suggests an alternative (an alternative is a caveat's verb).
- **Scope is written one way.** The inspector field is labelled **Scope**; everywhere inline it is
  "on:" followed by the scope as a fact ("on: largest connected component, 812 nodes"; a rule's
  "degree > 5, on: confidence >= 0.7"), never an adjective. "Without <set>" and "Within each group"
  are scope values written after "on:" ("on: filtered graph, within each group"), not prepositions
  of their own. Only real states get a state word (section 10).
- **Plain ASCII** in every string: "--" for a dash, straight quotes, "->" for an arrow, "~" for
  the estimate mark.

## 4. The document and the primary graph objects

A **primary object** is a node, an edge, or a named object whose body is an **existing subgraph**:
nodes of the current data plus a stated edge reading, so it can serve as a scope without losing
what it is about. The graph, a set and a path pass; so do the result items a group and a found
path. The test settles every other result kind:

- A **pair** fails: it is about an edge that does not exist, so it is a scored row that links to
  its two nodes.
- A **flow** fails: its body is a value per edge, which is attribute data. Its support (the edges
  with positive flow) becomes a set through Create set.
- A **node list** or **edge list** (articulation points, bridges, a min cut) is a result whose
  items are nodes and edges, already primary; Create set keeps the list as a set.
- A **comparison** fails: it is a table about two states.

graphty-element applies the same test to decide what the set API accepts as a source, so the
ontology and the contract cannot drift apart. Figma's test, "can you draw a selection box around
it?", agrees with it but is not the definition. The project is the file that holds them.

(`research/design-method.md`, follow-ups "three vocabulary checks" and "the weight-role row");

(https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.csgraph.connected_components.html),
by changing its catalogue `meta.label`; the parameter key `strength` stays.

Published today: `WeightMeaning.meaning: "distance" | "strength"`

## 12. Graph and statistics terms

Screen tier, used exactly as the field uses them, each taught by an (i). No friendly substitute.

- **Structure:** directed, undirected, weighted, multigraph, parallel edges, self-loop, acyclic,
  directed acyclic graph (DAG), tree, forest, isolate,
  induced subgraph, edge subgraph, bipartite, degree distribution, articulation point (cut vertex),
  bridge (cut edge).
- **Degree family:** degree, in-degree, out-degree, weighted degree, neighbor count (distinct
  neighbors), core number.
- **Node and edge metrics:** betweenness, edge betweenness, closeness, harmonic centrality,
  eigenvector centrality, Katz centrality, PageRank, HITS (hub score, authority score), local
  clustering coefficient, eccentricity, participation coefficient (the share of a node's edges
  that leave its own group), Burt's constraint.
- **Overview rows:** node count, edge count, density, bipartite density, component counts, degree
  distribution.
- **Graph statistics:** transitivity, average clustering, diameter, radius, average path length,
  global efficiency, degree assortativity, attribute assortativity, reciprocity, modularity (a
  property of a partition, never of a node). The graph-level clustering value is always named
  transitivity or average clustering; the per-node value is local clustering coefficient.
- **Groups:** partition, hierarchical partition, cover, community, weakly and strongly connected
  component, largest connected component (qualified "weakly" on a directed graph), k-shell,
  k-core (a rule set), cluster.
- **Paths:** shortest path, simple path, trail, walk, cycle.
- **Time:** time window, time-window snapshot (in (i) text), series.
- **Comparison statistics:** Spearman rank correlation, Kendall's tau, top-k overlap, adjusted
  mutual information (AMI), adjusted Rand index (ARI), normalized mutual information (NMI), Jaccard
  similarity (over the node sets of two results), Kruskal-Wallis test, AUC (area under the ROC
  curve).
- **Multiple testing:** false discovery rate (Benjamini-Hochberg).
- **Link prediction** (NetworkX's names): common neighbors, Jaccard coefficient (the same formula
  as Jaccard similarity, over two nodes' neighbor sets), Adamic-Adar index, resource allocation
  index, preferential attachment.
- **Null models:** null model, configuration model, double-edge swap and stub matching (the
  samplers), z-score, empirical p-value.
- **Layout parameter:** approximate repulsion (Barnes-Hut).

**Parallel edges** on screen reads "N extra parallel edges", because the published
`repeatedEdgeCount` counts the edges beyond the first between one pair of ends. The import policy
`repeatedEdges` is a separate control, "Parallel edges: Allow / Merge into one".

### Doors opened by recipes, attributes and filtering

`one-way-doors.md` 19 to 26 hold the names these revisions would publish: the recipe profile and

`"filtered"` beside `"visible"`, a scoped `properties(scope)`, typed traversal on the

### Additive now, old name on the same schedule

`Result` (new container, with `Result.name`) beside `RunResult`; `Run.name` beside `Run.label`;
`freshness` (`current`, `out-of-date`, `cannot-rerun`, `detached`, `unresolvable`) and `scopeDiffers` beside
`Run.stale`; `StaleNote.nowCovers` beside `nowVisible`, whose doc says it counts what the scope
resolves to, not what is visible; the origin value `authored`; shapes `cover`, `flow`,
`comparison`; a session pin API beside `element.pin()`, which the element contract's
"Layout settings and pins" row needs; the event `animation-canceled`, fired together with
`animation-cancelled` during the deprecation period and documented as firing both. Renaming
`NumericColumnView` is optional and API-only.

- Algorithm plainNames leave labels and become (i) text: Connections, Incoming connections,
  Outgoing connections, Bridges, Bridging, Reach, Influence, Influence by association, Influence

  pieces, Shortest route (and its "route" fields), How far from everything else, Steps away,
  Exploration order, Cheapest connecting network, Best pairing, Most that can flow, Weakest link,

  Grouping, No Crossings, Scattered, Tree, Two Columns, Columns by Group, Keep Positions
  (`catalog/layouts.ts` lines 347-513). The `hierarchical` technicalName "Layered layout" becomes
  "BFS layout". The `ngraph` entry's reason, "a Barnes-Hut simulation" (line 156), becomes "a
  spring-electrical simulation with Barnes-Hut approximate repulsion".
- Every plainName and label in American spelling and sentence case ("Eight distinct colors",
  "Node color"), enforced by a catalogue lint that rejects "colour" and Title Case.
- The components parameter's `meta.label` becomes "Connection"; no `connection` key is added.
- `spiral` and `planar`, which have catalogue entries and engines, join `KNOWN_LAYOUT_IDS`.
