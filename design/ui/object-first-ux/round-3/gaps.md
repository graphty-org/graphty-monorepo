# Gap register: key functions the object-first design does not draw

This register lists every function that the app needs in order to work, or that a reader needs for
data analysis or visualization, and that the second round of the object-first design
(`design/ui/object-first-ux/round-2/revision.md` and the mocks in
`design/ui/object-first-ux/mocks/v2/`) does not give a visible, drawn way to do.

## How to read it

- **Key function.** Either (a) required for the app to work end to end: getting data in and out,
  saving and reopening work, undo, finding things, moving around the canvas, selecting, settings
  that change behaviour, errors and recovery, large data; or (b) a data-analysis or visualization
  feature: algorithms, filters, paths, comparison, time, layouts, styling, labels, legends, 3D and
  VR, exporting pictures and data, notes. Onboarding, wizards, suggestion cards and tips are not
  key and are not listed.
- **Gap.** A key function for which no mock draws both how the reader gets to it (the _entry
  point_: the button, menu row or key) and what they see once there (the _main state_).
- **What v2 had** uses three words:
    - _absent_: no design document mentions it;
    - _text only_: a document describes it, but no mock draws it;
    - _entry only_: a mock draws the button or menu row, but never what it opens.
- **Resolution** names the screen that now draws the gap and the document section that now
  specifies it. Every gap is resolved; the consolidated design is `round-3/revision-round-3.md`.
- **Sources.** "Previous app plan" is `design/ui/app-shell-progressive-disclosure-design.md`.
  "Workflow Wnn" is `design/designloom/workflows/Wnn.yaml`. "Figma" is `design/ui/figma/`.
  A number after "#" is a GitHub issue on graphty-element.

owns its own screens and its own document sections, so no two designers edit the same place.
