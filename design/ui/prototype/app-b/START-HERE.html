Refined B, version 5: your decisions since version 3

What the studio did with each of your decisions, and where to click. "Your decision" means you decided it; everything else is a studio decision, reversible with an edit. The user study runs on this skeleton without waiting for your review.

1. Notes are part of graphty-element's API (your decision)

The element stores notes, issues their ids, stamps time and author, saves them with the project, undoes them and announces changes; the app only draws them. The API copies the kept-sets API, so a developer who knows sets has nothing new to learn. Styles can read a node's note count and latest note, so the Notes row is an ordinary style layer. A note whose target disappears is kept, never silently deleted. Every note control is enabled except noting an edge picked on the canvas, which waits on edge picking; an edge is noted from the table.

See Notes placeNote on an edgeTarget missingNotes as label fields

2. Note metadata, and no name as the normal case (your decision)

Required: the time and one or more targets (node, edge, group, path, run, filter step or the graph). The studio also requires text, because a note with no text only marks something, and marking is a kept set's job. Optional: author, edited time, and the runs a note rests on. Tags, status, replies and colors were left out. The name is entered only in Settings > General > Your name, kept per person and never saved in the project, so it cannot be stamped on the next person's notes. With no name, a note shows its time alone: no "Anonymous", no empty slot. Names appear only when a project has notes from two or more people. Nothing asks for a name on the way to a note.

See No namesTwo peopleWriting a noteYour name

3. Label "+" starts empty; several labels per node (your decision)

"+" adds a line and opens the field list at once; Esc leaves it reading "Pick a field", drawing nothing. Each line owns a position (Above, Below, Right...), and a new line takes the first free one, so names above and note count below is two presses. Keying by position is what lets a higher row override Above while a lower row's Below still shows.

See Empty lineTwo labelsPosition grid

4. Several data sources joined on any key column (your decision: a primary task)

One Data page replaces the load dialog for every load; a clean single file still loads with one Enter. Each table is "a node" or "an edge" table; roles (Key, From/To, Name, Time, Weight...) are set under column headers; "One edge per: Row | Pair" merges repeats with a count and earliest and latest times. The match report always shows what did not match and offers Add or Leave out. Your door-entries example works end to end, including each entry as its own node. The March transfers are the second domain.

5. Weight is chosen when the data is loaded (your decision)

Weight is a role on the Data page, and what a higher weight means (Stronger, Farther or Capacity) is set once per graph in its footer. Every run uses it; a run may override it for itself, recorded in its Made with and never written back. Without a declared meaning, a count read as a distance makes the most-used link the farthest.

See AnalyzeA run's overrideNode weight

6. Wide data: one field list everywhere (your decision: before the study)

The sample is an IT estate: 300 hosts with 69 attributes and 1,105 connections with 26. Every place that shows or picks an attribute now uses the same field list, in a panel size (Data > Attributes, the inspectors, the table's columns) and a menu size (bind, Label "+", Color, Size and Width by, filter steps, a link's "by" column, Go to column). Search appears past 15 items and matches word starts, so "cpu p95" finds cpu_util_p95_pct. Fields are grouped by table; "In use" comes first, each tagged with what uses it, as an order rather than a toggle a reader would forget is on. Long names are cut in the middle, because an end cut makes cpu_util_p50_pct and cpu_util_p95_pct look identical. The table freezes its key column and shows "Columns: 8 of 69", the one place a column can be hidden. Why: seven surfaces each behaved differently; now there is one way to find a field.

On the Data page, roles stay under the column headers. A column with no role reads "Attribute" in quiet text, columns with a role pin left after the key, and Find a column jumps to a header.

7. Nested JSON (your decision: before the study)

Plain graph JSON (node-link, d3, JGF, Cytoscape, graphology, vis, NetworkX) loads in one step as a graph file. Any other document is a source of tables: its row opens into a tree of objects and arrays with item counts, and the likely tables arrive ticked. Sub-objects become dotted columns at any depth, grouped under a parent header whose menu offers Keep as one value. An array in a record is chosen in its column's role menu as One value, Several values, Several edges or Several rows, each showing its count ("Several edges (514 edges)"). "First item" was rejected: it drops data silently. Refusals show on the tree row they concern. Why: every choice reuses a control the page already has.

8. The state matrix (your decision: before the study)

67 surfaces, every section plus shared components such as the field list and the problem block, against ten states: Empty, Loading, Error, Partial, One, Typical, Many, Long text, Narrow (a real 1024 x 768 window) and Waiting on graphty-element. Every cell is a route you can open or "N/A" with its reason; none says "falls back to". It names 326 distinct routes, 106 of them added for it, and a table of ten regressions, each with its own route and check. Narrow routes end in @1024, for example the graph at 1024.

The matrix: study/structure-comparison/state-matrix.md.

What graph-io and graphty-element must add

study/structure-comparison/element-requirements-5.md keeps version 4 whole and adds three sections. Wide data: graphty-element reports what uses each attribute, its parent in the nesting and its short name, and list attributes. Nested JSON: graph-io describes a document's tree, reads paths, flattens sub-objects, turns arrays into lists, edges or child tables, and gains new issue codes; graph-format gains a list type; graphty-element's JSON source reads every dialect (today it forces node-link), previews counts per choice, links to several types, and has one path reader that errors on a path that reads nothing. Searching and ordering the list stays in the app.

Success criteria from the last check

Met: every field was found in one to three words on every wide picker, Find a column jumps to the right header, role menus give reasons instead of a wall of controls, the inspectors collapse to "N more attributes". The four earlier defects are fixed and each has a route: Shift+Arrow walks nodes, a removed chip stays removed, the selection bar after a click, linking by badge.

Not met: "see which fields are in use". With two filter steps on, the Attributes list still says "In use (2)" with only id and hostname; environment and the critical-vulnerability count should be tagged Filter step.

Open

A blocker before nested-JSON tasks: researcher names. The inspector and the canvas walk call a node "Wei Diallo", the table calls it "Diallo", and the Data page never gives any column the Name role, so a participant sees names they never chose, two ways. The Data page should propose Name on the family-name column and every surface should read that one field; a name built from two fields would be a new graphty-element requirement.

The full click crawl of all 503 routes has not finished, so dead controls are not yet ruled out.
