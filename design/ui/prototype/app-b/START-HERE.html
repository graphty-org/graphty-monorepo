Refined B, version 2: answers to your eleven questions

Each answer says what changed and where to click. "Owner decision" means owner-feedback.md records it as yours; everything else is a studio decision. Anything marked "needs graphty-element" is drawn disabled and listed once in spec section 19 (structure-b-refined.md).

The eleven questions

1. The Everything layer shows only some styling options

Every row that paints gets one Style tab, generated from graphty-element's own list of 35 style properties (13 node, 22 edge) plus the label style, in fixed sections: Fill, Shape, Effects, Label, Tooltip for nodes; Line, Arrow head, Arrow tail, Label for edges. A row shows only what it sets; "+" adds any other property and a search icon finds one. That keeps rows short, and a property the element adds later appears with no app change.

See EverythingAdd a property

2. Rename by double-click

Your direction, done as Figma does it: double-click the name, Enter or click away saves, Esc cancels, and Tab moves to the next row so twelve communities can be named in one pass. F2 renames from the keyboard. The same gesture renames graphs, folders, saved views and the project.

See RenamingTab to the next row

3. Add data and Paste data belong under Data; Tableau's Data Sources

Yes, within what graphty-element supports. Data > Sources is the one place data enters a graph (file, URL, paste); File loses both items, and the load dialog ends with "Load into: this graph / replace this graph / a new graph". In Tableau a workbook holds many sources; in graphty a project holds many graphs, so "a new source" is usually a new graph. Joins, live connections and filter-at-import are drawn as needs graphty-element, because building them in the app would be a workaround.

See Sources menuLoad into

4. Notes as a style layer; styling left to the user

Yes. How noted elements look is now a built-in Notes row under Selection, with the same Style tab as every row. Its default is an outline, and you can choose any look or none. The old callouts painted outside the layer system, so they are deleted. General rule: the app adds no look of its own; only the element's defaults and a run's suggested style (owner decision) arrive unasked.

See Notes row

5. "Why this look" takes too much room

It now lists one line per layer that wins at least one property, e.g. "PageRank -- color". Layers that match but lose collapse into one line. Valjean's section drops from about 20 lines to 4 or 5. The list comes from the element's explain(), so the app computes nothing.

See Valjean

6. Toolbar on the left; Path under Select

The toolbar stays fixed at the bottom center. Toolbar labels are Auto, Always or Never in Settings; Auto drops them when the bar would pass about 60% of the canvas width. Space is not the limit: no element capability passes the test "changes what the next click does". Path leaves the toolbar but does not go into Select. With two nodes selected, the selection bar offers Path between, because a path is a one-shot query, not a mode. Hand is dropped, since a plain drag already pans.

See ToolbarPath between

7. All of graphty-element's functionality

Spec section 18 is a capability register. Every graphty-element capability gets one outcome: a home in the UI, a catalog generated from the element, plumbing with a stated reason, or a gap filed against the element. The biggest additions are camera views (question 8), Export > Image and Export > Video, an Analyze catalog generated from the element, and layout pause and resume.

See ImageVideo tourAll algorithms

8. Views, Present or Export on the rail; cameras

Views returns to the rail: Graph, Data, Views, Notes, Assistant. It holds the built-in and saved views in one draggable order, which is also the presentation and tour order. Present and Export are verbs, not places, and jumping to a camera is not a tool. You were right that camera controls existed but were hidden: the "100%" chip is now a Camera menu named after the current view.

See ViewsCamera menuPresent

9. One home per feature

The rule is kept and made testable. Every object and every piece of state has one home. A command can have many doors (keys, Quick actions, context menus, the selection bar), but a door never holds state. The main menu shrinks to File, Edit, Settings, Help. View mode lives on the toolbar only, labels and arrows become style properties, and the minimap is dropped. Spec section 17 has the full table.

See Main menu

10. Preferences versus Settings

They are the same thing, so it is renamed Settings (Ctrl+,). It now holds only per-person settings: your name, privacy, appearance, accessibility, canvas input, GPU use, Assistant provider and keys, headset, keyboard and diagnostics. Anything the project carries lives on the object it configures.

See PerformanceHeadset

11. Cluttered right sidebars

Every kind of selection now uses one frame: a header (name, kind, "..." menu), an optional state bar holding the only button (e.g. "Settings changed -- Rerun | Revert"), then Style and Data tabs in a fixed order. The rule: the sidebar shows properties, read and edited in place, and holds no verbs. Verbs move to "...". The layout method and its options are properties that re-lay the graph at once. Re-run layout lives in the canvas menu and Quick actions.

See State barLayout

What else changed

The app opens in 3D, which is the element's default. Edges are picked from the table, because the element cannot pick them on the canvas. A too-large graph is refused. Single-key shortcuts move off the element's camera keys (Analyze is now Shift+A).

graphty-element capabilities newly given a home

Saved camera views and tours; image and video export; Isometric and plugin views; Katz, HITS, Girvan-Newman, BFS, DFS, Prim, bipartite matching, min-cut and all-pairs distance; GML, DOT, Pajek and every CSV shape; all 7 repeated-edge policies; layout pause, resume, unpin all and pin on drag; GPU policy and live status; headset settings; the import report.
