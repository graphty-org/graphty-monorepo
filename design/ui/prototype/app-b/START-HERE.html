Refined B, version 4: your decisions after version 3

What the studio did with each of your decisions, and where to click. "Your decision" means you decided it; everything else is a studio decision, reversible with an edit. The user study runs on this skeleton without waiting for your review.

1. Notes are part of graphty-element's API (your decision)

The element stores notes, issues their ids, stamps time and author, saves them with the project, undoes them and announces changes; the app only draws them. The API copies the kept-sets API, so a developer who knows sets has nothing new to learn. Styles can read a node's note count and latest note, so the Notes row is an ordinary style layer. A note whose target disappears is kept, never silently deleted. Every note control is enabled except noting an edge picked on the canvas, which waits on edge picking; an edge is noted from the table.

2. Note metadata, and no name as the normal case (your decision)

Required: the time and one or more targets (node, edge, group, path, run, filter step or the graph). The studio also requires text, because a note with no text only marks something, and marking is a kept set's job. Optional: author, edited time, and the runs a note rests on. Tags, status, replies and colors were left out. The name is entered only in Settings > General > Your name, kept per person and never saved in the project, so it cannot be stamped on the next person's notes. With no name, a note shows its time alone: no "Anonymous", no empty slot. Names appear only when a project has notes from two or more people. Nothing asks for a name on the way to a note.

3. Label "+" starts empty; several labels per node (your decision)

"+" adds a line and opens the field list at once; Esc leaves it reading "Pick a field", drawing nothing. Each line owns a position (Above, Below, Right...), and a new line takes the first free one, so names above and note count below is two presses. Keying by position is what lets a higher row override Above while a lower row's Below still shows.

See Empty lineTwo labelsPosition grid

4. Several data sources joined on any key column (your decision: a primary task)

One Data page replaces the load dialog for every load; a clean single file still loads with one Enter. Each table is "a node" or "an edge" table; roles (Key, From/To, Name, Time, Weight...) are set under column headers; "One edge per: Row | Pair" merges repeats with a count and earliest and latest times. The match report always shows what did not match and offers Add or Leave out. Your door-entries example works end to end, including each entry as its own node. The March transfers are the second domain.

5. Weight is chosen when the data is loaded (your decision)

Weight is a role on the Data page, and what a higher weight means (Stronger, Farther or Capacity) is set once per graph in its footer. Every run uses it; a run may override it for itself, recorded in its Made with and never written back. Without a declared meaning, a count read as a distance makes the most-used link the farthest.
