Take a note

An analyst writes down why a finding matters, on the thing it is about: a set, a node, a result, or the graph itself. The note says what it is about before a word is typed, records who wrote it and when, cites the runs it rests on, and is waiting on that same object next week, marked if the numbers under it have changed. It leaves the project inside the project file and the findings report. Every shape in the diagrams links to the screen state it shows.

WhoSarah, a fraud investigator, has kept 14 flagged accounts as the frozen set "Mule ring" in March's 3,000-account transfer network (the graph "Transfers") and wants the reason on record before she writes the suspicious-activity report. The same flow serves a researcher writing "why did I keep this set?" in a weekly analysis.
StartSomething selected, or nothing selected. Same at every graph size.
Claim at the end"This finding is about these objects, rests on these results, and was written by me at this time."
What is recordedOne undo entry, "Add note"; the note's targets, its text, its cited runs and quoted values as written, its author and its date and time.
Compared with FigmaFigma: the Comment tool, a click on the canvas, typing, Enter. Nothing exists until Enter posts it; the composer opens at the pin and the posted thread opens in the same spot; every comment carries its author and time. graphty keeps all of that except the tool. A note is written with Add note..., because the selection already says what it is about, and a canvas click on one account is how the study's analysts pinned a group's reason to one member by mistake. A note is pinned to graph objects, never to a canvas position, because positions move at every layout. And notes live in a panel on the left rail beside a visible inspector, rather than in a mode that replaces the inspector.
Usage dataAlready decided before this flow: graphty asked Sarah once, at first use, whether to send usage data, and it stays off unless she said yes. Taking a note asks nothing and changes nothing about it. If she did say yes, a note's text, what it is about and the values it quotes are never sent: they are graph content, masked like every node name and value. The choice is in Preferences, Usage data (Where your data goes).
Needs graphty-elementAll of it. Notes do not exist in graphty-element yet: it needs a notes collection with targets, citations, quoted values marked when the live value differs, and an author and time on each note; an undo slice for notes; the note markers on the canvas; and the findings report writer that puts notes in the report. Discarding an empty note is part of the collection's commit rule, so it is the element's too. Dashed shapes below wait on these.

Decided by the owner, applied here

  • Each note records its author and its date and time. The author is the project's author setting as given, "Your name on notes and recipes" in Preferences, blank if it is not set. The author's name is shown only when the project holds notes by more than one author; the date and time are always shown in full ("Sep 28 2026, 10:14").
  • Usage data is off until the person says yes, asked once at first use, and never holds graph content. This flow never asks it again; it is shown as the choice already made, in the table above.
  • The findings report is one self-contained HTML file. Notes go into it as real text, with what they are about, who wrote them and when, what they cite and the values they quote. It opens offline in any browser and prints to PDF.
  • There is no Note tool (decided on the owner's behalf, reversible). Every note starts from Add note... Adding a tool later is additive; this flow's open questions say what would justify one.

Where it shows next session

A week later Sarah reopens the project. Her notes are in four places: the Notes panel on the rail (every note, newest first), the Notes section of each thing a note is about, a marker on the canvas at its targets while Note markers is on, and Find. Choosing a note goes where the note is about. A month later the data has been replaced with April's, and the note says what changed under it.

Where it leaves the project

Notes are saved in the project, so they go wherever the project file goes. They reach the case file through the findings report, which Sarah writes from Export... on the Data panel or the menu under the project name.

Counts, keyboard and where it goes wrong

  • Steps from rest: with the set selected, 1 step and 1 travel (opening the overflow) plus typing. With nothing selected, 2 steps (Add note..., choose the set) plus typing. Figma's comment is 2 steps plus typing.
  • Several notes in a row: on one subject, each further note is 1 step, because About remembers the subject. On different accounts, select each and Add note...: 2 steps a note, and the selection is changed each time.
  • Keyboard route: select with Find or the keyboard walk, then Add note... from Quick actions; or, with nothing selected, Add note... and choose the set with the arrow keys in About.
  • First failure: a note meant for a set lands on the whole graph. In the third study, the empty panel's button did exactly that for one of two first-click participants, and another pinned his group's reason to one member with the old Note tool. Now, with nothing selected, About: is the first thing focused and lists the kept sets, so the set is one choice away and the graph is never taken silently (the About field).
  • After the data changes: a month later, with April's transfers in place of March's, the note still cites the March PageRank run and still quotes ACC-753261 at 0.000551. The citation reads "Earlier data" with Add current value, and the quote reads "now 0.000428": in April ACC-946224 ranks highest in the ring, so the note's claim needs checking before the report goes out (state 8).

What the study showed works, kept

  • Clicking a note selects its accounts and brings them into view: "That is exactly the 'next week' thing."
  • Add note... is in the same place for one account, several, and a kept set.
  • A note keeps the value it quoted and marks, rather than rewrites, itself when the numbers change.
  • The empty panel says in one line where notes are kept and that they leave only with project files and findings reports.

Open questions

  • A source and a grade on a note. One investigator asked for the record a note came from, and a grade, as on an intelligence chart. It would add fields to the project file and the findings report, so it is a file-format decision for the owner; one voice so far, not designed.
  • Changing what a note is about. About is fixed once a note is added, so a note written on the graph by mistake is fixed only by writing it again and deleting the first. Is that right for an audit trail, or should a change of target be allowed and shown in the note's history?
  • Does the editor need to say that Esc keeps the text? An analyst who expects Esc to abandon a note gets a committed note instead. Test: ask the personas to write a note and back out of it.
  • When would a Note tool earn its place again? Only if analysts write notes on many different accounts in a row, where selecting each one costs a step and replaces the selection they built. Test that case with the fraud and bioinformatics personas before proposing it.
  • Should an audit note offer Add current value at all? Re-citing the April run changes what the note rests on. For a report already filed, an investigator may want the March citation kept with only the mark. Ask the fraud persona.

The screens

Two mocks carry this flow: Take a note (writing beside the ring, the note added, a note on a result, and the note after April's data) and the Notes panel (the empty panel, the About field with nothing selected, author and time on each row, the row menu, Find, Detached and Bring back). Each has light and dark themes and a "Design notes" toggle that cites the framework section behind each element and the compact-mantine component it would be built with.

Decisions made here, proposed to the framework

Where the framework was silent or contradicted itself these mocks decided; each is written up in the proposed framework changes, under "Take a note" and "Notes".

  • One place to write and read: a new note opens in the same Note editor, beside its targets, that reading uses, as Figma's composer does. The inspector's Notes section lists notes and offers "+".
  • Add note... with nothing selected asks what the note is about first, listing the graph, each kept set and Select something first, and the next Add note... remembers the subject.
  • Enter starts a new line; Ctrl+Enter adds (Cmd+Enter on a Mac), with both keys said under the box. Figma's composer adds on Enter, but analysts' notes run to several lines and Enter posted half-written text in testing; Esc with text adds and closes; Esc on an empty note leaves nothing.
  • How a note cites and quotes: "Cite a run..." and "Quote a value..." inside the Note editor, over the note's own targets and cited runs only.
  • Every note being written or edited says "Saving as: {name}. Change...", and the author setting says "Applies to notes you save from now on." Earlier notes never gain a name, and nothing offers to claim them.
  • A changed quote is marked "now {value}", beside the stale citation's "Earlier data".
  • What a note is about is fixed once it is added, so the note stays evidence of what was written about what.
  • Edit note, Delete note and Bring back are one undo entry each.
