# Milestone 1: the first complete set of storyboards, flows and mocks

The gallery now holds a full first pass over the design: 6 storyboards, 13 task flows and about
40 screen mocks, all built from compact-mantine's components and realistic data (Les Miserables,
a 300-protein network, 3,000 bank accounts, 124,318 patents). No simulated
user has seen any of it yet. What the study will test is written down as bets, one page per task,
each with a task that never names the answer.

Building the mocks surfaced gaps the design documents had missed; the studio fixed those it
could decide. Every mock now shares one set of keys, one name per thing, and compact-mantine's
sizes and colors. The alert-triage story was redone so that a new junior
reviewer clears alerts and the fraud investigator works only the referred case. The weekly-return
story now belongs to the investigator whose data it is. The biggest open problem: a filter step's
result depends on where it sits in the list, and today only a count shows that.

Questions for you:

1. The evidence file an investigator hands on: should it be one self-contained HTML file (opens
   in any browser, prints to PDF, tables stay copyable), or a PDF? Other tools will read this
   file, so it is hard to change later.
2. Should the project file save the selection when it closes, so an analyst who stopped mid-case
   can get the 14 flagged accounts back? It adds a field to a published format.
3. Notes: is a separate Note tool worth keeping when Add note already has six ways in? If it
   stays, its key would be C, as in Figma's Comment tool.
4. On the filter-chip page, a step in the wrong place takes out 15 characters instead of 1.
   Would you have noticed? Is the proposed warning mark enough?
