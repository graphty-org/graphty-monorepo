On the graphty-element backlog

Everything below is drawn on this page as graphty-element behavior. The app only shows what the element reports; a third party using graphty-element on its own gets the same checks, suggestions, directions and floors.

  1. One too-close check for every pair of colors in a layer. It runs on picked and default colors alike and reports each close pair with both color names and the color vision it models, for example "Orange and vermilion are too close for red-green color blindness (deuteranopia)." It simulates deuteranopia, then measures the color difference; a pair under the line is flagged. Today the element's own default palette fails it three times in one layer: orange #E69F00 against vermilion #D55E00, orange against yellow #F0E442, and reddish purple #CC79A7 against Other's light gray #BDBDBD (states 7 and 8). The default palette itself should be revisited so a fresh layer starts with no flags.
  2. Suggested colors when the palette runs out. With every palette color in use, the element offers colors that clear every other color in the layer by the same check; here wine #882255, brown #8C510A and indigo #332288 for DNA repair (state 7).
