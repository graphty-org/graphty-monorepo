The start screen says files are read in the browser and not uploaded. People liked that line, but the IT and security reviewers who approve tools could neither check it nor forward it. This page answers them: what stays in the browser, what leaves it and to whom, and what the page does not promise. Its home in the app is Data > Sent and saved, the list of everything this project has sent and written; the privacy line under the project name opens that list, and the list links here. So there is one place that says what left, and one page that says what can. The page now also says how long an Assistant key is kept and how to forget it, and that no password or key ever appears in that list, an exported copy of it, or a project file. Hosting, telemetry, running your own copy and an organization-wide way to turn the Assistant off are not decided yet, nor is where a data-source password is kept; the page marks each one in pink until the owner decides. Section 3 draws what the app itself says, as it happens, when the Assistant or a data-source query sends something. Turn on annotations to see the design rule and the compact-mantine component behind each part.

Where your data goes

graphty draws and analyzes graphs inside your web browser. This page says what stays in the browser, what leaves it, when, and to whom. It is written so you can forward it to whoever approves software where you work.

Describes graphty 2.0. Updated September 28, 2026. Copy link Print or save as PDF
A document, not a dialog: a page with its own address opens in a new tab so the link can be forwarded and the page printed. Nothing on it depends on this browser's state, so the reviewer reads exactly what the analyst read. The version and date say which release it describes. The framework has no page like this; proposed in framework-changes.md. Mantine Title, Text; Button (secondary) for Copy link and Print.

In short

  • Files you open are read by this browser and are not uploaded. graphty has no account and no server that receives your data.
  • Data leaves the browser only through two features, both off until you turn them on: Connect to data source and the Assistant.
  • Projects are kept in this browser, on this computer only.
  • No password or key ever appears in the list of what was sent, in an exported copy of that list, or in a project file.
The sentences a reviewer can quote, in the same words as the start screen's two lines, so every place that talks about data agrees. The fourth names credentials, because in the study every regulated reviewer asked whether a password could end up in a log or a file that gets forwarded; "the list of what was sent" is Data > Sent and saved, and its exported copy is that list's Export log. That the element keeps secrets out of its operation log and project file is an element need (framework-changes.md, "Where your data goes becomes the home of Sent and saved"). content-design.md 2, voice; the start-screen proposal in framework-changes.md. What stays in this browser

WhatWhere it is kept
Files you openRead from your computer into this browser's memory. CSV, JSON, GraphML, GEXF, GML, DOT and Pajek files are all read the same way. The file is not copied anywhere.
ProjectsThe graph, its results, styles, sets, views and notes are kept in this browser's storage for graphty, on this computer. They are not synced to another browser or computer. They stay until you delete the project or clear this site's data.
ExportsFigures, tables, recipes and project files are written by your browser's save dialog to the folder you choose. graphty keeps no copy.

What graphty does not send

  • No account, and no sign-in to graphty.
  • No file contents, graph data, results or notes, except through the features listed above.
  • No fonts, icons or code from other sites while you work: they come with graphty.
  • Usage statistics and crash reports:Owner decision open: whether graphty collects any. If none, this line reads "None: graphty collects no usage statistics and no crash reports." If some, it lists each, what it contains and where it goes, and how to turn it off.

Check it yourself. Open your browser's developer tools, choose the Network tab, and use graphty as usual. Requests go only to graphty's own address, except while you use one of the features listed above.

The negatives, stated so they can be checked: a bank investigator in round 1 said she would believe "uploads nothing" only after watching the network tab, so the page tells every reader how to do exactly that. Telemetry is an owner decision (framework-changes.md, Open decisions for the owner). Mantine List; the check is a Blockquote.

What this page does not promise

  • It does not cover what a data source or an Assistant provider does with data once it reaches them. Their terms, and your agreement with them, apply.
  • It does not keep projects safe from loss. Clearing this site's data, a private window, or a reset or re-imaged computer deletes them. Download project file, in the menu on the project's name, makes a copy you control.
  • It does not protect data from anyone or anything else that can use this browser: other people on the same login, browser extensions, or backups of the computer.
  • It does not follow a file after you export it.
  • It is a description of graphty 2.0, not a certification or a contract. When a later version changes any of this, this page changes with it and its date moves.
Limits said as plainly as the promises, because a page that only reassures reads as marketing to a reviewer. A re-imaged laptop losing Monday's setup was a fraud investigator's worry in the investigators focus group; the way to a copy is the chevron menu's Download project file (information-architecture.md, the left panel header). Mantine List.

Three ways in, all opening the same page in a new tab: the lock line on the start screen, before anything is opened; Data > Sent and saved once a project is open, the page's home in the app; and Help in the main menu, so it can be found again without starting over.

3. What the app says when something leaves

The page above is static. In the app, the privacy line under the project's name says whether anything has left, and opens Data > Sent and saved, the one list of what went, to which address and when. Shown on a bank analyst's March transfers, loaded by a query to the bank's own graph database, then asked about with the Assistant.

The privacy line under the project name (framework-changes.md, the start screen and header: "Nothing has been sent from this project", then "Sent to the Assistant: 2 questions. Nothing else."), with two wordings the framework does not yet have: after a data-source query, "Sent to {host}: {n} query. Nothing else.", and after both, "Sent: {n} query to {host}, {m} questions to the Assistant. Nothing else." (proposed, framework-changes.md, "Where your data goes becomes the home of Sent and saved"). The line is a Mantine Anchor that opens Data > Sent and saved, the reading home of every output (output-homes.md; the Data panel proposal); each send is one ActionRow naming its host, because the IT reviewer said a line reading only "Sent to: data source" is "useless to me". See what was sent is an Anchor opening a Popover of DataRows; Export log is a ghost Button in the section head. What a request carried must come from graphty-element's Assistant, which reports each send and keeps secrets out of it; the app only shows it (element need).
