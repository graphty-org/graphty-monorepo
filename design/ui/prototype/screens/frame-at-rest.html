What each part is, why, and what it is built with

  1. Rail. The main menu on top, then what the project owns: Graph, Data, Results, Notes, and the Assistant (22) last. Results is the one home of runs, each with its settings and date; a value is read on its node, in the inspector and in the table. information-architecture.md 5; framework-changes.md, "Places". NavRail, RailButton.
  2. Left panel header. The project name and its chevron menu. Not saved (state 6) or View only sits beside the name and shows only while it is true. interface-templates.md 2; interface-specification.md 1.2 and 3, the marks table. ActionRow, Mantine Menu.
  3. File chip. Names the file this graph's data was read from and stays in view whichever rail panel is open. Tooltip: "miserables.json, opened from this computer". A click opens the file popover (state 5): where the data is, where the project is kept, and where the data came from; whether the last save worked is in the project name menu (state 6). A proposal. framework-changes.md, "Main frame at rest: the file chip's popover holds the data file only". Mantine Pill.
  4. Filter chip. What every number on screen is computed on. Read-only until filter steps exist; the study checks whether anyone clicks it and is confused. interface-templates.md 7; implementation-mapping.md, slice 1. Mantine Pill.
  5. Graphs. One row, no count (Figma's page rows carry none; the size is in Statistics). Find on the header; the "+" is absent while several graphs are blocked, as every blocked command is. interface-templates.md 2; interface-specification.md 7.4. ControlSection, PageList.
  6. Sets and paths. Nothing kept yet: the header and "+" only, no "No sets yet" line. principles.md 5; content-design.md 4. ControlSection, Tree.
  7. Style stack (in the inspector, after Overview), drawn as on every other screen: the header carries the Look menu (B1) and "+", one line says the top layer wins, and each row has its drag handle at rest; Base style is always last and has none. The sample starts with one layer, Group color: every node is one size, so the one key on the canvas makes one claim. A size layer the reader adds goes on top, named for what it shows (state 9). No row carries an origin word: only a layer from a run or a recipe is marked, as Figma marks only a library style. The header's menu (Export style..., Source) shows on hover, as Figma's does. Chips: stacked chits for the categorical layer, the graduated glyph for size. interface-templates.md 9; canvas-drawing.md 3; framework-changes.md, "Only a layer that was not made here carries an origin word" and "The sample's starting look paints one channel". Tree rows with a leading chip.
  8. Views. Collapsed to its header. With no views it shows no count: an empty section is its header only. interface-templates.md 2; content-design.md 4, empty surface. ControlSection.
  9. Canvas. No text but labels, the legend and state cards. Labels follow the label budget with collision culling: where two would overlap, the lower-degree one is dropped (Thenardier yields to Javert). Nothing selected, so no marks. principles.md 5; canvas-drawing.md 9. Why these names are shown is said in the legend (23). graphty-element.
  10. Legend. One block per bound layer, titled by what it encodes. At rest one block: every group with its count, then Other (groups 6, 7 and 10, painted #BDBDBD) as its own row. Once size is added, a second block "Size: degree" with three graduated marks labeled 1, 10 and 36 (state 9). options-and-encodings.md 6, items 2 and 9; canvas-drawing.md 3; framework-changes.md, "Legends: a block's title says what the channel encodes". Drawn by graphty-element.
  11. Toolbar. Select, Path, Quick actions (26), and the view mode. Select and Path are icons with a tooltip naming the tool and its key ("Select V"), as on a drawing tool. There is no Note tool: notes are added from the Notes panel. The view mode, whose face says the mode in force, "2D", and whose menu lists 2D and 3D (state 7). interface-templates.md 14; figma-crosswalk.md. Toolbar, ToolButton, ToolGroup.
  12. Header row. One row: the zoom and view menu. No Export button (Export... is in the project name menu and the Data panel), no avatar (nothing signs in), no Undo button. framework-changes.md, "Navigation: one header row on the right". Mantine Menu.
  13. Type row, then the graph's properties. With nothing selected the inspector is the graph's, so its type row names it ("Co-appearances", Graph), as on every other screen; the two property rows follow under it without a second "Graph" heading. Background writes the graph's style, never a layer. Unset, the canvas follows the light or dark theme (canvas-drawing.md 1), so no single hex is right: the swatch shows both canvases and the value reads "Theme". Layout names the method with Run beside it. interface-specification.md 4.1, Nothing. PageRow type row, CompactColorInput, StyleSelect, TrailingSlot.
  14. Overview. The section every other screen shows with nothing selected. The state line first (24), then the headline readings (27) on an undirected graph; the Edges row opens the Edges editor (direction and weight are in the state line, so the row does not repeat them); Attributes; "5 more". No Last import row: the file chip names the file and its popover the date, so the row appears only when rows were unmatched or dropped. The header's menu (the overview in use, Change overview... and Over time...) shows on hover and focus, as a list row's trailing action does, so no "Overview: General" row repeats the heading. interface-specification.md 3 and 4.1. ActionRow, DataRow, InfoCircle.
  15. Location slot. Under the project name, one line in body ink. Version A reads "Nothing has been sent from this project" at rest; version B leaves it empty at rest (switch at the top). In both, it speaks when data leaves: "Sent to {host}: {n} query" after a data-source query, "Sends node names and statistics to {host} when you ask" while the Assistant is on (state 8). A click opens Data > Sent and saved; the same line, in the same place, in every frame. information-architecture.md 5; framework-changes.md, "Pending the round-2 comparison: where the data is, at rest". Mantine Anchor.
  16. Assistant, off. No icon, so nothing sparkles while nothing is sent; the caption says what off means. Tooltip: "Assistant: off until you set a provider in Preferences". A click opens the Assistant panel with its setup. framework-changes.md, "The Assistant's rail button while it is off". RailButton without its icon.
  17. Why nodes are named. The legend's last block says which nodes carry a name and by what rule: "Labels: the 18 characters with the most connections", then how many of those the drawing dropped where two names would overlap. In the study, readers took the named nodes for "the important ones"; the caption says it is only the most connected. On the transfers file, drawn as density, it reads "No labels: 3,000 accounts drawn as density". options-and-encodings.md 6, item 2; framework-changes.md, "Main frame at rest: the legend says why nodes are named". Drawn by graphty-element from its label budget.
  18. State line. How the file was loaded, in the same sentence the Data panel keeps on the file's row: "Loaded: miserables.json, undirected. value: no unit. Each run that uses it asks what a higher value means." It states facts only, with no link and no "not used yet": the column's name and unit (on the transfers file, "amount: $ (USD). Each run that uses it asks what a higher amount means."), because a column's meaning as a weight is asked by each run that uses it, never set on the data. A "Change..." link here drew 27 wrong first clicks across three study tasks, 15 of 16 on the cheapest-route task, and promised a choice the design makes per run. It stays; it is not a notice to dismiss. content-design.md 3, State line; framework-changes.md, "The Data panel: its order...", and "Main frame at rest: the Statistics state line carries the load". ProseBlock, Mantine Anchor.
  19. Table strip. The table is collapsed at rest but never gone: a one-row strip along the bottom of the canvas column, "Table" with what it holds, opens the dock at the height it had. No toolbar button. In the study, a reader looking for a table found none. interface-specification.md 1, Bottom dock; screens/table-dock.html, Collapsed. ResizeHandle with a Mantine UnstyledButton.
  20. Quick actions. The lightning button carries its name. With the icon alone, readers did not know it was where runs, commands and "Go to {name}" start; the tooltip adds the key, Ctrl+K. ToolButton with a label.
  21. Counts carry their unit. "77 nodes", "254 edges (rows)", "254 distinct pairs". Edges counts the rows of the file; distinct pairs counts each pair of nodes once, however many rows join them. On a file with repeated rows the two differ (the evidence file: 2,298 edges (rows), 1,262 distinct pairs), and a bare "Edges 2,298" was read as the number of interactions. The same words are in the table strip and the Data panel. content-design.md 3. DataRow.

State 2, dark. Group 0 is Okabe-Ito black, 1.26:1 on the dark canvas. Every node of the layer therefore carries the one-tone fill edge, which is what keeps those four nodes and the blue isolate at far left findable. graphty-element draws neither today: the fill edge and the default palette whose black becomes #6929C4 are both element needs ("The two palette defects decided"; canvas-drawing.md 4).

State 4, still measuring. The drawing and the counts the file states arrive first. A reading still being measured reads "not yet measured" and a progress glyph takes its (i) slot, so the row itself shows that work is under way; no notice appears, because nobody asked for a run. Row heights do not change when the values arrive. Whether "not yet measured" reads as "coming" is a study question.

State 5 (17), the file popover. First where the data is and where the project is kept, in the same words in both versions, with the link to the page that can be forwarded to an IT reviewer; then where this graph's data came from: a file on this computer (a browser cannot see its folder) and when it was read, plus Update with new data.... Counts are in Statistics and whether the last save worked is in the chevron menu, so neither is repeated here.

State 8, the Assistant on. A provider is set and the Assistant is on: the rail button gets its icon back, and the location slot says what leaves, in both versions. When the Assistant is turned off the slot returns to its resting form.

State 6 (18), Not saved. The autosave failed. "Not saved" sits beside the name and the header still fits its 241 px with both chips. The chevron menu's first line says why, then Download project file, then the menu's usual commands: Export..., Update with new data..., Version history, Project info..., Rename, Duplicate, Close. While the autosave works, that first line reads "Kept in this browser, saved 10:58".

State 9, size added. The reader has added size by degree: a layer "Size: degree" on top of the stack, and its own legend block in the same words, so a bigger dot says "more connections", not "more important". Group color is unchanged. A result the reader paints later (betweenness, say) takes one channel, color or size, never both, so each key on the canvas still makes one claim.

State 7 (19), view mode. The caret opens the mode menu, with the mode in force checked.

Word count at rest (app text, counted as principles.md 5; names, values, counts and legend categories are free). Left panel 8 against its 8 in version B; version A's standing line adds 4, making 12. Inspector 30 (the type row's kind word, Background, Theme, Layout, Overview, nine reading names and four count nouns, Attributes, more, Style stack, Look, Screen, and the six-word "Top wins each property it sets"), plus the state line's 14 ("Loaded", "undirected", "no unit", "Each run that uses it asks what a higher value means"), makes 44. Rail labels and the Assistant's caption 8, filter chip 2, the legend title 2, the labels caption 13 and the mode face 1 make 26. The table strip 5 ("Table", "nodes", "edges", "View > Table"). Screen total 83 in version B and 87 in version A, against a budget of 50. Every word over budget answers a question a participant asked out loud (where is my data, why are these named, how was it loaded, where is the table); the budget change is proposed with the Assistant's caption.

Blank project

  1. Rail. Unchanged: every place exists before data does. interface-templates.md 1. NavRail.
  2. Header. "Untitled" until the reader names it or data names it. In version A the location line stands here too, since it is already true. No file chip, because nothing was read; no filter chip, because there is nothing to compute on. A proposal. ActionRow.
  3. Graphs. One row, as Figma's Pages list always holds a page. state-matrix.md, Graph panel, Object list. PageList.
  4. Sets and paths. Header and "+". content-design.md 4.
  5. Style stack. In the inspector: Base style only, visible as the last row. state-matrix.md, Styles list, Blank.
  6. Canvas. Empty, no text and no card. Dragging a file over the window draws the start screen's drop box; whether a newcomer finds that without being told is a study question. framework-changes.md, "Start screen: the drop box while a file is dragged over the window".
  7. Toolbar. Present, as Figma's is on an empty file.
  8. Header row. The zoom only, as in the resting frame.
  9. Type row and Background. The type row names "Graph 1"; Background stays editable, because it does not depend on data, as Figma's empty file keeps its page color. Layout is absent: there is nothing to arrange, and the row appears with the first data. A proposal.
  10. Add data... The inspector's one command, full width under the type row. state-matrix.md, Inspector, Blank; content-design.md 4. Mantine Button.
  11. Location slot. Version A only, as in the resting frame.
  12. Table strip. Present with no counts: the table exists before data does, and is empty.
  13. Assistant, off. As in the resting frame.
