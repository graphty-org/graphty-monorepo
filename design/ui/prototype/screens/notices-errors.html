How graphty speaks when something happens out of sight or goes wrong. Most changes need no message at all, because the change itself is on screen (state 1b); a notice (the dark strip above the toolbar) appears only when the effect is out of sight, and an error appears where the failed thing lives. Only the failed autosave, which puts work at risk, keeps its notice until it is dismissed. Turn on owner mode to see each message as graphty-element publishes it: a stable key, its parameters, and the English text a host may replace. Keys marked proposed are not in the message catalog yet.

1. Undo whose effect is out of sight: a notice with Redo

Les Miserables. A minute ago the analyst made the set Friends of Valjean in the Graph panel, then opened the Results panel and started typing in its Find field. The field had lost focus, so Ctrl+Z undid the last graph command instead of the typing. Sets are listed only in the Graph panel and do not paint the canvas, so nothing on screen changes: the notice is the only sign of what the press did, and Redo puts the set back.

4. The WebGPU device is lost during a run the analyst cannot see

Card and transfer transactions, March 2026: 3,000 accounts. PageRank was running on WebGPU while the analyst worked in the Graph panel, and the browser dropped the WebGPU device the run was using. Only the computation device was lost: the canvas draws through its own WebGL context, which kept working, so the drawing is intact. The run failed and did not quietly finish on the CPU. The notice gives the headline and opens the result; the cause and Re-run on CPU wait on the result's row (see Results panel, the failed state).

Because the project is not saved, the card offers Download project file first and says what a restart returns to. For the study: show this screen and ask "What would you do now?", then "If you pressed Restart viewer, what would you have afterwards?"; do not ask whether the card is clear.
