Measure options with cost

What a measure's options look like when running it has a cost. First, Betweenness on the 300-protein network, well within the time limit: set to weight its paths by confidence, which nobody has said the meaning of, the run refuses and its one button opens the question; nothing runs until it is answered, and until then no measure uses confidence. Then Betweenness on the 124,318-patent citation graph, which would take hours, past the 30-second time limit, so graphty-element refuses to start it and lists the ways forward, each with its cost: the largest sampled estimate that fits, exact on a 5,318-node kept set, a larger sample of 500, or exact on the full graph in the background. Then the sampled estimate running, with its direction and seed in view, and a sample of 500 set after it finished. Every time word comes from graphty-element's cost model over the graph's real size; the page follows your system theme.

1Within the time limit: a weight the run cannot use refuses›
Screen reader hears: "Alert. Can't weight paths by confidence: confidence isn't set up as a length yet. Betweenness counts shortest paths. Until you say what a higher confidence means, no measure uses it, PageRank included." Focus: "Set up confidence, button."
A run that cannot use the chosen weight refuses before it starts, with the same component, wording shape and focus order as the filtered-scope refusal: the error slot says what cannot happen and why, the field that causes it carries the warning mark, and the header's one primary button is the fix. Here the analyst set Weight by to confidence on a Betweenness that had run unweighted; nobody has said what a higher confidence means. framework-changes.md, "Run options: a run that cannot use its weight refuses, like the filtered-scope refusal".
Nothing runs with the weight silently dropped, and an unanswered meaning is "not used" by every measure, PageRank included, so the same column never means something in one result and nothing in another. Both are graphty-element behavior, proposed to it (framework-changes.md, "graphty-element: an unanswered weight meaning is not used by every measure"); the app only shows the refusal the element returns.
Set up confidence: the header TrailingSlot Button (primary), where Run was. Focus lands on it and the error slot is announced; Enter opens the weight question for this column. Tab then reaches Close, Scope and the marked Weight by field, where "none" is the other way forward. Esc closes with nothing run; the unweighted values stay. Statistics reads "confidence: each run that uses it asks what it means".
Error slot: warning glyph, the cause in bold, one secondary line; role alert. interaction-pattern-entries 8.1. Weight by is a StyleSelect listing the numeric edge columns and none, with the FieldRow warning mark.

2Within the time limit: the question the refusal opens‹›
Screen reader hears: "For confidence, a higher number means..., radio group. A closer or stronger link, similarity, radio, not checked, 1 of 4."
The weight question, opened by the refusal's button, under the Weight by field, focus on its first choice. The words are the column's, the technical term secondary (glossary 11); the examples are real values of confidence: its largest, a middle one (TP53 to DUSP6) and its smallest.
Nothing runs until it is answered: Run is off, its reason in the hint under the question. Answering sets this run's option and turns Run on; the run is still the analyst's click. Enter in the group does nothing until an answer is chosen. The answer belongs to this run, not to the column, as on screens/weight-role-trap.html and screens/sets-and-paths.html. A closer link or a costlier step can weight paths; more can pass through cannot, so Betweenness refuses again, naming the answer; Don't use confidence sets Weight by to none.
Mantine Radio in a radio group (figma-spec 5.6). There is no "decide later" choice: leaving the question unanswered already means not used, and Don't use says so for good.

3Over the time limit: choose how to run it‹›
Screen reader hears: "Betweenness, error. Takes hours. The time limit is 30 seconds. Directed, on the full graph. Fits the time limit: Sampled, 101 sources, under a minute, 1 of 4."
Past the time limit the click creates the result and refuses it: an Error row with the band as its trailing text and the cause on hover and focus. state-matrix 3, Result row, Error (row); state-matrix 4.10, row 1. "Time limit", never "budget", which a first-time reader took for money. The limit cannot be raised here or anywhere.
The error slot: what happened, the direction and scope, and a Details link to the run's record, where the code lives. interaction-pattern-entries 8.1. The direction is the graph's own, directed, because Betweenness reads direction (graph-conventions 1, the direction list).
Four routes, grouped by whether they fit the time limit, cheapest first in each group. Each is a 32 px ActionRow: route left, band as trailing state, description in the tooltip. A sampled route sits beside every exact one: the largest sample that fits (101) above, a larger sample of 500 below, next to the hours-long exact run. The subgraph route says what it covers, "Exact, on 5,318 nodes"; its tooltip names the kept set. Arrow keys choose; focus lands on the first. One commit: the header's TrailingSlot Button names the chosen route (Run sampled, Run on set, Run exactly).
Nothing else shows while the gate refuses: no option rows and no Run line; the sampled route's options live on its own result. A route past the time limit runs in the background with its band and Cancel, as in screens/run-and-read.html.

4Within the time limit: the largest sample that fits, running‹›
Screen reader hears: "Running Betweenness (sampled), under a minute, within the time limit." (polite) Focus stays on the result's Cancel.
Run sampled created the sibling result and ran it at once: one commit, as a catalog click within the time limit. Cancel is in the header and the notice; the undo chord removes it. The refused exact result stays in the list beside it. interaction-patterns 3.3; glossary, sibling result.
State line: band and verdict together, then the direction read. state-matrix 4.10. Body order is the template's: state line, Scope, Parameters, Appearance, readings, Notes, Used by. interface-templates 10.
Direction: a StyleSelect defaulting to the graph's own direction, with Read as undirected as its other choice. Sample size is the library's real sampling parameter, k of betweennessCentrality, named in the InfoCircle; an integer ComboInput. Its default is the largest sample that fits, read from the element, never computed by the app.
Seed: a ComboInput showing the seed this run drew, editable, with New seed in the TrailingSlot (interface-templates 11), so a sampled run can be repeated exactly. It needs a seeded sample in @graphty/algorithms and graphty-element (framework-changes.md). The magenta-tagged caveat line is still proposed; toggle it off above.

5A sample past the time limit: offered, and run in the background‹
Screen reader hears: "Sample size, 500. 500 sources take a few minutes, past the 30-second time limit. Run starts it in the background."
After the run, an edit is held for Run, as on any result that has run. interaction-patterns 3.3.
A sample past the time limit is offered, not refused, as the hours-long exact run is: the field keeps 500, a warning under it gives the band and the limit, and Run starts it in the background with Cancel. The largest sample that fits is repeated. The finished estimate on 101 sources, with its seed, stays until the new one finishes. FieldRow warning slot; interaction-pattern-entries 8.1, the field scope.
