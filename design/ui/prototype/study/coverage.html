What matters most among the gaps

  • Almost nothing on the gallery today has been tested as it stands. Round 6 ran on pages whose round-5 decisions were partly undrawn (its precondition gate checked 0 pages), and 38 of 40 screens have changed since. Round 7 is the first chance to test the current design.
  • Layout is the one ranked everyday task with no test (top task 7, "make the layout readable"). The Layout row is on the mocks; no task asked anyone to run or tune it.
  • The ways a first file fails are mostly untested. The .xlsx refusal was tested once (round 6, 7 sessions). A file that cannot be parsed, a file refused for memory, and undoing a first load have mocks or flow text but no task.
  • The opt-in moment has never been tested. Turning on the Assistant is drawn (Preferences, the AI provider dialog: a refused key, a provider set), but no task has used it; participants saw only the "Assistant on" state afterwards, and round 6 found no screen for the app after a data-source query.
  • 15 capabilities have no mock, including saved filters, computed attributes, anomaly detection, node merging and guided onboarding; three workflows (threat hunting, recommendation, enrichment map) were never walked.

  • A screen is linked to a session when the session names the page, its render, or its plain name ("the load step"). That match is automatic; the capability, workflow, flow and storyboard columns are a reader's judgment from each task's prompt and screens.
  • Tree tests and first-click tests (rounds 4 to 6) measure where people look, not whether a feature works, so they never count as tested here.
  • "Current version": page files were compared by modification time with the round-6 sessions (written 04:35 to 05:18 on 2026-09-29); 38 of 40 screen files, 5 of 13 flow files and three of six storyboard files changed after.
