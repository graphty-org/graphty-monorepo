# Notes with names -- Analyst Alex

**Task, as the moderator read it:** "A colleague opens this project next week and will read your
notes beside her own. Make sure she can tell which ones are yours."

**Participant:** Alex, operations data analyst (NetworkX, Gephi, Excel). Uses graphs about once a
week; hands work over to colleagues and to his manager.

**Screens seen (study view, design notes hidden):** the Notes panel (empty, a list with two
authors, a row's menu, Find, a list with one author), the Note editor (writing, added), the main
menu's Preferences submenu and the name dialog, the navigation frame.

## Think-aloud

**1. Where would a name even go.**

"OK. 'Make sure she can tell which ones are mine.' So either the notes already carry a name, or I
have to put one on. First thing, I'll look at what a note looks like."

(Opens the Notes rail item. Empty project: "No notes yet. A note can be about a selection, a set,
a result or the whole graph. Add note... Notes are saved in the project and travel in project
files and findings reports.")

"'Travel in project files.' Good, so she'll get them when I send the file. That was my first
worry. Nothing about who wrote them, though. No profile picture top right either -- there's no
top right at all, it's just the zoom."

"I'm not going to go hunting through menus yet. Let me write one and see what it records. That's
how I'd find out in Excel too -- make a comment, see whose initials it puts on it."

**2. Writing a note.**

(Looks at the Note editor, writing state. "New note", "About Mule ring, 14 accounts", the text
box, Cites PageRank, Quote a value..., and at the bottom "Saving as: Marcus. Change..." next to
Add.)

"Oh. There it is. 'Saving as: Marcus.' So it does put a name on it. Right there by the Add
button, so I can't miss it. That's actually the thing I wanted -- I'm seeing it *before* I save,
not finding out afterwards."

"But I'm not Marcus. Who's Marcus? Is that the last person who used this browser? This is the
bit that makes me slightly nervous: on a hot desk or a shared meeting-room laptop, I'd have
written notes as somebody else and not known. Here I'd catch it because I'm looking at the
editor. Fine."

"'Change...' -- that's the obvious click. I'd expect that to let me type my name."

(Reads what Change... does: it opens the name setting.)

**3. Setting the name.**

(Looks at the dialog: "Your name on notes and recipes", Name field, "Saved with each note and
recipe you make from now on, exactly as typed. Shown only when a project holds work by more than
one person. Leave blank to record no name." Cancel / Save.)

"One box. I'd type 'Alex M.' -- no, full name, she might know another Alex. 'Exactly as typed',
fine, so if I typo it, it's typo'd forever on those notes. I can live with that."

"'From now on.' Hmm. I remember something like this. That means anything I wrote before I set it
has no name. For the task that matters, because the notes she reads next week are the ones I've
already written. If I'd set this on day one, no problem. If I'm setting it the day before I hand
over, half my notes are blank."

"'Shown only when a project holds work by more than one person.' OK, I get the logic -- why
print my name forty times on my own project. But it means I can't check it on the note itself."

(Also looks at Preferences in the main menu: "Your name on notes and recipes... Sarah Okafor".)

"And it's also in the menu, under Preferences, with the current name underneath. That's where I'd
have looked second, so good, two ways in. The line under it tells me what's set without opening
it. That's a nice touch."

**4. After Add.**

(Looks at the added note: "Note", About line, "Sep 28 2026, 10:42", the text, Cites, Quotes. The
Notes section in the inspector: "Sep 28 2026, 10:42".)

"And -- no name. Just the date. Which is what the dialog said would happen, it's just me on this
project. So I have to trust that it recorded 'Alex' behind the scenes. The editor told me who it
was saving as, which is honestly enough for me. Before I'd have been sending it off hoping; now
at least I saw it say my name when I clicked Add."

"I'd still like one place that shows it after the fact. Like when I reopen a note -- a little
'by Alex' in the header. Not on every row, fine, but on the note itself when I open it. Right now
the only proof is that I watched the editor."

**5. What she'll see.**

(Looks at the list with two authors: "Adam Powers, Sep 28 2026, 10:14", "Lin Chen, Sep 27 2026,
16:42", and so on, every row with a name and a full date and time.)

"OK, this is what she gets once her notes and mine are in the same project. Name, date, time, on
every row. That's clear. I can tell at a glance Lin wrote the CDK1 one and Adam wrote the TP53
one. That's exactly the task. If this is what she sees, I'm done."

(Compares with the one-author list: same rows, date only.)

"And that's the same list with just one person. So it switches on by itself when there are two of
us. Good -- I don't have to do anything."

"What I don't see is a row from someone who never set a name, sitting next to named ones. Does it
say nothing? A blank line with just the date? 'Unknown'? If my old notes show just a date next to
her 'Lin Chen, Sep 27' she's going to assume they're... whose? Maybe hers from before she set
hers. That's the case I'm actually in, and it's not on any screen I've got."

**6. Can I fix the old ones?**

(Looks at a row's menu: Edit note, Delete note.)

"Edit note. If I open an old one and edit it now that my name's set, does it pick up my name?
Nothing tells me. And the other way round -- if she edits one of mine next week, does it become
hers? That's worse, that's my finding with her name on it. I'd guess it keeps the original
author, like a Word comment, but it's a guess."

"Worst case I'd do what I do now: copy the text of each old note, delete it, add it again so it
gets the name. That's ugly, and I'd lose the original date, which I actually care about."

**7. Finding my own notes.**

(Looks at Find in notes: typing "Betweenness" narrows to two notes, highlights the word in text,
About and Cites.)

"If I typed 'Lin' or my own name here, would it filter to her notes? The example only matches
words in the note and what it's about. I'd try it anyway. If it doesn't work I'd scroll -- it's a
short list, it's not a big deal on thirty notes."

**8. Wrap-up.**

"So: setting the name -- easy, and this time I found it by just writing a note, didn't have to go
looking. The editor telling me 'Saving as' is the big improvement, that's the reassurance I was
missing. The two-author list is exactly what I want her to see. What's still hanging is my notes
from before I set the name. That's the real handover situation and I can't tell from these
screens what she'll see on them, or whether I can put my name on them."

## Single Ease Question

**5 out of 7.**

"Finding it was easy this time, the editor practically hands it to you, and I could see my name
before I saved. That's a 6 on its own. I'm taking one off because the notes I already wrote stay
nameless and I can't see what that looks like to her, and I don't know what happens when one of
us edits the other's note. The task was 'make sure she can tell which ones are yours' -- for new
notes, yes. For the old ones, I'm still not sure."

## Would he use this instead of his current tool?

"For this job, yes. What I do now is a Word doc next to the .gephi file with my initials in front
of every paragraph. Gephi has no notes at all. Here the note sits on the thing it's about, with
the run it cites, a date and time, and a name once there are two of us. I'd switch for that."

"Two things before I'd trust it for a proper handover: let me put my name on notes I wrote before
I set it -- even just a prompt the first time I set the name, 'put this on your 12 unnamed
notes?' -- and show me what a nameless note looks like next to a named one, so I know what she's
going to read."

## Moderator notes

- Alex found the name setting through the Note editor's "Saving as: Marcus. Change..." line,
  without searching menus. He read it before saving and called it the main reassurance. He also
  noticed the Preferences item with the current name under it and called it a good second route.
- He read "Marcus" as someone else's name left in the browser and raised a shared-laptop risk:
  notes silently saved under a previous user's name. He would catch it only by reading the editor
  footer.
- "From now on" in the dialog was again read at once as "my earlier notes stay nameless". This is
  the core handover case, and no screen shows a way to name earlier notes.
- No screen shows a nameless note beside named ones in a two-author list. He could not predict
  what his colleague would see on his earlier notes and guessed she might misattribute them.
- After adding, the note shows no name (one-author project). He accepted this, given the editor
  showed the name before saving, but asked for the author on the opened note itself.
- He asked, unprompted, whether Edit note changes a note's author, both for picking up his name on
  old notes and for a colleague's edit putting her name on his finding. The screens do not say.
  His fallback, delete and re-add, would lose the original date.
- He expected Find in notes to match author names; the example shows only text, targets and
  citations.
- Positive: the "Saving as" line in the editor; the name item in Preferences showing the current
  value; names appearing on their own once a second author exists; full date and time on every
  row; notes travelling in the project file.
- SEQ 5 (round 5: 4). Would adopt for this job over a Word document beside the Gephi file.
