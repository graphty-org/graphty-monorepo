# Session: notes with names -- Sarah, fraud analyst

Task as read to her: "A colleague opens this project next week and will read your notes beside
her own. Make sure she can tell which ones are yours."

Screens she saw, as renders: the Note editor on the March transfers project (take-a-note, the
writing and saved states), the notes panel in her project and in a two-author project (Human
protein interactions), the main menu with Preferences open, and the name dialog. She read the
page HTML only to see what a control does when clicked.

## Think-aloud

**1. Where she starts: writing a note.**

"Same as last time -- the only place I'd think about who wrote something is where I write it. So
I open the Mule ring set, three dots, Add note."

(Take-a-note, the editor open on Mule ring, 14 accounts.)

"OK, this is new. Under the box: 'Saving as: Marcus. Change...' Good -- that's exactly what I
asked for. It tells me who the note will say wrote it, before I press Add.

But it says Marcus. I'm not Marcus. Either somebody sat at this machine before me, or this is
Marcus's browser, or it's just the demo. If I saw that on a real case I'd stop right there. A note
on a SAR referral going into the file under someone else's name is worse than a note with no name
at all."

**2. Fixing the name.**

"'Change...' -- I'll click it." (The HTML says it opens the name setting.)

(Preferences, the name dialog: "Your name on notes and recipes", field reading "Sarah Okafor",
"Saved with each note and recipe you make from now on, exactly as typed. Shown only when a project
holds work by more than one person. Leave blank to record no name.")

"Right, I remember this one. It's the same dialog I dug out of the main menu last time. This time
it was one click from the note, which is where I needed it. Type my name, Save, done. That's
maybe fifteen seconds instead of the tour I took last round.

'From now on.' So the notes I already wrote as Marcus -- or as nobody -- stay that way. There's no
'fix the name on my earlier notes'. Fine for an audit trail, you shouldn't be able to re-sign old
work. But then I want to be able to SEE which ones went in under the wrong name, and I can't,
see below."

**3. Checking the note after it's saved.**

(Take-a-note, saved state; the notes panel in March transfers with six notes.)

"I press Add. The note shows 'Sep 28 2026, 10:44' and the text. No name. The inspector on the
right: date, no name. The panel list: date, text, what it's about. No names anywhere.

I know why -- last time I read it: names only show once there's a second person in the project.
I get the logic, it keeps the list quiet when it's just me. But the task is literally 'make sure
she can tell which are yours', and the only way I can check that is before I press Add. After
that, nothing on screen tells me what my note says about who wrote it. I'd have to trust it.

And if the 'Saving as' line had said Marcus and I hadn't looked, I'd never know, because the saved
note won't show it until the colleague's notes arrive -- and then it's her who finds out, not me."

**4. What the colleague will see.**

(Notes panel, Human protein interactions, two authors: each row "About ...", then "Adam Powers,
Sep 28 2026, 10:14" or "Lin Chen, Sep 27 2026, 16:42", then the text.)

"OK, this is what she gets once both of us have written in the project. Name and date and time on
every row, the About line on top. That's readable. I can tell Lin's from Adam's at a glance, and
the inspector on the right says 'Adam Powers, Sep 24 2026, 09:05' too. Good. That's the answer to
the task -- if the file she opens is the file I wrote in, and she's set her own name.

What if she hasn't set a name? Then it's me and a blank. The screens don't show me what a note
with no name looks like in a list that does show names. Blank? 'Unknown'? 'No name'? If it's just
missing, her notes look like the date line of mine with the name dropped, and on a printout in
grey you'd miss that."

**5. The things I'd still worry about on a real case.**

"'Exactly as typed', kept in this browser. So it's a label. Nothing stops my colleague typing
'Sarah Okafor' into hers. Nothing stops me forgetting to set it on the other laptop. For telling
two of us apart in a working chart, it's enough. For anything an examiner reads, it's not a
signature and I wouldn't let anyone treat it as one.

Edit note and Delete note are on every row's three dots. The page says Delete has no
confirmation -- one undo step. So next week my colleague can delete my note, or edit my text and
it still says Sarah Okafor on top. Nothing I saw says 'edited by' or 'edited on'. Last time I said
that's the part that worries me most. It still is."

## Single Ease Question

**5 out of 7.**

"Better than last time. The 'Saving as' line under the note is the thing I was missing: I can see
my name before the note goes in, and 'Change...' takes me straight to the fix. That's a five.

Not higher because the moment I press Add, my name disappears from my own note, and the screen I
got said 'Marcus', which on a real case would have been a wrong-name note I'd only discover when
my colleague did. And I still don't know what happens to my name when someone else edits my
note."

## Would she use this instead of her current tool?

"For telling my notes from my colleague's inside the chart -- yes, it's good enough now. Better than
i2, where we paste notes into Word and write our initials by hand.

Instead of the case system -- no. The case system logs me in and stamps my user ID on every comment
and nobody can edit it under my name. This is a name I typed into a browser, and anyone can
delete my note without a prompt. I'd use it for working notes between two of us on a ring. The
record of who concluded what stays in the case system."

## What the session showed (plain summary)

1. The Note editor now says "Saving as: {name}. Change..." under the text box. She found it at
   once, and it answered the task at the point where she was already looking. Change... took her
   straight to the name dialog; last round she had to search four places for it.
2. The editor render she saw said "Saving as: Marcus". She read it as someone else's name left in
   the setting and said on a real case she would stop, because a note under the wrong name is
   worse than a note with no name. The editor line is what catches that; nothing else does.
3. After Add, her note shows no name anywhere (row, inspector), because the project has one
   author. She cannot check what name a saved note carries. A wrong name would be discovered by
   the colleague, not by her.
4. The two-author project reads well: name, date and time on every row and in the inspector.
5. Open question from her: what a note with no name looks like in a project that shows names
   (colleague never set hers). Not shown; she worried it would be missed on a grayscale printout.
6. Carried over from last round, still unanswered for her: the name is a label, not an identity;
   it is kept in one browser; notes written earlier keep their old name or none; Edit note leaves
   the original author's name with no "edited by", and Delete note has no confirmation. For her
   this rules it out as an audit record, not as a working-notes tool.
