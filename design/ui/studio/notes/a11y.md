## Priorities and values

- **Equal path, not a separate path.** A keyboard or screen-reader user does the same task through
  the same commands, not an "accessible mode". Follows the owner's rule of no persona-specific
  features (2026-09-26): accessibility is met by the default UI.
- **Get to the data, and get back to where I was.** Text equivalents (table, inspector, key) and
  predictable focus return are worth more than canvas tricks.
- **Measure, do not assume.** Contrast by computed ratio, names by accessibility tree, keyboard by
  real key presses on the frozen build. A simulated participant's opinion is held one level down.
- **Fix it once, where every consumer gets it.** compact-mantine for controls (rings, menus,
  badges, sliders, comboboxes), graphty-element for canvas and graph facts, the app for its own
  wiring and words. An app-side aria patch over a component defect is forbidden.
- **Quiet but not silent.** One utterance per change; notices never take focus; never the same
  thing twice.

## Design criteria

- **Keyboard (2.1.1, 2.1.2):** every control reachable and operable; no trap; composite widgets
  (rail, toolbar, tree, grid) are one Tab stop with arrow keys; Tab leaves the canvas.
- **Focus order and return (2.4.3):** closing a popover, dialog or menu returns focus to its
  opener; removing a row moves focus to a neighbor or its section's "+"; focus never falls to the
  page; a mode switch moves focus into the mode.
- **Focus visible (2.4.7, 1.4.11):** 3:1 ring on every focus target, headings that take focus
  included; inside tight rows the ring draws inside the box; a ring must differ from the
  neighboring control's ring.
- **Names (4.1.2, 2.5.3):** every icon control has its tooltip's words as its name; the visible
  label is in the name; no two reachable controls share a name; row actions name their row;
  disabled = `aria-disabled` with a readable reason (a section "+" with nothing left is the agreed
  exception: no Tab stop, reason in `aria-description`).
- **Status messages (4.1.3):** counts, adds, runs, undo, loads, opens and search results reach the
  reader once without moving focus.
- **Contrast (1.4.3, 1.4.11):** app theme is `createCompactTheme({ highContrast: true })`; text
  4.5:1, controls and rings 3:1. Data fills may sit lower when their text form exists.
- **Color never the only signal (1.4.1):** spoken color words must tell apart what the palette
  tells apart.
- **Single-key shortcuts (2.1.4):** switchable off in Settings; global chords (Control+A) must
  not fire from inside an editor.
- **Target size (2.5.8):** 24 px or 24 px spacing, unless an equivalent control exists.
- **Reflow (1.4.10):** at 900 x 700 nothing is cut without a way to read it whole; notices fit
  their column.
- **Motion (2.2.2, 2.3.3):** a layout over 5 s has a pause; reduced motion cuts camera motion
  (element work, owner's list).

## Thinking

- **The core path for a first-time keyboard or screen-reader user, in order:** start screen (Open a
  file first in Tab order, card names with their titles); a status line saying what arrived, in
  counts; the inspector's Values as text; a layer by "+" with focus in its name; the picker by
  Enter with focus on "Add a condition"; each change announced with its count; the key as real
  text; find by "/" with a spoken result count. Round 1 shows the middle of this path is solid;
  the start screen and the edges (modes, global chords, notices) are where it frays.
- **The canvas is not the blocker -- its text equivalents are.** Everything the drawing says must
  be in the table, the inspector, the key and the spoken names. So the spoken color words are a
  text equivalent and must keep the palette's distinctions.
- **Scattered live regions are a risk both ways.** One app announcer fed by element facts would
  satisfy 4.1.3 cleanly; decide after hearing what each build says.
- **Where my findings go.** Component defects to compact-mantine; graph facts and keys to
  graphty-element; app-only defects (names, focus targets, region wiring, command scope) fixed in
  the app; tool gaps (a check the walk does not run) to the design engineer.
