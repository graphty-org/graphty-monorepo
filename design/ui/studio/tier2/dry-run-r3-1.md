# Tier 2 first dry run before round 3

Before any round 3 session, every tier 2 task half (A and B of T4, T17 to T24 and T12R) was piloted
from its start on the round 3 study build b6d932823642 (`criteria.md`, first line). The walks are
in `rounds/r3/pilot/<task><half>/`. The pilots reported 92 items; the first T4 A report holds nine
numbered defects, listed here one per row, so the table has 100 rows. Each row gives its class and
the reason. Every item classed as a fix, and every new item classed otherwise, was checked in
source and on its screenshot before it was classed; the reason names the file.

The question this dry run answers: would a participant spend session time on a flaw in the build
instead of on what the task asks? Rarely. Every success path landed, every reference value held,
and no walk logged a script error, a console error or a failed request. Eight rows are defects a
participant could hit, in six small units: a heading drawn as a row, a header that moves when a
scrollbar appears, a stale toast, a button that does nothing on a second press, focus left in the
find box after a tie is picked, and a confirmation that did not show on the first open of a saved
project. The rest are the design questions the sessions exist to answer, behavior already decided
on purpose, or repeats of items earlier dry runs classed.

Classes:

- **fix: <unit>** -- an implementation or polish defect a participant could hit. Fixed before the
  first session in the package that owns it; the units are listed after the tables.
- **design** -- a question the sessions exist to answer (where something lives, what a returning
  user expects, what to call it). Left alone.
- **no change** -- the behavior is right or deliberate, or the claim did not hold; the reason says
  which.
- **owner** -- already waiting on the owner in `../owner-decisions.md`.
- **process** -- about how the pilot ran or what graders are told, not the app.

Reasons that recur are named once here:

- **3D overlap**: two nodes, or a label and a node, drawn on top of each other. It is
  graphty-element's label and node placement, expected to fail bar 10, and too large to change
  between rounds.
- **Names by default**: whether a returning user expects names on the drawing, or a hover card on
  a node (a new element capability). Left to the sessions every round.
- **Focus on a heading**: after an action, focus goes to the inspector's title, a heading that
  takes no mark. A box and an underline each read as a control or a link (round 1 dry runs three
  and four). The next Tab reaches a marked control (`T21A/08.png`).
- **Covers until closed**: an open menu, list or tooltip covers what is under it until a choice,
  Escape or the pointer leaving closes it.
- **All N rows**: the caption says what the preview holds, which is every row; the pane scrolls
  and draws its scrollbar (decided in the round 2 dry runs).
- **Hover under the pointer**: a gray fill on the row the unmoved pointer now rests on; it goes
  when the pointer moves.
