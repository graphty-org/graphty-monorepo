# Tier 2 second dry run before round 3

Every tier 2 task half (A and B of T4, T17 to T24 and T12R) was piloted again from its start on
build 897d9aed9ffe (`criteria.md`, first line), the build that carries the first round 3 dry run's
fixes (`dry-run-r3-1.md`). The walks are in `rounds/r3d1/pilot/<task><half>/`. The pilots reported
95 items, one row each below, with the class and the reason. Every item not already classed in an
earlier dry run was checked on its screenshot, and in source or on the build, before it was classed.

The question is the same as before: would a participant spend session time on a flaw in the build
instead of on what the task asks? Almost never. Every success path landed, every reference value
held, and no walk logged a script error, a console error or a failed request. Three of the first
dry run's fixes held where the pilots walked them: the import page's header stays put when the
preview's scrollbar appears, the "Opened ..." notice shows on the first open of a saved project,
and a tie picked from the find box takes focus with it. One did not: the Overview's "Full graph"
is now a column caption, but it sits at the rows' own inset and size with nothing beside it, so
it still reads as a row whose value is missing (T17B/07). That is the one fix below. Over 90 of the
95 items are repeats the answer key already holds, each classed the same way as before.

Classes, as in the first dry run:

- **fix: <unit>** -- an implementation or polish defect a participant could hit. Fixed before the
  first session in the package that owns it.
- **design** -- a question the sessions exist to answer (where something lives, what a returning
  user expects, what to call it). Left alone.
- **no change** -- the behavior is right or deliberate, or the claim did not hold.
- **owner** -- already waiting on the owner in `../owner-decisions.md`.
- **process** -- about how the pilot ran or what the answer key tells graders, not the app.

Reasons that recur are named once in `dry-run-r3-1.md` and used here by the same names: **3D
overlap**, **names by default**, **focus on a heading**, **covers until closed**, **All N rows**,
**hover under the pointer**. One more:

- **Tooltip on entry**: the shared tooltip opens when the pointer enters a control and closes on
  a click; a pointer that has not moved has not entered again, so the next tooltip waits for the
  pointer to leave and come back (compact-mantine's tooltip rule, kept in the round 2 dry runs).

## The fix

- **Overview** (graphty app, `src/workspace/inspector/GraphValues.tsx`): under an on filter step,
  the whole graph's rows (Nodes, Edges, Direction and the rest) sit in a section of their own
  titled "Full graph", drawn with compact-mantine's `ControlSection`, the same heading the
  Overview itself has, below the Overview's "Nodes showing" and "Edges showing" rows. The column
  caption `DataRowHeader` goes. With no step on, the Overview is unchanged (21).

Counted: 95 rows. 1 fix, in one unit; 45 design; 42 no change; 2 owner; 5 process. Nothing in the
design questions was touched. The answer key gains two lines: the path form's open lists on T20
(59) and the panel title on T21 half A (72). After the fix the build is frozen again and T17 A
and B are piloted again on it; no other half walks the Overview under a filter step.
