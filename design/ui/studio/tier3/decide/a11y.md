# Unified styles: the twelve open questions, from accessibility

Answers for the unified style panel, judged against WCAG 2.2 AA and one rule: a keyboard or
screen-reader reader edits a layer through the same controls as everyone else. Sources: the mock
and its design (pull request #2098), the agreed model (`design/ui/unified-style-layers.md`), the
style catalog, graphty-element and compact-mantine source, and the study personas Morgan
(screen-reader analyst), Alex and the knowledge engineer (red-green color weak) and Expert Emma.

Two facts shape several answers: compact-mantine's `ControlSection` titles are named groups, not
headings (`ControlSection.tsx:286-300`), yet Morgan moves by headings first; and nothing in
graphty-element reads the reduced-motion preference.

## 1. Cardinality: is "+" right for single-value properties?

- **A. "+" on every section (the mock).** Two steps per property, and a screen-reader user cannot
  hear what a layer could set until it is added.
- **B. A switch per property.** Cannot say "not set".
- **C. Always-present field, empty until set.** One Tab stop and type.

**Recommend C for 0-or-1 properties** (shape, size, color, opacity, width, line pattern, curved,
head, tail): the row is always there and empty means not set. The words must carry the state, not
placeholder gray (1.4.1): the field's description reads "Not set; the layers beneath decide". Kinds
with a real "None" (arrow kind) list it apart from "Not set". Booleans use `SegmentedControl` Not
set / On / Off (a radiogroup with arrow keys), never a switch. "Clear" (the minus, named "Clear node
size") appears only once set. Keep "+" for lists.

## 2. Where "+" stays, what does it open?

"+" stays for effects, text entries and rule conditions.

- **A. A text menu with icons** (Mantine `Menu`: arrow keys, type-ahead, icons hidden from the
  accessibility tree).
- **B. An icon grid.** Needs a name on every cell and two-dimensional arrow keys; slower to hear.
- **C. Straight into a color picker,** as Figma adds a default fill
  (https://help.figma.com/hc/en-us/articles/360041003694-Guide-to-fills). The two-dimensional color
  area is a dragging gesture first.

**Recommend A**, like Figma's effect menu
(https://help.figma.com/hc/en-us/articles/360041488473-Apply-effects-to-layers). Focus then lands
on the new entry's first text field (the hex field for a color).

## 3. A long panel when a layer paints nodes and edges

- **A. Tabs Nodes / Edges.** Hides half of a route layer; readers miss the second tab.
- **B. Collapsible sections everywhere.** Many disclosures, many Tab stops.
- **C. Two collapsible groups, Nodes and Edges, as real headings.** `ControlSection` already
  supports `collapsible` and a `summary` that becomes the button's description, so a closed group is
  heard as "Edges, collapsed: color, width by betweenness".

**Recommend C.** Both groups open when written; sections inside stay open. compact-mantine adds an
optional heading level to `ControlSection` (additive) so heading navigation reaches them.

## 4. A layer with no nodes, or no edges

- **A. Hide the group.** The layout shifts between layers.
- **B. Show it disabled.** Our rule makes disabled controls focusable with a reason, so a disabled
  Edges group is eight dead Tab stops.
- **C. The heading stays, with one line and one button.** "No edges: Which elements reaches nodes
  only", and "Include edges", which moves focus to the rule.

**Recommend C**: stable headings, no dead stops. Decide by the kinds the rule can match, not
today's count.

## 5. Many fields in "vary by"

- **A. One searchable list** (`ComboInput` with `aria-activedescendant`, grouped by Data, each run,
  Facts).
- **B. A tree by source.** Deeper navigation.
- **C. List A, with fields that do not fit moved behind a "Show N that do not fit" row.** Listing
  200 disabled fields makes a screen reader say "dimmed" 200 times.

**Recommend C.** Each option is read as "degree, number, from Degree"; the type is a word, not only
a glyph. The filtered count goes to the one status line ("12 of 240 fields"). graphty-element adds
(additive) a read-only "can this channel take this value" check returning the refusal code; today
`encode` refuses only when it writes.

## 6. A visual gradient that keeps every degree control

- **A. Text fields (the mock).** Readers must picture where values fall.
- **B. A histogram with a two-thumb range under the ramp.** Each thumb sets one end of the domain.
- **C. Gradient stops on the ramp itself** (compact-mantine `GradientEditor`), each tied to a value.

**Recommend B, with C for custom stops.** Mantine `RangeSlider` (already themed in compact-mantine)
over `HistogramRow` (`ChartRow.tsx:559`, an image with a hidden table). Each thumb is an APG slider
whose value text is in the data's terms: "Lightest color at degree 3, 10th percentile". The number
fields stay below the picture: they satisfy 2.5.7 (dragging movements) and are the screen reader's
version. The palette list marks colorblind-safe palettes with a word, using the
`colorblindSafe` field graphty-element already declares (`catalog/palettes.ts:17`).

## 7. Is the Louvain "folder" a layer? What about folders in general?

Settled: a split parent is a layer, a folder writes nothing. The risk is that both sound the same
in an ARIA tree.

- **A. Different icons only.** Fails for a screen-reader user.
- **B. The kind in the row's accessible name.** "Louvain, layer split by group, 6 layers" against
  "Annotations, folder, 2 layers".

**Recommend B.** A folder's eye and lock are announced with their reach ("Annotations hidden, 2
layers").

## 8. One "which elements" picker, or one per kind?

- **A. One rule at the top of the tab (the mock).**
- **B. A rule inside each of Nodes and Edges.** Two editors and two focus targets after Add layer.
- **C. A, with a kind choice first:** `SegmentedControl` Nodes / Edges / Both, then conditions.

**Recommend C.** It is the first thing heard and the place focus goes after Add layer. The rule is
read back as one sentence, built by the app from the rule's parts. graphty-element must add
(additive) a layer that paints both kinds: today it refuses one (`session/styles/Layer.ts:111,891`).

## 9. Does the mock cover every style?

No (the catalog lists 47 label fields and 8 rich-text fields no channel reaches). Two gaps matter
most here:

- **Motion.** Label animations (pulse, bounce, shake, glow, fill) and edge motion run regardless of
  the reader's settings. Moving content that runs over 5 s needs a pause (2.2.2, AA). graphty-element
  adds (additive) a motion option whose default keeps today's behavior. Whether it should follow the
  operating system by default changes the default, so that goes to the owner.
- **Selection contrast.** The default halo, `#FFD700` at 40% on the `#F5F5F5` background, measures
  1.13:1 against 3:1 needed (1.4.11), and edges show no selection (`src/Edge.ts:1126-1146`). The
  Selected layer's default look needs a measured 3:1 mark, such as an outline plus size.

## 10. Text labels

- **A. A pop-out with every field.** Complete; 47 fields need headings inside it.
- **B. Named presets,** like Figma text styles
  (https://help.figma.com/hc/en-us/articles/360039957034-Create-and-apply-text-styles). One named
  choice is one step by keyboard.
- **C. Both:** a preset `StyleSelect` on each entry, "Edit" opens the pop-out.

**Recommend C.** Escape closes the pop-out and returns focus to its button. Presets must meet
contrast. Measured on the element's badge presets (`BadgeStyleManager.ts:3-117`),
white text: `label-success` 2.22:1, `notification` and `label-danger` 3.55:1, `label` and `count`
4.02:1; only `label-warning` passes 4.5:1. The default black label also disappears on a dark
background. Show presets that pass, and graphty-element's preset descriptors expose their text and
background colors (additive) so any consumer can check.

## 11. Picking elements for a hand-made layer, generically

- **A. From the selection or Find:** "Make a layer from these". For a screen-reader user the data
  table's row selection and Find are the equal path, not the canvas.
- **B. A condition builder:** value, comparison, operand (`ComboInput`, `StyleSelect`,
  `TextInput`), "and" rows.
- **C. An expression field** (the element's JMESPath subset). It refuses with a code and a character
  position (`session/styles/predicate.ts:400-440`), so the app can point at the error with an
  `aria-invalid` field and a description.

**Recommend all three, B first.** "Edit as expression" shows what the builder wrote; A writes an ids
rule. Emma's persona asks for a query language. Today neither example works:
functions are refused (`function-not-supported`), so "name contains Bob" cannot be written, and
"odd ids" needs a remainder. graphty-element adds (additive) `contains`, `starts_with` and
`ends_with`, and computed values (model extension 8) for the remainder.

## 12. What can vary

Every channel except label style (literal only, catalog 9.3) and `node.marker` (not drawn). From
accessibility, varying more than color is how 1.4.1 is met: Alex and the knowledge engineer tell
classes apart by shape, label and position, not red against green.

- **A. Color only by default.**
- **B. A one-click "Also vary shape"** (or line pattern on edges) beside a categorical color
  binding: a second binding on the same value. The element's `overflow: "shape"` already does part
  of this.
- **C. A label from the value** as the text form of any derived color.

**Recommend B and C.** graphty-element adds (additive) bindable label size and label color as their own channels, so
"label size by degree" works.
