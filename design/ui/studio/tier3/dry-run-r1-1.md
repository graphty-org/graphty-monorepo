# Tier 3 dry run before round 1: what to fix and what to leave

Every tier 3 task (T37 to T51, both halves) was piloted on the frozen build 58556989e8 before any
study session: the success path by pointer, the commonest detours, and the whole task by keyboard
with a screen reader's reading. This page lists every problem the pilots found, sorts it, and
gives the reason.

The sessions are for learning what a first-time user needs to style a graph. A session spent on a
clipped word, a dead key or focus falling to the page teaches nothing about that, so every such
problem is fixed before round 1. A problem that is a real design question -- where something
lives, what a reader expects, what a new concept is called -- is left in, because answering it is
what the sessions are for.

Classes:

- **(a) fix now.** An implementation or polish defect a participant could hit: text cut with room
  to spare, a control that does nothing or gives no feedback, focus falling to the page, a key
  that does nothing where a person expects it to, a missing or wrong screen-reader name, a message
  that is never spoken, raw internal text, a wrong count or value. Each names its fix group.
- **(b) leave for the sessions.** An open design question the study exists to answer.
- **(n) no change.** Expected behavior, a decided convention, a property of the frozen start that
  the answer key records, or a note about the study tool rather than the app; the reason says which.

Screenshots are under `rounds/r1/pilot/<task>/` (for example `T38A/success/14.png`). Fixing the (a)
list changes the build, so round 1 runs on a new frozen build: every task is piloted again on it.

## Decided in this triage (the team's calls, reversible)

- **The base layer is not narrowed.** Everything holds the base look; a condition on it made
  every node outside the condition vanish from the drawing (T41B, T45A, T45B, T48A). Its "Which
  nodes" reads "All N nodes" with no invitation and no Add a condition. A reader who wants fewer
  nodes makes a layer, which is the path every task's key already takes.
- **Escape in a style field keeps focus in the field.** The earlier rule ("outside a pop-out it
  reverts and leaves the field") left focus on the page itself. Escape now reverts what was typed
  and keeps focus in the field, inside a pop-out or not, so the next keystroke has a home.
- **A cursor stays an arrow over buttons.** compact-mantine sets `cursorType: "default"` on purpose
  (desktop convention, Figma's). The pointers reported as "cursor: default" are that rule, not
  defects.
- **Wheel zoom toward the pointer** is an additive graphty-element camera option; the graphty app
  turns it on. The element's default stays as it is.
- **More groups than a palette has colors:** the app picks a categorical palette that covers the
  group count when the element's catalog has one, and the element's catalog gains one when it has
  none (additive). The element's extension of an 8-color palette made three near-identical oranges.

## Open questions the dry run hands to round 1

The (b) items cluster on five questions, worth reading first in the sessions:

1. **What names a node.** Ids stood in for names in find, the inspector, layer names, the key and
   undo notices on every task whose file has a name column, and hover showed nothing. The product
   has no concept of the column that names a node; whether it needs one, and where it is set, is
   a design question -- and an element concept, so possibly the owner's.
2. **Where the color of everything lives.** Every pilot that started at the Graph inspector's
   Style tab found only a background color.
3. **What Enter in find takes.** Pilots expected Enter to take all matches.
4. **Whether a number card needs "at least".** Between with the column's highest value worked but
   was not what pilots reached for first.
5. **Keyboard on the canvas.** The canvas takes focus and no key reaches a node; the table is the
   only keyboard route. A graphty-element capability not built yet.
