# Tier 3, iteration 1: accessibility walkthrough of the style panel -- Accessibility Specialist

Build under test: the frozen build `.study-builds/tier3-i1-68a2140049/` (build stamp
`cfa6408d84a4 graphty@0.8.68`), the one served at https://dev.ato.ms:9373, opened at `/?next`.

How it was checked (WCAG 2.2 AA):

- **Keyboard and screen reader, by keys only.** Two screen-reader-mode sessions of the studio's
  `real.mjs` (Playwright, its own browser, through the browser gate) on that build, which print the
  focused control's role, name, value and states after every key, every live-region change, and
  what browse mode reads. Les Miserables open with Degree ("Connections"), Louvain ("Communities")
  and later Edge betweenness ("Bridge edges") run. Every control of the tree, the Style tab, the
  Values tab, Graph settings, every popover and menu the panel opens, the draft, Which elements, a
  folder, several rows, a locked row. Session folders: `tier3/build/a11y-i1/sr1/` (202 screenshots)
  and `sr2/`.
- **axe-core** (tags wcag2a, wcag2aa, wcag21aa, wcag22aa) in nine panel states, in the light and
  the dark theme, against https://dev.ato.ms:9373 in a Playwright context of its own:
  `tier3/build/a11y-i1/axe-walk.mjs`, results `axe/axe.json`, screenshots `axe/<theme>-<state>.png`.
- **Computed contrast** of every text in the tree and the inspector and of every placeholder, both
  themes: `contrast.mjs`.
- **200% zoom** (720 x 450 CSS pixels): `zoom.mjs`, `zoom-*.png`.

Every screenshot cited was looked at. `build/` is not committed; the paths below are under
`design/ui/studio/tier3/build/a11y-i1/`. "Owner" is the package where the fix belongs.

Severity: 4 blocks a keyboard or screen-reader user from a task; 3 loses their place or hides
information a task needs on a common route; 2 slows or misleads; 1 polish; 0 not a defect.

No step raised a script error, a `console.error` or a failed request.

## What already works

Worth keeping, because each was an ask from the design answers:

- Nodes and Edges are real headings (level 3) under the layer's name (level 2), so a screen reader
  user can jump between them.
- Every select and number field says its state in words: "Node size, not set, Node defaults gives
  1", "Node size, set here, 3", "Edge head, not set, Triangle by default", "Node size, mixed:
  Connections".
- **Unsetting (the owner's first question) works by keys for numbers and selects.** The minus is a
  Tab stop named "Clear Node size", described "Clear: back to 1, from Node defaults", and after
  Enter focus lands on the field, now named "Node size, not set, Node defaults gives 1" (`sr1/28-30`).
  The gaps are the color fields and Label settings (finding 7).
- Tree rows are named with their kind and reach: "Communities, layer, 77 nodes", "People, folder, 0
  layers"; "hidden" and "painted over by the layers above" are their descriptions.
- The ramp's thumbs are sliders whose value is in data terms: "Ramp starts at Degree rank 4".
- Counts are announced once, politely: "77 labels, 16 hidden" when a label is added, "1 of 77
  nodes" when a Which elements rule changes, "Edge betweenness finished".
- Which elements: Done returns focus to the rule sentence, "Which elements: Nodes where name
  contains val. Edit"; the condition rows are named (Attribute, Is, Value, Remove condition).
- Settings popovers (Shape settings, Label settings) and menus return focus to their opener.
- axe: one hit in all eighteen runs (finding 24). Text contrast: every text in the tree and
  inspector measures 4.5:1 or more in both themes; placeholders 4.66:1 (light) and 6.65:1 (dark).

## Severity 4

1. **A layer cannot be put into a folder by keyboard.** Alt+ArrowUp and Alt+ArrowDown move a row
   among its siblings and pass over a folder (Communities moved above the empty People folder,
   `sr1/157`); nothing moves a row into or out of a folder, and the row menu (Shift+F10 or "Layer
   actions") offers Rename, Pin to top, Pin to bottom, Unpin, Delete -- no "Move to folder", which
   the design lists (`sr1/159`, `sr1/125`). Dragging is the only way. Folders are part of the
   owner's settled model, so a keyboard user can make a folder and never fill it (WCAG 2.1.1, level
   A). Owner: graphty app (the row menu's "Move to folder", from the design), and compact-mantine
   `Tree` (Alt+ArrowRight into the folder above, Alt+ArrowLeft out to the parent, reported through
   `onMove` like the up and down moves).

2. **Label settings runs past the window and does not scroll, so Tab walks focus off screen.** The
   pop-out is taller than the window (`sr1/77`); Tab moves on through about forty controls below
   the edge without bringing any into view. A sighted keyboard user cannot see what has focus
   (2.4.7, 2.4.11). The Design Engineer's audit found the same and measured it
   (`iterations/1/engineer.md`, finding 1). Owner: compact-mantine (`Popout` caps its height at the
   window and scrolls its content), so every pop-out gets it.

## Severity 3

3. **Closing the value picker or a binding popover drops focus to the page.** Escape from the "by
   attribute" picker (opened by its button, `sr1/33`, or by "=" in the number field, `sr2/06`),
   Escape from "Size from data" (`sr1/53`), its Close button (`sr1/56`) and Escape from "Color from
   data" (`sr1/65`) all leave focus on nothing; the next Tab lands on "Resize inspector" at the
   panel's end. The script reproduces it with the picker opened by keys and the ramp by a click, in
   both themes (`axe/axe.json`: `focusAfterPickerEscape` and `focusAfterRampEscape` are "page").
   Every binding edit, the heart of questions 5, 6 and 12, ends with the keyboard user lost (2.4.3).
   Shape settings, opened the same way from the same row, returns focus correctly (`sr1/61`).
   Suspected mechanism, not yet traced: both broken triggers wrap `PopoutButton` in a `Tooltip`
   inside `Popout.Trigger` (`PropertyRow.tsx`, `VaryButton` and `BoundValue`), so the trigger ref
   that `PopoutPanel` focuses on close is not the button. Owner: compact-mantine (`PopoutTrigger`
   must hand its ref to the button through a Tooltip, as every caller writes it), checked by a
   real-key test in the app.

4. **Making a layer from the panel drops focus to the page, and nothing says a layer was made.**
   Three routes: typing the draft's first value and pressing Enter (`sr1/94-95`; the draft becomes
   "New layer" and the panel redraws with nothing focused); "New layer for 1" in a category's menu
   (`sr1/140`); Escape on a draft, which also discards it silently and opens Graph settings
   (`sr1/200`). The only live text is "77 of 77 nodes", which arrives with the region already filled
   and many screen readers will not read. Adding a layer is the first step of question 11's
   generic path (2.4.3, 4.1.3). Suspect: `TreeRowPanel` keys `RowStyle` on the row ids, so the
   new layer remounts the panel. Fix: focus the field that was edited (or, for "New layer for", the
   new layer's first property, as the design says), and one polite line "Layer added: New layer".
   Escape on a draft should close the draft and return focus to "Add a layer or a folder". Owner:
   graphty app.

5. **The category popover hides which row is which.** The value names and counts are in the
   accessibility tree ("Pick Louvain 1 color", "1 20") but drawn under the color fields, so a sighted
   user sees six hex codes and cannot tell community 1 from community 5 (`sr1/136`,
   `axe/light-4-categories.png`, measured: each name sits at x 1113, inside the 1013-1195 color
   field). Low-vision and sighted keyboard users cannot recolor a chosen community (1.3.1). The
   Design Engineer traced it to `ValueRow` not passing `CompactColorInput` its slot width
   (`engineer.md`, finding 2). Owner: graphty app.

## Severity 2

6. **Space on a tree row hides or shows the layer, silently.** The app's `onRowKeyDown`
   (`StyleTree.tsx:253`) takes Space before compact-mantine's Tree, where Space selects; Shift+Space
   and Control+Space also hide. Three presses on Communities changed the drawing three times with
   no announcement (`sr1/22-24`); the first time it happened by accident while trying to select
   (`sr1/06`, the drawing switched to Degree colors at `sr1/14`). A screen-reader user expects Space
   to select in a tree (4.1.3, 3.2.2). Fix: leave Space to select; keep hide on the row's eye
   button and a chorded shortcut (Figma uses Shift+Command+H), with a polite "Communities hidden".
   Owner: graphty app.

7. **"Not set" and "Mixed" are not said for color fields or in Label settings.** A color the layer
   does not write shows the inherited hex in italic, and a screen reader hears it as a value:
   "Louvain 1 color, E69F00" for a palette color, "Glow color 00B4FF" for a glow just added, "Text
   color 1A1A1A" in Label settings (`sr1/77`, `sr1/85`, `sr1/136`). A color field that is mixed shows
   "MIXED" but is read as an empty "Node color" (`sr1/92`, `sr1/162`). In Label settings, number
   fields show "Default" on screen and are read as "0" ("Line height 0", "Margin above 0"), so the
   screen reader is told something the screen does not say. Selects and number fields on the Style
   tab already do this right. This is the owner's first question for every field kind: the reader
   must hear "not set" and what comes from beneath (1.3.1, 4.1.2). Owner: compact-mantine
   (`CompactColorInput` and the number input used in Label settings take the same "not set" and
   "mixed" naming the Style tab's `StyleSelect` and number field use).

8. **Repeated names in a layer that paints nodes and edges.** Both groups have "Add text" and "Add
   to Text"; once set, both have "Detach Color", and each label row has "Look", "Size", "Position",
   "Label settings", "Hide label", "Remove label" with no Node or Edge in them (`sr1/198-199` read;
   `sr1/75` for the label row). Studio rule: no two reachable controls share a name. Fix: the kind
   word in each ("Add node text", "Detach node color", "Node label size"). Owner: graphty app.

9. **Two Tab stops for one action, and a menu of one item.** An empty list's title is a button that
   opens the same menu as its "+": "Add text" and "Add to Text", "Add node effect" and "Add to node
   effects" (`sr1/09`). The "+" says "Add text" as its tooltip but "Add to Text" as its name (2.5.3).
   Text's "+" opens a menu holding only "Label" (`sr1/68`). Fix: one stop per list; where a menu
   would hold one item, the button adds it. Owner: graphty app.

10. **The binding popover has two unlabeled From / To pairs.** Data range and size range are both
    "From" and "To" to a screen reader, and on screen neither pair has a visible label: four boxes
    reading 1, 61, 1, 3 (`sr1/49`, `sr1/52`; the color ramp's pair the same, `sr1/64`). (3.3.2,
    2.4.6.) Fix: captions "Data from / to" and "Size from / to" (or the column name), used as both
    the visible label and the name. Owner: graphty app.

11. **A bound value's button does not name its property.** The size pill is "1 to 3, variable Degree
    rank", the color pill "Degree, Color", their neighbors "Detach Size", "Detach Color"
    (`sr1/46-47`). Read in order after "Node shape", a listener does not know the first is size.
    Fix: "Node size from Degree rank, 1 to 3"; "Node color from Degree"; "Detach node size".
    Owner: graphty app.

12. **A locked layer's panel is empty to Tab.** Locking puts every control in a native disabled
    fieldset, so Tab goes from the Style tab straight to "Resize inspector" (`sr1/122`, read at
    `sr1/124`). The line "This layer is locked" is found only in browse mode, and nothing is said on
    the Lock button beyond "pressed". Studio rule: disabled controls stay focusable
    (`aria-disabled`) with the reason as their description. Owner: graphty app (or compact-mantine
    if a shared "locked group" is wanted).

13. **A number field takes letters, and ArrowDown then writes 0.** Typing "rank" into Node size and
    pressing ArrowDown set the size to 0 and every node vanished, with no warning (`sr1/38-40`).
    Undo did not restore it from the field. (3.3.1, 3.3.4.) Fix: the field refuses letters and
    keeps the channel's minimum. Owner: compact-mantine (the number field), with the minimum from
    graphty-element's channel descriptor.

14. **Which elements: unexplained disabled choices and look-alike options.** After the first write,
    Edges and Both are disabled with no reason (`sr1/99-101`). Find offers "This node" three times,
    one per hit, with nothing saying which node (`sr1/110`). A search with no hit says nothing
    (`sr1/103`). Fix: a reason as the description ("Make a new layer to paint edges"); "This node:
    Valjean"; "No element matches bob" in the existing status line. Owner: graphty app.

15. **Category rows need context in their names.** "Hide 1", "1 menu", and the count read as a bare
    number ("1 20") (`sr1/136`). Fix: "Hide Louvain 1", "Louvain 1 actions", "20 nodes". Owner:
    graphty app.

16. **The legend, the drawing's text equivalent, disagrees with the panel.** Size bound to Degree
    rank is listed as "Size: Degree" (`sr1/49`); Louvain's values 0 to 5 are "Group 1" to "Group 6"
    in the legend but "Louvain 0" to "Louvain 5" in the panel and the new layer "Louvain 1"
    (`sr1/136`, `sr1/140`); a label's size shows as "Degree / Connections 72" (`sr1/75`). (1.3.1,
    3.2.4.) Owner: graphty-element if `styles.legend()` reports the wrong source or labels; else the
    app's legend card.

17. **Graph settings does not open the settings.** Enter on "Graph settings" keeps focus there and
    the inspector shows the graph on whichever tab was last open, Values here (`sr1/168`); nothing
    is said. Fix: open the Style tab and move focus to its first section. Owner: graphty app.

18. **Algorithm layers have no Which elements.** Only layers the reader made show the rule; Degree,
    Louvain and Bridge edges show none (`sr1/05`, `sr1/133`), so a screen-reader user learns what a
    run's layer paints only from the tree's count. Provenance changing behavior also breaks the
    owner's settled model; the Design Engineer reports it as finding 3. Owner: graphty app.

19. **At 200% zoom the bottom toolbar is cut off under the inspector.** Only Analyze, Layout, View
    and part of Legend are visible (`zoom-2-layer.png`) (1.4.4, 1.4.10). Not new in tier 3. Owner:
    graphty app's workspace layout (or compact-mantine's shell, if the toolbar's placement is
    shared).

## Severity 1

20. **Shape list.** Names are cut ("Octahed...", "Torus k...") with no tooltip, and the highlighted
    option is announced "selected" while the field is not set (`sr1/14`); Down moves by a row of
    four, Right by one. Owner: compact-mantine (the glyph-grid select; Mantine marks the hovered
    option `aria-selected`).

21. **Ramp slider steps.** On a rank, Right moves 1 to 4 to 6.85; Page Up and Page Down do nothing
    (`sr1/51-52`). Owner: compact-mantine `RampEditor` (whole steps for whole-number data, page keys
    for tenths).

22. **The value picker's names.** Its dialog is named "From data" while its title reads "Size by
    attribute"; its groups (Degree, Louvain) are not exposed, so "Degree" the group and "Degree" the
    value sound alike (`sr1/32`). Owner: graphty app.

23. **Colors are spoken as hex.** "Fix at #B84203", "Clear: back to #6366F1, from Node defaults"
    (`sr1/64`, `sr1/47`). A color name from the palette when it has one, the hex after it. Owner:
    graphty app.

24. **Tree row targets.** axe's only hit: "Lock Bridge edges" is 20 by 24 px where the row's other
    button overlaps it (2.5.8), both themes. The tree also takes two Tab stops per row (lock, eye)
    before the panel: 12 stops for 6 rows. Owner: compact-mantine `Tree` row actions.

25. **Smaller ones.** Label settings' section captions (Type, Box, Letters, Placement) are plain text
    run into the first field's label, not headings or groups (`sr1/77`). After naming a new folder,
    focus goes to "+" rather than the folder's row (`sr1/146`). The Attribute list in a condition
    row opens as soon as Tab reaches it (`sr1/113`). A list title's shade alone says whether
    something is set beneath ("Text" bright, "Tooltip" dim, `sr1/75`). Owner: graphty app.

## Not checked, and why

- **Selected and Hovered.** The real app starts with no Everything, Selected or Hovered row (the
  Design Engineer's finding 4), so the selection halo's contrast (1.13:1 on `#F5F5F5` when measured
  from source) and the badge presets' contrast could not be re-measured on the build. Owed once the
  app turns the starting rows on.
- **What a real screen reader says.** The sessions read Chromium's accessibility tree; phrasing and
  interruption in NVDA or VoiceOver still need a person.
- **Reduced motion** (label animation, edge Motion): graphty-element does not honor it yet; not
  drawn, not judged.
