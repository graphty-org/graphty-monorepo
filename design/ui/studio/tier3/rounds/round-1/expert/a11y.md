# Tier 3 round 1: accessibility walkthrough

Build 758b8e8081 (graphty@0.8.91), served from
`/home/apowers/Projects/graphty-monorepo/.study-builds/tier3-r1d2-758b8e8081`. Walked 2026-10-21 against
WCAG 2.2 AA: names, roles, focus order and visibility, contrast, announcements.

How it was walked:

- Every bar 6 screen at 1440 x 900 and 900 x 700 in both themes, from the round's scripted walk
  (`../bars/sessions/`, dark; `../bars-light/sessions/`, light), every screenshot looked at, with
  the walk's axe results, shared names, focus checks and spoken text (`../bars/spoken.json`).
- Three keyboard-only screen-reader sessions of my own (`real.mjs --sr`, which refuses every
  pointer step and prints focus and live-region text after each key), under `a11y/`:
  `k1` light 1440 x 900 (start screen, a sample, Everything's tabs, a new layer, picker, text
  card, "Starts with", color, Undo, menus, Louvain, the folder and its dialog, find, a node's
  inspector, two layers picked), `k2` dark 900 x 700 (a file read and loaded, category, yes/no,
  number and has-no-value cards, color and size bound to columns, the shape list, a colleague's
  project, the color picker, Select layers), `k3` dark 1440 x 900 (sample search, start buttons).
- Contrast by measurement: axe's computed colors, and pixel ratios from the screenshots
  (`tmp/a11y-t3r1/px.py`) where axe does not look (focus rings, the purple token).

Severity: 0 not a problem, 1 cosmetic, 2 minor (a detour or a lost place, no task blocked),
3 major (a task blocked or misread for some readers), 4 catastrophic.

## Summary

- **No severity 3 or 4.** Every success path of the round's tasks was walked by keys alone, with
  no place a keyboard user cannot reach, operate or leave. Focus never fell to the page after any
  action I took. Every core change is announced once: a card's count ("16 of 24 nodes"), a color
  ("Node color now purple, on 6 nodes"), Undo, a run ("Louvain finished: 6 groups, each a layer in
  the Louvain folder of Style layers"), a load, an open.
- **Bar 6 fails as measured on this build, in both themes.** Dark: axe target-size on the "Open
  layer" buttons of "Why this look" and on the number card's slider thumbs; axe
  scrollable-region-focusable on the shape list and the find list; three names shared on the start
  screen. Light: all of those, plus the Autosave chip's contrast (2.17:1) on every workspace screen.
  Focus never fell to the page (all 48 actions) and every typing check wrote its text: those parts
  pass. Findings 1 to 3 and 15 to 16 below are the failing parts.
- **The purple "Layer" token passes in both themes:** #d1a8ff on #2c2c2c is 7.15:1 (dark),
  #8638e5 on #ffffff is 5.66:1 (light), measured on `bars/sessions/first-use-1440x900/31.png` and
  its light twin.
- The pill tabs (Node / Edge) now draw a #868686 border on the active tab, 3.34:1 against the panel
  (`k1/16.png`): fixed since the tier 3 design review.

## The backlog's accessibility entries, walked

Confirmed and rated above: F6 (8), Samples Enter (5), focused heading (7), shared names (3),
the demo first in Tab order (4), a sample card's name (6), the private notice (17, 9), the
pre-filled live region (18), the library search (13), the hex in "Edit discarded" (19), Tab in a
"+" menu (20), Tab in the color picker (21), Enter on a condition's checkbox (22), the yes/no
value's name (23), the size dialog's histogram (24), the attribute list's headings (25), "Close
panel" (26), grid cell names and "Reset Palette" (27), Enter on the breadcrumb (28), "Degree 36"
(29), the start buttons' ring (31), "Pick edge color" ring (32), the folder's color names (10),
Control+A (12).

Closed on this build:

- **The analysis filter: Tab lands on a disabled button, Escape on Back does nothing.** Tab with
  "deg" typed opens Degree with focus on "Run Degree"; Escape on the form returns to the list
  with "deg" kept (`k2`).
- **After a line is removed focus goes to another section's "+".** Removing the node color
  focused "Add to node fill", its own section's "+", with "Node color removed" spoken (`k2`).
- **Shift+Tab from the bound Color line skips "Pick node color".** A bound color has no picker:
  its stops are the value button ("Node color: role, ..."), "Stop varying node color by data" and
  "Remove node color" (`k2`). Not a defect.
- **Select layers mode: checkboxes with no name.** The rows are tree items that report "selected";
  the drawn checkboxes are decoration (`k2/97.png`). The mode's real problem is focus (finding 11).
- **A tooltip and the control's name differ.** The eye's tooltip now matches its name; the dimmed
  Undo's "Nothing to undo" is its reason, not its label. Severity 0.
- **After Discard focus once landed on the canvas.** Discard then open went to the title heading
  with "Opened lesmis-poster" spoken (`k2`). Not reproduced.
- **Tab commits "Size from" but stays in it.** Tab moved from "Size from" to "Size to" (`k2`).
- **Escape in a popover's or the picker's box reverts silently.** Not reproduced in the two boxes
  walked: the color box says "Edit discarded; this stays ..." and the picker's text keeps what was
  typed. The size popover's number boxes were not tested with Escape.

Not walked (their screens are not on round 1's walk): "Degree finished" names no node, "34
selected", "Filter to..." in the Data place, committing a label's size, "Color by kind" naming two
of three groups, an icon with no tooltip (hover only; my sessions refused pointer steps).

- Bar 6: fails as measured. The fix list is findings 1, 2 and 3 (real defects), 15 (a hit area or
  an agreed exception) and 16 (the tier 3 walk needs its in-view scroll check before the agreed
