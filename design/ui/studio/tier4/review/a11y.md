# Tier 4 review: accessibility (keyboard, focus, screen-reader names, contrast)

Build: e52d7c4f5748 (graphty@0.8.92), the tier 4 branch's `graphty/dist`, copied to
`tmp/design-studio/tier4/review/a11y/dist` in the main checkout. `real.mjs` served the copy on loopback
(no servherd server was needed). Every walk ran in screen-reader mode (`--sr`), by keys only, on the GPU,
at 1440 x 900, dark mode off. Screenshots are under the main checkout's
`tmp/design-studio/tier4/review/a11y/`:

- `k1`: pantries.csv. The data table, the issue fixes, Fields "+" (Time), Add source > File > Join.
- `k2`: volunteers.graphml. Filter cards (trained + hours, then role with Select), and Export > Data.
- `k3`: the start screen. Open network data > web address.
- `k4`: pantries + deliveries. The Data source card.

Severity: 4 blocks a task for a keyboard or screen-reader user; 3 loses work or misleads silently on
the success path; 2 costs extra steps or hides a fact the reader needs, but the task can still be done;
1 is cosmetic.

## What already works

Every flow can be finished by keys alone: loading from a file and from a web address, joining, setting
the time, fixing issues, building two filter cards, and exporting data. Several of the best parts are
the filter cards:

- Names carry the condition ("Apply trained is Yes and hours is between 10 and 52", "Remove role is
  staff", "hours from, number").
- Each change says its count once ("Filter on: 14 of 24 nodes, 22 edges", "5 nodes selected").
- The cards' combobox follows the pattern every other list should copy: it says "expanded" when open,
  it does not mark the highlighted option as selected, and it opens on ArrowDown.
- After a join, focus goes to the new source row and the reader hears the new counts.

Contrast was measured on the screenshots and checked against the tokens:

- Highlighted option: 9.1:1.
- Focus border on a combobox (#588300): 4.5:1.
- Unchosen segment label (`text-secondary` #0000008c on the track): 4.7:1.
- "Lost in CSV" heading: 4.85:1.
- Table meta text: 4.7:1.

No new contrast failure was found on these flows.

## Findings

### 1. Tab out of a new filter card throws the card away without saying so -- severity 3

- **Flow:** Filters (task T65). **Screen:** Data > Filters > "+" > role. This adds a card with three
  value checkboxes.
- **What is wrong:** Focus lands on the first checkbox. Tab is the normal way to read a list of
  checkboxes. After the last value, Tab discards the card, because nothing is checked yet, and sends
  focus up to "Add filter". Shift+Tab from there goes to "Collapse Filters", not back to the card. No
  message says the card is gone (k2, screenshots 26-29). A keyboard user who reads the choices before
  choosing loses the card and lands above where they were.
- **Pattern to reuse:** tier 4 `decided.md`: "Escape on a just-added line or card that holds nothing
  takes it back, **says so**, and puts focus on the '+' or 'Add a condition' that added it." Only
  Escape takes a card back, and it says so.
- **Change (app, `graphty/src/workspace/data-place/Filters.tsx`, in the card code it shares with the
  Style panel's Which nodes cards):** Tab never discards a card. An empty card stays, with its count
  chip showing nothing matched yet, and Tab moves to the next control in order. Discarding stays
  Escape's job, with its message. Add a real-input test: Tab past the last value keeps the card.

### 2. A column's data issues cannot be heard from its header -- severity 2

- **Flow:** Data issues (T67). **Screen:** Table > a header with the warning glyph (families, site).
- **What is wrong:** Arrow keys move through the header buttons. Focus reads `button "mixed families"`,
  described as "100% filled 12 unique". The warning's names ("Issues in families", and as its
  description "1 not a number") sit on a separate `role="img"` that focus never reaches. A
  screen-reader user moving through the grid never hears that a column has a problem. Only browse
  mode reads the warning.
- **Pattern:** the Fields location rows (tier 3, issue #3315): a fact shown by a glyph is also in the
  control's `aria-description`, never in the glyph alone.
- **Change:** in compact-mantine `DataTable`, let a column's config carry an extra accessible
  description for its header button. This is additive and changes no look. In the app
  (`table/HeaderCell.tsx`), pass the issue labels into it. The header then reads "mixed families, 1
  not a number, 100% filled ...".

### 3. Nothing tells the reader how to open a header's menu -- severity 2

- **Flow:** issues, column kind, rename, filter-to (T62, T67). **Screen:** the table header.
- **What is wrong:** Alt+ArrowDown, Shift+F10 and the context-menu key open the header menu, and every
  fix lives in that menu (compact-mantine `DataTable.tsx`, `opensHeaderMenu`). But:
    - The header button says nothing about it: no `aria-haspopup`, no `aria-keyshortcuts`.
    - The visible "..." button ("Options for families") has `tabIndex -1`, and its tooltip shows no key.
    - Enter on a header sorts instead.

    A reader who does not already know the key never finds the fixes. This breaks the owner's rule that
    every hotkey has a visible button showing its key.

- **Pattern:** compact-mantine `MenuShortcut` and `aria-keyshortcuts`, already used on menu rows.
- **Change (compact-mantine `DataTable`):** add `aria-haspopup="menu"` and
  `aria-keyshortcuts="Alt+ArrowDown Shift+F10"` to the header button. These are ARIA only, with no look
  change. The "..." tooltip should also show "Alt+Down". That changes the tooltip's words, so it is
  recorded for the owner in `owner-decisions.md` if it counts as a look change under the Figma lock.

### 4. Menu section labels are not heard: fixes and fields lose their context -- severity 2

- **Flow:** issues (T67), Filters "+" (T65, T66). **Screens:** the header menu, and the Add filter menu.
- **What is wrong:** `Menu.Label` text is not a group name:
    - The header menu's first item reads "Make blank, menuitemradio, not checked". It never says "1
      not a number" or which column.
    - In the Add filter menu with two sources, "trips" is heard with no "Edges" around it, so a reader
      cannot tell node fields from edge fields.
- **Pattern:** tier 3 decision of 2026-10-23 (issue #3315; Layout and Analyze menus): each heading is
  `role="group"` with `aria-label`, so the reader hears "Edges, group" on entry.
- **Change (app, `table/HeaderMenu.tsx` and `data-place/Filters.tsx`):** wrap each section in a group
  named by its label, the same way the Analyze menu does.

### 5. Fixes and designations happen without a word -- severity 2

- **Flow:** issues (T67), time (T62, T63). **Screens:** the header menu > Make blank or Trim; Fields
  "+" > Time > opened.
- **What is wrong:** Make blank fixed families and silently re-sorted the table. Choosing the time did
  four things with no status message:
    - designated the column;
    - opened a timeline strip;
    - added a clock to the toolbar;
    - added a "Time" card under Filters.

    The reader learns of none of them (k1, screenshots 20 and 40).

- **Pattern:** the filter cards' single status line ("Filter on: N of M ...").
- **Change (app):** one polite message per act, through the same announcer. Examples: "families: 1
  value made blank" and "Time: opened. Timeline opened."

### 6. Loading and joining speak the same counts two or three times -- severity 2

- **Flow:** load (T60), join (T61).
- **What is wrong:** each act repeats itself:
    - The join says "13 of 13 rows", "13 of 13 rows", "pantries: 13 nodes, 18 edges", "13 nodes, 18
      edges".
    - Opening from a web address focuses the heading "Graph, sources: 24 nodes, 59 edges", then says
      "sources: 24 nodes, 59 edges" and "24 nodes, 59 edges".
    - Opening the join screen says "19 of 19 rows", which means nothing there.

    This breaks the notes rule "one utterance per change, never the same thing twice".

- **Change (app):** the table's "N of M rows" region speaks only when a table filter changes. Keep one
  load status line, not two.

### 7. The Fields and Join lists report the wrong state -- severity 2

- **Flow:** Fields (T62-T64) and Join (T61).
- **What is wrong:** the two screens use plain `Select` from `@mantine/core`, not the combobox the
  condition cards use:
    - A newly added Fields row ("Node time") opens its list with `defaultDropdownOpened`, yet says
      "collapsed" while the list is on screen.
    - Every option the arrows pass is announced "selected", so the reader hears four selections before
      choosing one (k1, screenshot 38).
    - The Join screen's four selects open their lists when Tab reaches them, so tabbing across the row
      pops up four lists that cover the Target row (k1, screenshot 49).
    - Every other list in the app opens on ArrowDown.
- **Pattern:** the filter card's combobox ("trained: how to match"), and tier 3's decided "Opening an
  existing card changes nothing ... typing or ArrowDown opens it".
- **Change (app, `data-place/Fields.tsx`, `join/MatchRow.tsx`):** use the same compact-mantine
  combobox as the condition cards. It already fixes Mantine's highlight-as-selected (`listbox.tsx`)
  and keeps `aria-expanded` true.

### 8. The Fields rows name themselves in four different ways -- severity 2

- **Screen:** Data > Fields.
- **What is wrong:** the names are "Id", "Node time", "Node latitude column" and "Node coordinates
  column" (the code is `Fields.tsx` around line 356). A reader comparing rows hears four grammars.
- **Change (app):** use one form, "<Node|Edge> <role>", for example "Node id", "Node time" and "Node
  latitude". The visible label stays inside the name.

### 9. The Data panel has no headings, and its "+" menus have no menu state -- severity 2

- **Screen:** Data panel.
- **What is wrong:**
    - Sources, Fields and Filters are not headings. They read as "Collapse Sources" buttons, and
      "Filters" is plain text while it holds no card. A screen-reader user cannot jump between them by
      heading.
    - "Add source", "Add to node fields", "Add to edge fields" and "Add filter" each open a menu but
      report no `aria-haspopup` or expanded state. Only "pantries.csv menu" does.
- **Pattern:** the inspector's sections ("Overview", "Degree" are level 3 headings) and the source
  row's own menu button.
- **Change:**
    - compact-mantine `ControlSection`: give the title heading semantics (`role="heading"` with a
      level). This is ARIA only.
    - App `style/Section.tsx` `AddButton`: add `aria-haspopup="menu"` and `aria-expanded` when it
      opens a menu.

### 10. The rail does not say which place is open -- severity 2

- **Screen:** the left rail (Graph, Data, Notes).
- **What is wrong:** all three read as plain buttons whichever is open.
- **Change (app rail):** give the open place `aria-current="page"` or `aria-pressed="true"`.

### 11. Export: choosing a kind is silent, and the dialog opens on Close -- severity 2

- **Flow:** Export (T68). **Screen:** Control+E > Export dialog.
- **What is wrong:**
    - The kinds (Image ... Project) are `gridcell`s with no selected state.
    - Arrowing to "Data" does not choose it; Enter does, and nothing says the options below changed
      (k2, screenshots 39-43).
    - Focus opens on "Close", not on the chosen kind.
    - The preview is a focusable `generic` element, so it is read with no role.
- **Pattern:** compact-mantine vertical `Tabs` (a tablist with `aria-selected`), the Settings
  dialog's left list.
- **Change (app export dialog):**
    - Make the kind list a vertical tablist that follows focus, or a listbox with `aria-selected`.
    - Open the dialog on the chosen kind.
    - Give the preview `role="region"` with its name, or make it a read-only textbox.

### 12. The web address box has no visible label and no visible Open -- severity 2

- **Flow:** load from a web address (T60). **Screen:** start screen > Open network data.
- **What is wrong:**
    - The box's name exists only for assistive technology. Once text is typed, nothing on screen says
      what the box is (WCAG 3.3.2).
    - Enter is the only way to open the address; there is no visible Open button.
    - The icon inside the box is "Choose file", a different act.
- **Pattern:** the Join screen's explicit Join button, and the owner's rule that every key has a
  visible button.
- **Change (app):** add a visible label above the box and an "Open" button beside it. The file icon
  stays outside the box or goes.

### 13. F6 lands on resize handles instead of panels -- severity 2

- **Flow:** every long keyboard walk.
- **What is wrong:** after a resize separator has once been passed with Tab, F6 returns to the
  separator ("Resize left panel", then "Resize inspector"), not into the Data panel. The panel is
  skipped as a stop (k1, the F6 cycle).
- **Pattern:** decided: a region is entered at its focused, selected or resting row.
- **Change (app region cycle):** never remember a separator as a region's last focus. Enter the Data
  panel at its selected source row.

### 14. The join screen commits without the reader hearing what will happen -- severity 2

- **Flow:** join (T61). **Screen:** the join screen.
- **What is wrong:** focus opens on "Join" and the reader hears only "Join" (and "19 of 19 rows"). The
  facts that answer T61 are not spoken: 18 edges added, 1 new node, 1 not in graph, 1 repeated key.
  "1 not in graph" and "1 repeated key" are Tab stops further on; the first two are plain text.
- **Change (app, `join/JoinScreen.tsx`):** point the screen's `aria-describedby` at the chips row, or
  announce that summary once when the screen opens.

### 15. A filter card is not a named group -- severity 1

- **What is wrong:** reading a card in order gives "Node 15 of 24, Select, Hide, Apply ...". Nothing
  marks where one card ends and the next begins.
- **Change (app, the shared card):** make the card `role="group"` named by its condition.

### 16. Small visual focus faults -- severity 1

- **The selected source row:** its focus ring is drawn over the row's own "17/19" text and cuts the
  "9" (k1, screenshot 52). The ring and row belong to app CSS. If the ring is compact-mantine's tree
  ring, it is recorded for the owner.
- **The timeline window slider:** it says "Mar 1, 2015 - Mar 31, 2023", while the button beside it
  shows "Mar 2, 2015 - Mar 8, 2023".
