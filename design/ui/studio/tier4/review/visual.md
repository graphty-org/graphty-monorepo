# Tier 4 review: the Visual designer

Build e52d7c4f5748 (graphty@0.8.92), the studio worktree's `graphty/dist`, walked with `real.mjs` on the GPU at
1440 x 900: light (pantries alone, then joined with deliveries; sources.graphml from its web address) and dark
(pantries joined). Lens: density, alignment, spacing, truncation, and consistency with the Style panel and the
rest of the app. Screenshots are under the main checkout's `tmp/design-studio/tier4/review/visual/` (`s1` to
`s4`, crops beside them); they are not in git.

Severity: 4 blocks a task, 3 misleads or hides the fact a reader needs on a success path, 2 inconsistent or
costly but readable, 1 polish.

## For the director first: the setups fail on this build

`graphty/dist` has no `site.json` (only `graphty/sites/<channel>.json`), so every setup start logs a 404 and
`real.mjs` ends it with `SETUP FAILED` (s1 first attempt). A copy of the build with `sites/production.json`
written as `site.json` starts cleanly. The frozen build the workflow serves must carry `site.json`, or every
session that starts from a setup file is void.

## What holds up

- Dark mode keeps the Data place, chips and cards legible (s4 02); the canvas staying light is the owner's choice.
- The Server form and the Fields block use the Figma property-row pattern (gray label left, control right)
  consistently.
- Count chips (blue dot nodes, orange stroke edges) mean the same thing in Sources, Fields, cards, join and
  export.

## Top three to fix

V1 (the cards are the owner's chosen Style card in name only), V4 (the source name is cut on every two-source
project) and V3 (a date column readers must read is unreadable). V2 is the shared-part fix that also settles the
Type and role pickers.
