# Selection cards -- Accessibility Specialist's proposal (tier 5 panel)

Walked on build 13ab62a0bb (graphty@0.8.92), volunteers.graphml, pointer session plus screen-reader
read-outs: `tmp/design-studio/tier5/panel/a11y/p1/` in the main checkout (screens 04-14). Standard:
WCAG 2.2 AA and the studio's binding rules in `tier4/decided.md`.

## What the live surfaces do today (the baseline the new card replaces)

- **The two cards are not one card to a screen reader.** The Style "Which nodes" card has no group:
  it reads as loose text "24 of 24 nodes Nodes that pass every condition hours 24 nodes", then
  "Remove hours" (screen 11). The Filters card is a disclosure button "role, expanded", a count, then
  "Remove role is volunteer" (screen 10). Same act, two names, two structures.
- **Filters' effect radios read every sentence twice**: radio "Select: Select the nodes that match;
  nothing leaves the picture", followed by the same words as text. Three radios cost six utterances.
- **"Nodes that pass every condition"** sits at rest under Which nodes: a UI sentence (owner rule),
  and it becomes false once a selection is a union of groups.
- **The condition picker lists only Data and Structure** (screen 14). Algorithm output is reachable
  only through Analyze, which already has the right run pattern: a description, a cost ("Under a
  second") and an explicit Run (screen 13).
- **The range test is keyboard-complete** (two sliders, two boxes); mock J's brush is pointer-only.
- Open defect: the table's Tabs have no `Tabs.Panel` (`aria-controls` names nothing).

## Answers to the owner's questions

**1. Open the data table automatically while picking? No.** It moves the layout unasked, and at 900 x 700
the strip already cuts the Edges tab. Instead, the selection editor's header gets one **"Show in table"**
toggle button (tooltip shows its key; `aria-pressed`) that opens the table with a **Group** column
(swatch plus group name as text) and "Show only matches". The table is a screen-reader user's view of the
picture, so the toggle sits one Tab stop from the editor, and opening it never takes focus.

**2. Suspend node/edge styling and paint group colors while picking? Yes, as a visible, reversible
preview, never silently.** While a selection editor is open, a **"Preview groups"** toggle (default
on) shows the group colors. Built as an element-owned temporary style layer on top (the styling
rule: through the StyleManager, never by touching meshes), lifted on Done or Escape. Conditions:
announce it once ("Previewing groups, styles paused"); a non-matching node is faded _and_ keeps
its name, so color is never the only signal (1.4.1); every group fill measures 3:1 against the
canvas in both themes; the spoken color words for the group palette are distinct (the compact-mantine
`colorWord` hue-first fix); no animated transition under reduced motion.

**3. Run algorithms in the cards or outside? Outside, with one gate.** A field of a not-yet-run
algorithm starts a normal Analyze run **only on commit (Enter or click), never on highlight**:
arrowing through the picker must not start work. Above the live budget the card shows Analyze's own
Run button with its estimate; the run's state is a chip with text ("running", "failed", "waits for
step 1"), and its end is announced once: "Betweenness done, Group 1: 12 of 77 nodes". "Computed on
this group so far" is the only run the step owns, and its row says so in words.

## Dropdowns: contents and order

All are the existing compact-mantine combobox or SegmentedControl (real radios), headings as
`role="group"` inside the listbox (decided 2026-10-23), arrows stop on disabled options.

- **Verb ("+" on a group):** a menu, in order **Add, Keep, Except**, each icon plus word. Icons follow
  Figma's boolean operations: Union = Add, Intersect = Keep, Subtract = Except; Figma's Exclude is not
  offered. The accessible name is the word, not the icon ("Keep"); the icon meaning goes in the
  tooltip. compact-mantine has no boolean-operation icons today; if they are wanted from Figma's set,
  that is an owner item, and the words alone ship meanwhile.
- **Start with:** a two-segment control "All nodes | No nodes" (edges on the Edges tab), named
  "Start with".
- **Value picker:** the approved attribute picker (`WhichPicker`), extended, in order: **Data**,
  **Computed** (fields of runs that exist, with a done mark), then the **Analyze catalog categories
  in Analyze's own order** (Rank nodes and edges, ...), **Added** (user algorithms), **Structure** last.
  Each option's name reads value first, then source and state: "betweenness, Betweenness, not run,
  about 6 minutes". Unsupported kinds are `aria-disabled` with the reason. Graph values never appear.
- **Test ("how to match"):** the existing select, options chosen by kind (number: Between, At least,
  At most; category: Is any of, Is none of; flag: Is, Is not; ...). **By value | By position** is a
  separate two-segment control under it. The histogram is a view: the two sliders and two number
  boxes stay the input, and the bars have a text form (the hidden table already used).
- **Reference:** a combobox in order **Focus, Selected node, Picked nodes, This group so far, named
  selections**, then nodes by typing. The target button is a toggle (`aria-pressed`, "Pick from
  graph"); Escape disarms and says so. **Focus must also be the keyboard walk's focused node**
  (Shift+Arrow), not only the hovered one -- otherwise every Focus condition is pointer-only (2.1.1).
- **Computed on:** "Whole graph 77 | So far 41", sizes in the names; the disabled segment keeps its
  reason.

## What must match Figma and graphty's existing controls

- **Layers-panel row grammar for steps and groups:** the step list is one Tab stop walked with arrows
  (decided: tree and grid), a step row opens its card on Enter, rare options behind "...". Reorder by
  **Control+] / Control+[** (Figma's order keys) with Move up/down in the row's "..." menu (every hotkey
  needs a button); drag is never the only way; a move announces the new position and count.
- **One card component for both surfaces**, `role="group"` named by its step line ("Keep, hours 2 to
  52, 24 nodes"); remove names its step the same way on both. The Filters effect radios become short
  names ("Select", "Filter to", "Filter out") with the sentence in the tooltip only.
- Escape, Done and focus-after-remove as already decided.
- Groups are collapsible sections with a swatch, a name and a count; the spoken name carries the
  color word.

## Counts and announcements

One polite announcer, one utterance per settle: "Group 1: 24 of 77 nodes. Total 30." Provisional
steps say "waits for step 1" in text, never by a dashed style alone.

## Risks

1. **Pointer-only paths** in mock J: the histogram brush, hover Focus, the target button,
   drag-to-reorder. Each needs its key path in the first build.
2. **Tab cost**: five open cards are 30+ stops. Cards rest as one row; only the open card is in
   the Tab order.
3. **Run storms** from arrowing the picker or walking Focus by keys.
4. **Reflow**: at 900 x 700 the card keeps its count and remove visible; clipped words stay in
   the name and tooltip.
5. The table's Tabs defect blocks answer 1 until fixed.

## Who owns what

graphty-element: group evaluation and counts, runs and their pending/failed codes, the preview
layer, Focus bound to the hovered _or walked_ node. compact-mantine: nothing new in look; the
`colorWord` fix and any boolean icons go to the owner. App: names, focus targets, the announcer
words, the table toggle.
