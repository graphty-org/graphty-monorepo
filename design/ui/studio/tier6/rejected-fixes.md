## Rejected: panel-names-say-what

Unit: give each Assistant panel control a name of its own (`panel-names-say-what`, graphty). Each control in the Assistant panel -- the composer, the waiting line, the Undo at the end of a turn, the top-bar Undo and Redo -- names what it acts on (fix 7062e1aeae with test follow-up a18bfee708, reverted by 5423eff810 and 69e6f402ac). Part of the words and Checks change landed in sibling commit 208e142062 and is still in place: refix it in the shared part, so one naming rule covers every control that undoes a turn.

- REGRESSION (route T93 B keyboard): the Undo button at the end of an Assistant turn takes its accessible name only from the turn's first change line. In this walk the turn computed connected components and then removed 82 nodes, so the button is named 'Undo: Computed Connected components for 331 nodes'. Pressing it also restored the 82 removed nodes and 63 edges (331 and 361 again, live 'Undid ...'). A screen-reader reader who wants to take back the removal hears a button that names only the computation, so they may not press it or may misjudge what it will undo. Before this change the name was plain 'Undo', which made no claim. The unit test only covers a turn whose first line is the removal ('Undo: Removed 12 nodes'), so it passes. Source: graphty/src/workspace/assistant/Checks.tsx line 373, aria-label={turnUndoName(lines[0])}. Possible fixes: name the line that changed the graph (a removal or an edit) ahead of a computed one, or name every line. Screenshots: design/ui/studio/tmp/t6r2-recheck-panel-names-say-what/kbd/49.png (turn showing both lines and the Undo button), kbd/50.png (focus reads 'Undo: Computed Connected components for 331 nodes'), kbd/51.png (after Enter, 331 and 361 are back).
- Not caused by these changes, seen on the walk: the top-bar Undo tooltip's text runs past its dark box. Past the box the white text sits on the light canvas and cannot be read, and the 'Ctrl+Z' key hint is lost. The new 60-character cap makes the text shorter than before but does not fit it in the box. Screenshot: design/ui/studio/tmp/t6r2-recheck-panel-names-say-what/kbd/71.png (taken 1.5 s after focus, so the tooltip had finished opening).
- Not caused by these changes: the live 'Undid ...' and 'Redid ...' messages read the whole typed message, uncapped, and end in '..' (a doubled period). This is the trailing period near historyWords.ts line 359 that is already on the fix list (kbd/51.png, kbd/67.png).

## Rejected: show-in-table-lists-its-rows, no-raw-text-on-app-rows, spoken-once, disabled-looks-disabled, assistant-door

- Regression (disabled-looks-disabled). Routes: 'empty composer' and 'a question with nothing picked'. When keyboard focus lands on the grayed-out Send or Answer button, no focus ring shows. Before this change the buttons looked filled and showed the ring; now nothing on screen says where focus is, which fails WCAG 2.4.7. The screen-reader read confirms focus is there: 'focus: button "Send" disabled' and 'focus: button "Answer" disabled'. Cause: compact-mantine/src/theme/css/buttons.css.ts. The disabled rule `.cm-button:is(:disabled,[data-disabled]):not([data-loading])` (specificity 0,3,0) sets outline-color transparent, and it outranks the focus rule `.cm-button:is(:focus-visible,[data-state=focus])` (0,2,0). ActionIcon already has the matching exception at line 178 ('A button disabled by aria-disabled stays in the tab order ... must not hide the focus ring'); the plain button has none. The fix belongs in compact-mantine and touches its Figma lock. Screenshots: design/ui/studio/tmp/t6r2-recheck-show-in-table-lists-its-rows/sr-spoken/53.png (Send focused, tooltip shows, no ring; compare Talk's ring in 52.png), sr-spoken/61.png (Answer focused, no ring; compare the radio's ring in 62.png).
