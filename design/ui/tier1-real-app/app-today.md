# The graphty app today, measured against the tier 1 path

What the graphty app on master (commit 8a48b2f71) does for each step of a first-time user's
core path, how far its shell is from the refined structure B design, and which of its code the
design replaces. Paths are relative to `graphty/src/` unless they start with a package name.
Findings come from reading the code and stories; no server was started.

The refined B design is
`design/ui/prototype/study/structure-comparison/structure-b-refined.md` on the
`ux-storyboards-mocks-and-study` worktree. "Section N" below means a section of that spec.

## 1. How the app is built today

- `App.tsx:17-33` renders one thing, `AppShell` (plus a `?demo` component gallery).
- `components/shell/AppShell.tsx` is 5,244 lines. Almost all of it is one component,
  `ShellFrame` (lines 960-5228), which holds every piece of shell state: load, runs, layers,
  selection, inspector content, drawer, overlays, palette. `bindings.ts` (1,114 lines),
  `constants.ts` (835) and `types.ts` (774) support it.
- `components/Graphty.tsx` wraps `<graphty-element>` and hands the shell the element and its
  `GraphSession`. All graph changes go through `session` (transactions, `styles`, `runs`,
  `selection`, `layout`, `data`), which matches the project rule that the element owns graph
  logic. Earlier app-side graph code (component counting, metric math, cost models, legend
  math) has already been moved into the element; the file headers of
  `shell/analysis/graphShape.ts`, `metricCost.ts`, `nodeMetrics.ts` and
  `canvas/legendChannels.ts` record what moved.
- Shell regions on screen: a top bar (`topbar/TopBar.tsx`), an activity rail with six places
  -- Data, Explore, Analyze, Style, Present, AI -- plus Help and Settings
  (`shell/types.ts:22`, `AppShell.tsx:345-352`), a left panel per place (`shell/panel/*`), the
  canvas with overlays (legend, insights strip, minimap, time slider, welcome state), a bottom
  canvas toolbar (`toolbar/CanvasToolbar.tsx`), a bottom table drawer
  (`canvas/DataTableDrawer.tsx`), a right inspector (`inspector/*`), a status bar
  (`statusbar/*`) and a command palette (`CommandPalette.tsx`).
- Deployment: `.github/workflows/deploy-pages.yml:3-7` already publishes `graphty/dist` at the
  root of graphty.app (`tools/assemble-pages-site.sh:12,44`), but it runs after every green CI
  on master, not after a release.

## 4. Code the design makes obsolete

Each item is replaced by a different structure in refined B; "obsolete" means the tier 1 build
does not need it, not that it is wrong today.

- **Rail places and their panels**: `panel/ExplorePanel.tsx`, `panel/AnalyzePanel.tsx`
  (Suggested cards, Results tab, All statistics, Metric histograms, History, Recipes, More),
  `panel/StylePanel.tsx`, `panel/PresentPanel.tsx`, `panel/ActivityPanel.tsx`, and
  `layout/LeftSidebar.tsx` (replaced by the paint tree). `panel/AiPanel.tsx` becomes the later
  Assistant place.
- **Result cards**: `inspector/ResultInspector.tsx`, the `activeResult` state and
  `runNodeMetricCard`/`runFindGroups` card plumbing in `AppShell.tsx` (2704-3130),
  `readings/*` sentences built for cards. Runs become tree rows read on their Data tab.
- **Inspector bodies outside tier 1**: `inspector/PatternMatchInspector.tsx`,
  `inspector/CleaningStepInspector.tsx`, `inspector/PinnedCard.tsx`, the node verb list in
  `inspector/NodeInspector.tsx:254-292` (most entries are unwired), `inspector/InspectorActions.tsx`.
- **Canvas overlays the design drops**: `canvas/InsightsStrip.tsx` and `insights/*` (the
  design suggests nothing on load), `canvas/Minimap.tsx` (a placeholder drawing; the design
  drops the minimap until the element has one), `canvas/FilterStatusStrip.tsx` (the header's
  filter chip replaces it).
- **Status bar**: all of `statusbar/*` (loading becomes a state card, layout state becomes the
  toolbar's Layout button, counts move to the inspector).
- **Top bar pieces**: `topbar/HistoryPopover.tsx`, `historyRows.ts`, `useSessionHistory.ts`
  (version history becomes a full-canvas mode, not tier 1), Share and Compare buttons.
- **Load-time opinions**: the top-degree label layer and its budget
  (`defaults/styleDescriptors.ts:80-94`, `defaults/loadDefaults.ts`, `AppShell.tsx:2120-2147`),
  the first-load switch to Explore (`AppShell.tsx:1934-1938`), the suggested-card-on-sample
  route (`AppShell.tsx:2152-2158`).
- **Modals the design folds into other surfaces**: `LoadDataModal.tsx` (Data page),
  `RunAlgorithmModal.tsx` (Analyze popover), `RunLayoutsModal.tsx` (graph inspector's Layout
  section), `options/OptionsForm.tsx` if the "All options..." popover is built from the
  element's schema directly.
- **"Coming" tags**: `ComingTag.tsx` and its re-exports. The design hides needs-graphty-element
  items in the user-test build (section 2.5) instead of drawing them disabled.
- **App-side derivations the element already answers**: `neighborsOf` in `AppShell.tsx:3818-3855`
  (use the selection target `{ neighborsOf }`); `edgeEndpoints` in `analysis/graphShape.ts` once
  the element publishes neighbor rows with their edge values.

Kept or adapted: `Graphty.tsx`, `canvas/Legend.tsx` and `legendChannels.ts`,
`canvas/DataTableDrawer.tsx`, `CommandPalette.tsx` and `bindings.ts`, `utils/channelControls.ts`
(already built from the element's `CHANNEL_DESCRIPTORS`, the input the design's Style tab needs),
`sidebar/controls/*` compact controls, `analysis/metricCost.ts` (reads the element's estimate),
`data/sampleManifest.ts`, the load transaction in `loadDataset` minus its label layer.

## 5. graphty-element gaps the tier 1 path hits

- **Whole-project document** (save and reopen, task 10): runs, results, style layers, sets,
  notes, positions, camera and views in one document the element writes and reads. Without it
  the app would assemble a project file from five element calls and its own glue, which is the
  kind of workaround the project rules forbid. Recorded in `element-requirements-5.md:174`.
- **Field list metadata for binding** (tasks 5 and 6): which attributes suit a property
  (`AttributeDescriptor.domainKind`, `element-requirements-5.md` section 7) so the bind list can
  disable unsuitable fields with a reason.
- **Neighbor list with tie values** (task 8b): the design lists "Valjean, 17 shared chapters";
  the element's neighborhood selection gives ids, not neighbor rows with the connecting edge's
  weight.

Everything else tier 1 needs exists in the element today and is unused or under-used by the app:
`styles.encode` (bind to a field or result), `exportGraph` (CSV with results),
`selection.apply({ neighborsOf })`, `captureScreenshot` presets and `canCaptureScreenshot`,
`styles.legend()`, `session.layout`.
