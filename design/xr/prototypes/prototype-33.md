**Prototype 33: Verb, Count, Scope** -- A vi-like grammar for graphs: flick a verb, optionally give a count, then flick a scope (this node, its neighbors, its community, the path, the selection, a stored set, the top of a result, everything) -- or point at an object first and flick one of its own verbs; one button repeats the last whole command on a new target, and lettered registers hold sets, views, option presets, values and recorded recipes.

**Setup.** Fixed environment: solid colored background in full VR, the graph floating at chest height about 75 cm away. Devices: Meta Quest 3 / 3S and Samsung Galaxy XR with controllers (the primary mapping); hands only on any of them and on Apple Vision Pro (a full second mapping, below); PS VR2 Sense controllers on Vision Pro where Safari exposes them. Eyes are used only on Vision Pro, where look-and-pinch aims "this". Voice is optional and only types into an open text field. A paired Bluetooth keyboard, where the browser passes its keys into the session, types the same grammar key for key, as in vim. The dominant hand is the right hand here; everything mirrors for left-handed people. Every panel is fixed in space around the graph, not on the body, so no arm has to stay raised to read: the echo line just below the graph, the registers panel to its left, the options sheet and tables to its right. With controllers, forearms can rest on a lap or armrests; only "this" needs aiming. Nothing else is in view.

Every verb is "picked, then waits for a scope", except the few that need no target (save, settings, help, stop a recording, play and pause of time), which run when picked; their ring label ends with a period to say so. Some verbs always stop on an amber echo and wait for one more trigger on the echo, showing what will change: delete, remove run (with its dependent layers counted), clear, merge, playing a recipe, and any verb that changes more than a set number of elements (500 by default, a setting).

**One hand, seated and other needs.** A one-hand setting puts both rings on the one stick in turn (verb, then scope; the echo names which ring is live), keeps A as Repeat and B as close, moves take back to the stick click, steps the number by pointing at the count chip on the echo and dragging, and scales the graph with the grip held and the stick pushed up or down. Everything is reachable seated: the graph and panels sit within 30 degrees of straight ahead and nothing needs a step or a turn. Ring sectors are 45 degrees wide, which tolerates tremor; the ray snaps to the nearest node within 2 degrees. "Reduce motion" turns frame and go into a fade instead of a glide.

### The grammar

| Part                | Where it comes from                                                                                 | Examples                                                             |
| ------------------- | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| Verb                | Verb ring, Search, or the object page after a target                                                | select, filter, color by, PageRank, Ring layout, note, compare       |
| Register (optional) | "this" on a slot in the registers panel while the verb is pending; `"` and a letter on the keyboard | `i` (a set), `p` (a tuned Katz), `v` (a value 0.070), `q` (a recipe) |
| Count (optional)    | The other stick's up / down while a word is held; digits                                            | 2 hops, top 10, 3 routes, 7 days, up 2 places                        |
| Scope (last)        | Trigger ("this") or scope ring                                                                      | neighbors, community, path, top, visible                             |

The verb decides what a named register is in its sentence: the destination (`store`, `mark`, `record`), the argument (a run or layout reads an option preset, `filter` reads a value or a saved rule, `play` reads a recipe), or, for a set, view or node, the target itself, which completes the command. So `union`, then "this" on slot `r`, then the scope "set s" reads "union r with s". With nothing pending, "this" on a slot opens that slot's object page instead.

Where a scope needs an anchor and the pointer is on empty space, the anchor is the selection; with nothing selected, it is the latest node mark (neighbors, path), or the count picks the Nth largest (community, component). A scope flick that starts on a register slot or a table row anchors on that set or element.

### The scope ring (dominant stick)

| Direction  | Scope     | Count means                                                      | Anchor                                                                                                                                                                         |

| up-right   | community | the Nth largest group, with no anchor                            | a node's group in the latest group result (the sheet picks another result)                                                                                                     |
| right      | component | the Nth largest component, with no anchor                        | a node, or the selection                                                                                                                                                       |
| down-right | path      | k routes (default 1)                                             | from the anchor (or the second-latest node mark) to the latest node mark                                                                                                       |
| down       | selection | --                                                               | none                                                                                                                                                                           |
| down-left  | set       | --                                                               | a second flick: the 5 most recent registers, "all" (everything, including hidden and filtered), "region" (a lasso drawn with the ray while the trigger is held), and the panel |

Scopes are type-checked: a verb shows only the scopes it accepts at full brightness, and the others are dim and do nothing. A verb that takes an attribute paints, filters or reads edges when the attribute is an edge attribute, so the same scopes serve edges.

### The options sheet

Opened by "this" on the echo, for the pending command or the last one; opening it for the last one makes that command pending again on the same scope, so A (Repeat) runs it again with the new values and keeps both runs. It is generated from the descriptor of whatever the verb is (an algorithm, a layout, a style property, a reader, a writer): one row per option, advanced options folded, a Reset row at the bottom.

| Option kind                  | Row                                      | How you set it                                                                                                                        |
| ---------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Number with range and step   | value with detents                       | point at the row; the off stick's up / down step it by its step (hands: pinch-drag along the row); "this" on the value opens a keypad |
| Logarithmic (1e-4 to 1e-10)  | decades                                  | the off stick steps the exponent; "this" on the mantissa sets it on the keypad                                                        |
| Attribute                    | a list of columns of the right kind only | "this" on one; a long list pages with X / Y                                                                                           |
| Node (source, target, focus) | an empty slot                            | "this" on a node in the graph, a mark or a Find result                                                                                |
| Choice of a few              | a row of chips                           | "this" on one                                                                                                                         |
| Toggle                       | a switch                                 | "this"                                                                                                                                |
| Text                         | a field                                  | paired keyboard, system keyboard or dictation, or a suggested value                                                                   |

The sheet's Store row, with a register named, keeps the sheet's current values there as a preset.

### The journey

1. **Enter.**
    - **What you do:** On graphty's 2D page, open the Florentine families sample and choose Enter VR. Put the headset on, controllers in hand.
    - **What you see:** 16 families floating at chest height, labels on all of them at this size. Just below the graph the empty echo line reads "Ready. Trigger: point at a thing. Left stick: verbs. Right stick: scopes." That hint disappears after the first command you finish. (Entering with no data, the space where the graph would be shows a start card of samples and recent projects; the trigger on one opens it.)
    - **Controls:** none.

2. **Get oriented.**
    - **What you do:** Hold the right grip and turn the graph a little; let go. Flick the left stick up (Look), hold it a moment the first time so the ring labels show, then flick up again (inspect). Point at empty space and pull the trigger ("this" = the graph). Then open the Registers group (left stick right), flick down-right (mark), and pull the trigger on empty space again ("this" = the graph, so the mark keeps the view; with no register named it takes the first free letter, a).
    - **What you see:** The echo reads "Inspect" and waits; the scope ring on the right controller lights the scopes inspect accepts. After the trigger, the graph card reads "16 families, 20 marriages, 2 pieces (Pucci has no marriages), undirected, density 0.167". The mark puts slot "a: view, Florentine families, whole graph" in the registers panel.
    - **Controls:** dominant grip (hold the graph), off stick flick twice (verb), trigger ("this" on empty space = the graph), off stick flick twice and trigger (mark the view into the first free register).

3. **Find the Medici.**
    - **What you do:** Flick Look, then find. Type "Med" on the paired keyboard, or on the letter keypad that opens beside the echo. Pull the trigger on the first result, "Medici". Then flick Registers, mark, and pull the trigger on Medici.
    - **What you see:** The echo reads "Find Med: 1 result". The trigger frames Medici and leaves the pointer on it. The mark suggests "m" (the initial of the name) and stores "m: node, Medici". In a 16-node graph you could also just point at the label; Find matters at larger sizes.
    - **Controls:** off stick flicks, keypad or keyboard, trigger, off stick flicks and trigger.

4. **Who they married into.**
    - **What you do:** With the pointer on Medici, flick Select, then select. Push the right stick up (neighbors) and hold it. Push the left stick up once to see what 2 hops would be, down once to come back to 1, and let the right stick go. Then flick Registers, store; click the left stick to open the registers panel and pull the trigger on slot i (for in-laws); flick the right stick down (selection). Without naming a slot, store would take the first free letter, b.
    - **What you see:** While held, the echo reads "Select neighbors of Medici: 7 families, 7 marriages" and the ghost outlines Acciaiuoli, Albizzi, Barbadori, Ridolfi, Salviati and Tornabuoni with Medici. After the left stick's up, it reads "Select 2 neighbors of Medici: 12 families, 14 marriages"; after down, back to 1. On release the seven are selected. With slot i named, the echo reads "Store selection into i", the panel shows "i: set, 7 families (frozen)", and Registers, edit can label it "in-laws".
    - **Controls:** off stick flicks (verb), dominant stick flick held (scope, ghost), off stick up / down while held (count), release (commit), off stick click and trigger (name a register), dominant stick flick (store selection).

5. **Who matters most (PageRank).**
    - **What you do:** Flick the left stick left (Analyze). The ring shows page 1, Recent and suggested; PageRank is there, marked as suggested. Flick toward it. Then flick the right stick up-left (visible, which is the whole graph here).
    - **What you see:** The echo reads "PageRank on 16 families, under 1 s" while the scope flick is held. On release the run appears as row 1 under Runs in the registers panel, "1: PageRank, visible, damping 0.85", and a small ranked list of the top three stands beside it. (Without the suggestion, X twice pages to Centrality, where PageRank always sits in the same sector; Y from page 1 opens Search, where "pager" finds it.)
    - **Controls:** off stick flicks (Analyze, PageRank), dominant stick flick (scope).

6. **Read the result.**
    - **What you do:** Pull the trigger on run 1's row in the registers panel; its object page opens on the left stick. Flick up (read).
    - **What you see:** A 16-row table to the right of the graph: Medici 0.145, Guadagni 0.098, Strozzi 0.088, Albizzi 0.079, Tornabuoni 0.071, Ridolfi 0.069, Castellani 0.069, Bischeri 0.068, Peruzzi 0.067, Salviati 0.061, Barbadori 0.050, Pazzi 0.036, Ginori 0.032, Lamberteschi 0.031, Acciaiuoli 0.030, Pucci 0.010, with a histogram chip beside the title. Pointing at a row lights that family in the graph; "this" on a row frames it. B closes the table.
    - **Controls:** trigger ("this" = the run, target first), one off stick flick (read), B (close).

7. **Color and size by PageRank.**
    - **What you do:** Flick Paint, color by, then flick the right stick up-left (visible). Flick Paint, size by, and flick visible again (Repeat would only repeat the color). To change the size range, pull the trigger on the echo before the scope flick, point at the range row and push the left stick up twice.
    - **What you see:** "Color visible by PageRank (latest result), sequential" while held; the verb takes the latest result field by default, and the sheet can pick any other attribute. Then "Size visible by PageRank, 1x to 3x". Two new rows appear under Layers: "1: color by PageRank", "2: size by PageRank", and a legend appears next to the graph.
    - **Controls:** off stick flicks (verb), dominant stick flick (scope); trigger on the echo and off stick steps for a one-off range.

8. **Keep only strong families (filter).**
    - **What you do:** Flick Filter, filter. Push the right stick left (top) and hold it; push the left stick down five times from the default of 10 (or hold it down to ramp) until the echo shows 5; let go.
    - **What you see:** While held: "Keep top 5 by PageRank (at least 0.071): 5 of 16 families, 4 marriages". On release, Medici, Guadagni, Strozzi, Albizzi and Tornabuoni remain (Strozzi now has no visible ties), and row "1: top 5 PageRank" appears under Filter steps. The graph card reads "Showing 5 of 16". To filter by a value instead, name a value register holding 0.070 before the same scope.
    - **Controls:** off stick flicks, dominant stick flick held with off stick steps (count), release.

9. **Write a note (object first).**
    - **What you do:** Point at Medici and pull the trigger: the echo reads "Medici" and the left ring opens on the node's page. Flick down-left (note). Type "Married into six families; the hub of the network." on the paired keyboard, or the system keyboard, or dictate where the browser allows it. Pull the trigger on Done.
    - **What you see:** A note card beside Medici with your text, then a small marker on the node and row "1: Medici" under Notes.
    - **Controls:** trigger ("this", target first), one off stick flick (verb), keyboard or dictation, trigger.

10. **Undo a mistake.**
    - **What you do:** You decide to hide Strozzi, who now sits alone. Flick Filter, hide, and pull the trigger, but the pointer had slid onto Guadagni beside it, and you let go before reading the ghost. Guadagni disappears. Tap the left trigger. Then put the pointer on Strozzi and press A (Repeat).
    - **What you see:** While the trigger was held the echo showed "Hide Guadagni"; after the left trigger tap it reads "Undid: Hide Guadagni" and Guadagni is back. Repeat reads "Hide Strozzi" and hides him: Repeat still knows the last command after an undo. The undone hide is not lost: holding the left trigger and flicking the left stick up would switch to that branch and replay it as a new step.
    - **Controls:** off trigger tap (take back), A (Repeat), off trigger held with off stick (undo tree).

11. **Save.**
    - **What you do:** Flick Project, save. (Its label ends with a period: it runs as soon as it is picked.)
    - **What you see:** "Saved Florentine families". The registers, marks, runs, layers, filter steps, notes and history are saved with the project.
    - **Controls:** off stick flicks.

With hands only, every step is the same sentence: off-hand pinch-drag strokes for the verb, a dominant pinch-drag stroke starting on the anchor for the scope, the off hand's pinch-drag up or down while the scope stroke is held for the count (step 8: five steps down), a dominant pinch for "this", the take back chip at the left end of the echo (or a thumb-to-middle pinch), an off-hand double pinch to Repeat, and fists to hold the graph.

### Advanced journeys

- **Compound rule.** "type is account AND (degree above 20 OR risk_score at least 0.8) AND created in the last 30 days": Filter, where opens the rule sheet, generated like the options sheet: one row per clause (attribute from a list of the right kind, comparison chips including "in the last N days", value on the keypad or by "this" on a node to take its value), an "any of" row to nest the OR, a NOT chip per row, and a live count. Save as filter with slot `f` named keeps it. A week later, "this" on slot `f` opens its page; flick filter to apply it to the visible graph, or edit to open the same rule. The plain grammar alone builds AND (each filter is a step) and OR (union two stored sets), but a nested rule needs the sheet.
- **Tuning algorithm options.** Pull the trigger on the echo after picking Katz: its 7 options are rows; tolerance is a decades row (the off stick down four times, from 1e-2 to 1e-6), the weight attribute a list of numeric columns. The sheet's Store row with `p` named keeps them; later, flick Katz, "this" on slot `p`, flick a scope. For a resolution sweep of communities (0.5, 1.0, 1.5, 2.0): run Louvain with resolution 0.5, then three times: trigger on the echo (the last command is pending again), point at the resolution row, off stick up once (step 0.5), A. Every run is kept as its own row.
- **Comparing two runs.** "this" on run 3's row, flick compare, then "this" on run 4 (the echo waits for the second: "Compare run 3 Louvain 1.0 with ..."). A table reads "4 groups and 5 groups; 3 families changed group", rows per family that moved. Split opens a second, synchronized view of the same graph colored by the other run; "this" on a node in either view selects it in both, and inspect shows its values side by side. Repeat on another pair of rows compares them.
- **Layers on subsets.** Paint, color by, then the scope "set" and its second flick to `i`: a layer that paints only those seven. "this" on a layer row, raise, with the count stepped to 2 while the flick is held, moves it up two places; toggle on the same page hides the layer.
- **Recipes.** Registers, record, "this" on slot `q`: the echo shows a red "recording q". Every command you finish is captured as its sentence, with scopes kept as relations (neighbors of the anchor, top 5 of the latest run, the set in `i`), not as node ids. Registers, stop. ends it. A recipe can also be made after the fact: "this" on a row of the History list, store as recipe from here, and the echo offers "Store steps 4 to 19 into r?" with each step toggled off by "this" on it. On another graph, "this" on slot `q`, play: the amber echo reads "Recipe q: 6 steps, needs 1 start node; point and pull the trigger", then runs them as named steps, each undoable. A step whose attribute is missing pauses with the options sheet open on that slot, so you map it.
- **Computed score.** Analyze, Results, compute opens a formula sheet: function chips (mean, sum, difference, ratio, rank, normalize, log), rows that take columns from the attribute list, and a name row that suggests "score 1" or takes a typed name. "Mean of normalized rank of degree, betweenness, closeness, eigenvector" is four column picks and two chips, no keyboard. The result is a run row like any other, so top, paint and read work on it.
- **Joining tables and importing data.** Project, open lists recent projects, samples and "from laptop", which shows a short code to type on graphty's 2D page so the file is sent to the headset session (planned; today the headset's own file picker opens its downloads). Import mapping is the options sheet of the reader: one row per column with role chips (id, source, target, attribute, skip) and kind chips, paged with X / Y. Project, add data opens the join sheet: the file, the key column, "as a second network" or "join onto nodes", and the match count ("412 of 450 rows matched"). With 25 columns this works; with 40 the 2D page is quicker, and the sheet says so.

### How a new feature plugs in

- **A new algorithm with options.** Its descriptor (plain name, technical name, family, options, result fields) places it in the next free sector of its family's page, or on a new page of that family; Search finds it by either name. Its options sheet is generated row by row from the option kinds, so "set the third option of an algorithm a plugin added last week" is: pick it (Search if you do not know its page), trigger on the echo, point at row 3, step it with the off stick or open the keypad. Its scopes are whatever its inputs type-check to (a node input takes "this"; two node inputs take the path scope; a set input takes set, selection or community).
- **A new layout.** A verb on Layout's next page; the scope says what it lays out; its options sheet is generated; stored layout presets work by letter.
- **A new object type.** It declares which verbs apply (from the existing verb list) in the order its object page should show them, and appears as a numbered list in the registers panel, so "this" can point at its rows and open its page. If it has members (a time slice, a group of groups), it can be used as a scope by starting a scope flick on its row, or from the panel through the "set" sector. No new ring direction is spent.
- **A third-party plugin of several kinds.** The "Biology: enrichment" family with 4 algorithms becomes one Analyze page; its gene-list input is a set scope (a stored set or the selection) or a text value register typed on the 2D page; its two number options are rows on its sheet; its result reads with the generic table and histogram.
- **The limit.** Rings stay at 8 by 8 per page, so the catalog grows by pages: past about 4 pages in a group, paging with X / Y is slower than Search, which is one Y away from any page 1. The grammar is the second limit: anything that is not "verb a target" (drawing a pattern, laying out a report) has no good sentence and goes to a sheet or the 2D page. Scopes can only be added with care: the scope ring has no free sector, so new scopes are reached by starting a flick on their row, or through the "set" sector.

### Why it should work

- vi's grammar of operator, count and motion (Bill Joy, vi, 1976) and Vim's text objects, dot repeat and registers (Bram Moolenaar, Vim, 1991) have let people edit text at high speed for fifty years with a small vocabulary that composes; Vim's visual mode lets the same people select first and apply an operator after, which is the target-first order here; Vim 7.0 (2006) added the branching undo tree used here.
- Kakoune (Maxime Coste, 2011) inverted the order to selection first and found it easier to learn because you see the target before acting; this scheme offers both orders, keeps verb first for Repeat on new targets, and borrows Kakoune's lesson twice: target first for beginners, and the ghost preview of the target before the last word commits.
- Marking menus (Kurtenbach and Buxton, "The limits of expert performance using hierarchic marking menus", CHI 1993) showed that experts select by direction without looking, with good accuracy at breadth 8 and depth 2; multi-stroke marking menus (Zhao and Balakrishnan, UIST 2004) keep accuracy at greater depth by lifting between strokes, which is what one flick per level does. Pie menus in VR (Gebhardt and colleagues, "Extended pie menus for immersive virtual environments", IEEE TVCG 2013) carried this into headsets.
- Finger-count menus were fast and accurate in 3D gesture studies (Kulshreshth and LaViola, "Exploring the usefulness of finger-based 3D gesture menu selection", CHI 2014); here they are an expert shortcut, raised deliberately, with a drag as the default count.
- Repeat with adjustable options is shipped: Blender's Repeat Last (Shift-R) and its Adjust Last Operation panel are the same pair as Repeat and the options sheet opened from the echo.
- Recorded macros as user-made commands are long shipped: Emacs keyboard macros, Vim's `q` registers, Photoshop Actions. Storing them with relative scopes is how Vim macros survive on new text.
- Controller radial menus on a stick are a mass-market control in games (weapon wheels), so the flick itself needs no teaching, only its contents.
- Our own catalog (design/xr/vr-control-surface-catalog.md, operator, count, scope) rated this expert-fast without voice or text and noted its weaknesses: a steep start and attribute-valued commands still needing a list. Target first, the hesitation labels, the echo and the generated sheet answer both.

### What it would teach us

- Can people who have never used vim learn a verb-then-scope grammar in a headset, and how long until they stop hesitating on the rings?
- Which order do people choose -- target first or verb first -- and does the choice change as they gain speed?
- Is Repeat used, and how much work does it save on real tasks compared with re-picking a command?
- Do lettered registers help or intimidate? Do people rename them, rely on suggested letters, or avoid them?
- How accurate are 8-way stick flicks and pinch-drag strokes in a headset, at two levels, with and without looking?
- Is "the other stick steps the number while a word is held" learnable, or do people reach for the keypad?
- Do people understand and use the undo tree's branches, or only linear undo?
- Do relational scopes make recipes replay correctly on new data, and how often does a replay need a step mapped by hand?
- How many acts does each of the six stress journeys take, compared with the desktop app's clicks?

### Known risks

- **A steep start.** A grammar is invisible until learned. Mitigation: target first needs only the trigger and one flick on a page of that object's verbs; rings label themselves after a hesitation; the echo spells every half-built command in words and shows the ghost before the last word commits; verb groups have plain names; the tour builds five whole sentences; help shows both rings and every object page.
- **Two orders, one stick.** With a target pending, the left stick picks from the object page; with nothing pending, it picks a group. Mitigation: the echo always starts with the pending words ("Medici ..." or "Select ..."), the ring draws the object's name in its center, and take back clears either.
- **Mode errors from a half-built command.** A pending verb waits for its scope; a stray flick completes it. Mitigation: every completing word commits on release with its ghost shown while held; take back cancels a held word or drops the pending one; amber confirm for destructive verbs and above the change threshold.
- **Repeat on the wrong target.** Mitigation: Repeat commits on the release of A, aimed at what the pointer is on then, with the ghost shown while A is held; one take back undoes it, naming it.
- **Letters mean nothing.** "Register q" is jargon. Mitigation: every slot shows a label and a summary, letters are suggested (initials, then the first free), the panel can be sorted by kind, and a slot opens its own page of verbs; experts use letters, others point at the slot.
- **The number chord is unfamiliar.** Holding one stick while stepping the other is a two-thumb chord. Mitigation: it is the only chord, it has one meaning (step the number), the echo shows the number live, and the keypad on the echo's count is always there.
- **Finger counts misread.** A relaxed hand looks like two fingers. Mitigation: counts by fingers are an expert option read only from a raised hand, palm toward the graph, held still 300 ms; the default count is a drag.
- **Off-hand strokes near the system gesture.** A palm toward the face triggers the system menu. Mitigation: off-hand strokes are recognized only palm down or sideways; the tour teaches the posture.
- **Pointing "this" in a dense graph.** The scheme still needs one anchor. Mitigation: anchors can be marks, Find results, table rows or the selection instead of the node; a snapping ray; scopes reach many nodes from one easy anchor.
- **Text entry.** Names, notes, search strings. Mitigation: suggested names, keypad for ids, paired keyboard where the browser passes keys, dictation where it exists, value registers filled on the 2D page, long text on the 2D page.
- **Rings run out of room.** Eight scopes and eight groups are fixed. Mitigation: new verbs go to pages and Search, new scopes are reached from their rows; positions never shuffle so learned flicks stay valid.
- **Two mappings drift apart.** Controllers and hands may behave differently. Mitigation: one grammar, one echo, the same ring layouts and object pages; only the input that produces each word differs, and both are tested on every journey.
