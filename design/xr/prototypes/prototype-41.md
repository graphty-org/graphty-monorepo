**Prototype 41: Facet Browser** -- Every attribute and every computed result is a facet listing its values with counts, beside relational facets ("within k hops of", "on a route from A to B"); tapping values narrows one query whose role (Select, Filter or Highlight) is a switch, and you move through the network by pivoting the query to neighbors.

**Cards.** A card names its object and lists every facet value it has, each tappable: tapping one adds it to the query like a value in the rail ("Piece 1" on Medici's card next to "Connections at least 3" gives both); "Start a new query from this" is a labeled verb on the card, which sends the old query behind the back arrow. A node card adds Add to query, More like this, Neighbors, Move, Pin, Note, Copy, Why this look, Suppose gone, Hide (after a divider), and a list of its edges, each opening the edge's card. A group value has a card too: point at a value and tap its "i", or tap its row in the group table; it carries Note, Label, Keep as set and the value's profile (size, density, top members by each amount, attribute mix). A card with "Keep open" stays while a second card opens beside it, for comparing two elements. With several matches, Step through shows one card at a time with previous and next, framing each.

**Comparisons and peeks are views, not steps.** Compare with, Split views by and a count peek open or change what you look at and never enter the Undo list; closing them is free. So Undo after "Re-run with, then Compare with" takes back the run's paint, not the comparison.

**Destructive and wide steps preview first.** Remove, Merge, Delete (a set, layer, result, filter, saved view or note), Reset styles and Collapse show what they will change, with counts ("Remove 6 families and 9 marriages?"), and wait for Confirm. Hide, Pin these and Move of one node do not ask, because each is one named step that Undo takes back; Hide and Pin these on more than 20 elements, or on the whole graph, preview with counts first ("Pin all 214 nodes?").

**Nodes and edges in one query.** The query has a node part and an edge part, and the Nodes / Edges switch shows one at a time; switching never drops chips. On the Edges side the node part appears as one automatic chip, "Both ends in [node chips]", which you can change to "Touches [node chips]" or remove; on the Nodes side the edge part appears as "Has an edge in [edge chips]". So an edge time window and node rules combine, and a live Hide others on nodes stays live when you switch sides. The role acts on the side you are looking at: Hide others on the Edges side hides the other edges and, with them, nodes left with no shown edge only if you tick "and their lonely nodes".

**Filling a slot with "these".** A relational slot filled by "these" (Within 2 hops of [these], On a route from [these] to ...) takes the chips that made "these" into itself, as Pivot does, and the bar says so: "Within 2 hops of [Name is ACC-48213]". It never ANDs with the chips it absorbed. A relational facet with two anchors gives OR by default, like any facet; "All of" in its chip editor gives AND ("Within 1 hop of all of [Medici], [Strozzi]": the common in-laws).

**For each value.** On any group facet header (communities, categories, sets), For each value applies one verb once per value: Note or Label (typed per row in the group table, or "the top value of [facet]" for every row at once), Keep as set, Run on these, Lay out these, Paint these, Export, and every verb in the More list that a descriptor declares for a set of nodes (a plugin's "Enrich this set" included). Run on these with a node-level algorithm writes one combined result facet, not one per group ("Degree within MCL community": each node's value computed inside its own group), with one History step and one Methods line. A preview lists every value with what will happen to it ("12 communities of 4 or more: 12 labels, from the top GO-slim term"), you edit any row, then Confirm; it is recorded as one step ("For each community of MCL (inflation 2.5): Label by top GO-slim term"), undone as one. Step through on a group facet walks its values one at a time, replacing the chip each time, so profiling cluster 3 never ORs it with cluster 2; the whole walk is one entry on the query arrows.

### The query is recorded with every step

Query edits stay off the Undo list, but a query that was used is never thrown away:

- **Every project step stores its scope**: the exact chips, the role and the kept filters that were on when it ran. Its History name shows them, the changed option first: "Run Louvain, resolution 1.0 -- on 214 accounts: Within 2 hops of [ACC-48213] via shared device, shared phone; has an edge created Sep 3 to Oct 3, 2026". Tapping a step's scope puts those chips back on the bar.
- **The Methods view prints each run's scope** beside its options, with every window as dates, so a methods paragraph can be written from the headset and read a year later ("Louvain, resolution 1.0, on the 214 accounts within 2 hops of ACC-48213 via shared device or shared phone, with a shared-device or shared-phone edge created Sep 3 to Oct 3, 2026").
- **A recipe replays the recorded chips, never whatever is on the bar at replay.** When you save a recipe, every node anchor in its chips, every group value it picked and every time window it used becomes an input with its own label: "Flagged account: [ ]", "Which community: [ ]", "Window: [last 30 days of the data]". The inputs screen shows each window resolved against the new data with how much it covers ("Sep 1 to Oct 1, 2025 -- 1,204 accounts"), and every step's scope is shown beside the size it had when recorded ("Louvain: 6 accounts now, 214 when recorded -- Continue / Stop"), so a scope that shrank to a sliver is seen before it runs, not only one that is empty. A group value from a run inside the recipe is asked after that run, with the new run's values and counts shown, so you pick the community on the new data. Inputs a recipe cannot map are named before it starts, and nothing replays silently with an empty scope.
- **A saved view stores the query, the role, the camera and which kept filters are on.** It does not hold layers: going to a view never changes the Painted strip, so a Video touring several views keeps one palette. A view can carry a short list of layers to show or hide, each shown on the view's card and in its History name. Going to a view is a query edit (free, on the arrows) plus, if it changes which kept filters are on, one named step ("Go to view: Ring 7 close-up -- turns on Strong families").
- **Undoing a step that a query depends on** is named: "Undo: Run PageRank -- 1 live chip and 1 kept filter use it". After the Undo, chips that read the result turn gray, read "result undone", and match nothing until Redo or until you remove them; a kept filter that reads it is switched off and marked the same way. Take back only this lists dependent chips, kept filters, sets whose rule reads the result ("Strong in-laws: PageRank at least 0.070"), layers and saved views as well as later steps; a set whose rule is undone keeps its last members, frozen, and says "rule undone -- kept 5 members".

### What is kept is resolved

A recorded query only helps if it means the same thing next week. So anything that holds a query beyond the moment -- a step's recorded scope, a kept filter, a set, a saved view, a layer on a subset -- stores what the query resolved to, not just its words.

- **Time windows are dates.** The presets (last 7, 30, 90 days) count back from the newest time in that column of the data, never from today, and every time chip prints its dates: "Created last 30 days -- Sep 3 to Oct 3, 2026". Step back a week rewrites the dates on the chip ("Aug 27 to Sep 26, 2026 -- 30 days, 1 week back"). For live monitoring data, the chip's editor has "Count back from today"; the chip then reads "rolling: last 30 days from today" in words and in a dashed outline.
- **Keep stores the resolved values.** A kept filter, a saved view and a step's scope store their windows as dates. A set stores its member list beside its rule. Each has a Rolling switch on its card, off by default; with it on, the chip and card read "rolling" and the rule is re-evaluated on every load. A rule that reads a result names the run it read ("Community is 3 of Louvain, resolution 1.0"), never "the latest Louvain", so re-running does not move it.
- **Change is shown on reopen.** When a project opens, every rolling object whose members differ from when it was last kept says so on its chip and card: "Ring 7 (rolling): +4, -2 since Oct 3 -- Show changes / Keep as it was / Accept". Show changes puts the +4 and -2 on the bar as a query you can look at; Keep as it was freezes the old members; Accept takes the new ones as kept. A note, callout or layer on a changed object carries the same mark. A fixed set whose members left the data after a re-import says "2 kept members are no longer in the data".

### Relational facets search the whole graph

"Within k hops of", "On a route from [A] to [B]", all routes up to length L, flow and cut find their hops and paths in the whole graph -- less only kept filters switched to "filter what algorithms see" -- never inside the other live chips. The other chips do not decide which routes exist; they only mark them. The chip says so: "3 shortest routes in the whole graph -- 2 pass outside your other chips", and each route value lists its nodes with the ones outside the other chips marked "outside" (and lit faint in the graph, or named as hidden in Filter role). The route chip still ANDs with the others for membership, as every chip does, and "Start a new query from this" on it sends the other chips behind the back arrow when the route is the whole question. This is the one place where a facet is not computed inside the other chips: a route through a low-degree account that a Connections chip removed is still the shortest route, and must be shown as one.

### Live highlight and style layers

- **The live query draws through a highlight channel, not through style layers.** graphty-element gets one per-node and per-edge highlight state (bright, faded, hidden, outlined), written from a membership mask the facet worker computes and uploaded once per change. Brushing, pointing and stepping update the counts at once and the graph at most every 100 ms, so on a 10,000-node graph the lit nodes trail the count by at most a tenth of a second instead of stalling the frame. Pointing picks nodes through a spatial index over node positions, rebuilt when a layout settles, and only when the ray has moved.
- **What a count before release promises, by size.** Attribute facets (text, groups, amounts, times) count live while you brush or step at 10,000 nodes. Relational and route facets count live up to about 2,000 nodes; above that the stepper shows the last count with "counting..." and the new count about a second after release, and the bar says "counts after release" until it arrives. So the claim "12 families before you let go" holds for attributes at every size and for structure only on small and medium graphs.
- **The live role is a preview, never the published look.** Highlight's fade and Select's outline are like a hover: not saved in a picture, an export or a report as they are. Keep, as layer target, then Fade others or Outline these turns the live query into a real style layer in the Painted strip ("Fade: not Within 1 hop of Ring 7"), which presets, reorder, the legend and Why this look all see. Picture, Video and Report ask when a live highlight is on: "The live highlight is not a layer -- Keep it as a layer / Leave it out".

### The journey

1. **Enter.**
    - **What you do:** On graphty's 2D page, open the Florentine families sample and choose Enter VR. Put the headset on, sitting or standing.
    - **What you see:** The 16 families floating at chest height, labeled, with Pucci floating apart. The rail at your left shows three pinned facets: Name (16 values), Connections (computed on load, a histogram from 0 to 6) and Piece (2 pieces). The statistics strip reads "16 families, 20 marriages, 2 pieces, density 0.167". The bar reads "All 16 families -- Highlight" and a hint under it says "Tap a value to narrow".
    - **Controls:** none.

2. **Get oriented.**
    - **What you do:** Point along the Connections histogram, then tap the "Piece 2" chip in the Piece facet. Look at the graph, then tap the back arrow. Pinch on the graph and turn it a little.
    - **What you see:** Pointing at a bar reads its count and lights those families: "0 marriages: 1 family", "1: 4", "2: 2", "3: 6", "4: 2", "6: 1". Tapping Piece 2 lights Pucci and fades the rest; the bar reads "Piece is 2 -- 1 of 16" and every other facet recounts for Pucci alone (Connections: 0), while the Piece facet itself still shows "Piece 1: 15", so it could be added with OR. The back arrow returns to all 16 at once, with no undo step spent. The pinch holds the whole graph even when it starts on a family, so nothing is moved or pinned by turning it.
    - **Controls:** point (readout), tap a value, query back arrow, pinch and drag on the graph.

3. **Find the Medici.**
    - **What you do:** Tap "Medici" in the Name facet (with 16 values it is in the list; in a large graph you type or say "Med" in its field first).
    - **What you see:** The bar reads "Name is Medici -- 1 of 16"; Medici stays bright and the rest fade. With one match, the result-set bar shows Medici's card: "Medici -- Connections 6 -- Piece 1", each value tappable, and the verbs, headed "Medici:". Tapping the Medici node instead opens the same card without changing the query; its own verbs then act on Medici whatever the query is, and its Add to query puts "is Medici" on the bar.
    - **Controls:** tap a value (or tap a node), keyboard or voice optional.

4. **Who they married into.**
    - **What you do:** Tap Pivot to neighbors on the result-set bar.
    - **What you see:** The chip becomes "Neighbors of [Name is Medici]" and the bar reads "6 of 16 families": Acciaiuoli, Albizzi, Barbadori, Ridolfi, Salviati and Tornabuoni light; Medici dims. The facets recount for the six: Connections now shows 1 family at 1 (Acciaiuoli), 2 at 2, 3 at 3. The camera has not moved; Frame results would bring them to the middle. (For the in-laws with Medici, Within k hops of [Medici] at 1 reads "7 families, 7 marriages among them"; its stepper at 2 reads "12 families" before you let go.)
    - **Controls:** tap a verb (pivot); optionally a relational chip's stepper.

5. **Who matters most (PageRank).**
    - **What you do:** Tap Add facet at the top of the rail, under its search field; the catalog opens in front of you, between the rail and the graph. In the catalog, the Suggested row offers Influence (PageRank); tap it. The form shows Damping 0.85, Maximum iterations 100, Tolerance 1e-6, Weight (none), a Scope row "All 16 families / These 6 (Neighbors of [Name is Medici])" and a "Paint the result" switch (off for amounts); leave All and tap Compute.
    - **What you see:** A new facet "Influence (PageRank)" pins itself under the Painted strip as a histogram, with a progress ring and Cancel on its header for the moment it computes. The six in-laws' values are bright in it and the other ten faint, because the query still matches the six. The History list gains "Run PageRank on: all 16 families".
    - **Controls:** tap (Add facet, catalog entry, Compute); the generic options form.

6. **Read the result.**
    - **What you do:** Tap Clear on the bar. On the PageRank facet's header, choose Sort by value. Tap Table on the result-set bar.
    - **What you see:** The histogram becomes a ranked list: Medici 0.144, Guadagni 0.097, Strozzi 0.087, Albizzi 0.078, Tornabuoni 0.071, Ridolfi 0.069, Castellani 0.069, Bischeri 0.068, Peruzzi 0.067, Salviati 0.061, Barbadori 0.050 ... Pucci 0.010. Pointing at a row lights that family in the graph. The table opens at the right and lists all 16 with the pinned facets as columns (Name, Connections, Piece, PageRank). Describe on the header reads "PageRank, damping 0.85, all 16 families; Pucci has no ties, so its value is the share every family gets by chance".
    - **Controls:** tap (Clear, header menu, Table), point (readout).

7. **Color and size by PageRank.**
    - **What you do:** On the PageRank header, choose Paint by, then Color, and tap a sequential palette. Choose Paint by again, then Size, and drag the range handles to 1x and 3x.
    - **What you see:** The graph recolors light to dark by PageRank; sizes follow the handles live. Two layers appear in the Painted strip, "Color: PageRank" and "Size: PageRank", and a legend hangs under the Painted strip. History gains "Paint color by PageRank" and "Paint size by PageRank".
    - **Controls:** tap (header menu, palette), drag range handles.

8. **Keep only strong families (filter).**
    - **What you do:** On the ranked list's range strip, pinch the "at least" handle and drag it down to 0.070 (or tap the handle's field, marked with a keypad icon, and type 0.070). Tap Filter on the role switch. Then tap Keep, as filter, and accept the suggested name, or say "Strong families".
    - **What you see:** The handle stops with a detent in each gap between two families' values, and its readout names the edge: "at least 0.070 -- 5 of 16; Ridolfi and Castellani at 0.069 are out". One step further would read "7 of 16", so a hand that overshoots sees why the count jumped. In Filter role the other 11 vanish; the bar reads "PageRank at least 0.070 -- 5 of 16 families, 4 marriages -- 11 hidden". Medici, Guadagni, Strozzi, Albizzi and Tornabuoni remain, and Strozzi floats alone: none of its four marriages is to another strong family. After Keep, a gray "Within: Strong families" chip sits at the start of the bar, the live query is empty again, the role returns to Highlight, and every facet now counts only the five. History gains "Keep filter: Strong families (PageRank at least 0.070)".
    - **Controls:** drag a handle on the ranked list (or tap its field: keypad), tap the role switch, tap Keep, voice optional.

9. **Write a note.**
    - **What you do:** Tap the Medici node to open its card, tap Note, and dictate or type "Married into six families; the hub of the network." on the in-scene keyboard, which opens in front of you at the graph's height and offers completions from the data's own names and values. Tap Done.
    - **What you see:** A note card on the result-set bar with your text, a caret you can place by pointing, and its target, "Medici". When closed, a small note marker hangs on Medici, and a Notes facet appears in the rail ("Has a note: 1"), so notes can be found and narrowed like anything else.
    - **Controls:** tap a node, tap Note, keyboard or voice.

10. **Undo a mistake.**
    - **What you do:** With Medici's card open, you tap Hide, after the card's divider, instead of Note. Medici disappears ("Hide Medici: 1 family, 2 marriages hidden"); the hide is a filter step, listed under the Within chip. Tap the Undo button in the middle of the constraint bar's control row, just above the graph, which reads "Undo: Hide Medici" (or press B); the back arrow beside it reads "Back: Name is Medici", so the two are told apart in words.
    - **What you see:** Medici returns with its note intact and the Within list is back to one step; Redo now reads "Redo: Hide Medici". The query arrows would not have helped here, because hiding is a project change, not a query edit; the Undo button's label always says which step it will take back, so the two histories cannot be confused.
    - **Controls:** Undo button or B / Y.

11. **Save.**
    - **What you do:** Tap the Project tab at the right end of the constraint bar and tap Save; accept "Florentine families".
    - **What you see:** "Saved Florentine families -- 1 run, 2 layers, 1 filter, 1 note". The live query and its role are saved too, as where you were.
    - **Controls:** tap (Project tab, Save).

### Advanced journeys

- **Compound rule.** "type is account AND (degree above 20 OR risk_score at least 0.8) AND created in the last 30 days": tap "account" in the Type facet; brush Connections above 20; brush risk_score at 0.8 and drop that chip onto the Connections chip, which brackets them as OR (or open the risk_score chip and choose "Or with the chip before"); tap the "last 30 days" preset on the Created time facet. Switch to Filter, Keep as filter, name it. A week later, tap the gray Within chip, tap the filter in the list, and its chips come back into the bar for editing; Update replaces it in place. On Florentine: "Connections at least 3 AND (PageRank at least 0.080 OR Within 1 hop of [Medici])" gives Medici, Guadagni, Strozzi, Albizzi, Tornabuoni and Ridolfi. Nested brackets deeper than one level are workable but slow; the assistant can write them into the bar as dashed chips to accept.
- **Tuning algorithm options.** On the PageRank header, Re-run with ... opens the form prefilled. Set damping to 0.70 and Compute: a sibling facet "PageRank (damping 0.70)" appears beside the first and both stay. A number field accepts a list ("0.5, 1.0, 1.5, 2.0" for Louvain's resolution), which makes one sibling facet per value: a sweep in one act. Reset to defaults and Show advanced sit on the form.
- **Comparing two runs.** On one result facet, Compare with ... and tap the other: two amounts give a rank-change list ("5 families change rank: Ridolfi 6th to 8th, Castellani 7th to 6th, Bischeri 8th to 7th, Peruzzi 9th to 10th, Salviati 10th to 9th") and a scatter you can brush; two group results give a cross table you can tap cell by cell. Split views by on a run's header puts two synchronized views side by side; tapping a node in one lights it in both.
- **Layers on subsets.** Build the subset as a query (Within 1 hop of [Medici]), then Paint these on the result-set bar, or Paint by on a header with "Only these 7" chosen. A choice on the layer says whether it follows the rule (members change with the data) or keeps these members. Layers reorder by dragging in the Painted strip; each layer's card has edit, hide, rename, delete and Why this look.
- **Twelve scattered nodes.** Tap Picked in the Relational facets, then Pick nodes: the bar reads "Pick nodes: 0 picked -- Done, Cancel". Tap each node (pointing at a sub-degree target is still slow, about the 12 to 21 s per node studies report; a crowded tap opens the short list of nearby nodes rather than picking the wrong one, and typing names into the Name facet with OR is often faster), then Done: one "Picked: 12 nodes" chip, editable like any other. Keep as set names it.
- **Recipes.** In History, tap the steps to keep (Run PageRank, the two paints, Keep filter), then Save as recipe and accept the suggested name "PageRank triage". The recipe holds each step's recorded scope, not the bar: a step run "on: Within 1 hop of [Medici]" asks "Center family: [ ]" on replay, and a step that kept "Community is 3" of a run inside the recipe asks "Which community: [ ]" after that run, showing the new values and their counts. On another dataset, Project panel, Recipes, tap it: it lists its inputs first (a weight column, a center node, a community), each filled by a facet pick or a slot, then replays and reports what it made and on what ("made 1 set of 23 nodes from community 4, 1 layer, 1 filter"). An input it cannot fill stops the replay at that step with the reason; nothing runs on an empty scope.
- **Labeling every cluster.** On the MCL header, groups at least 4 (stepper), then For each value, Label. The preview lists the 12 communities as rows with size and mean logFC; "top value of [GO-slim]" fills every label at once, and any row can be retyped. Confirm: one step, "For each community of MCL (inflation 2.5): Label by top GO-slim term", 12 labels drawn on the graph, undone as one. Step through on the same header then walks the clusters one at a time, framing each and replacing the chip, to check the labels by eye.
- **Joining tables and importing data.** Project panel, Open, From laptop shows a six-letter code; on the laptop's graphty page, Send to headset, enter the code and drop the file. The pairing is a WebRTC data channel between the two pages, introduced by a small signaling endpoint that graphty has to host; it is a required build item, not an option. Until it exists, a file reaches the headset by URL or through Open, This headset's files: the session pauses, the headset browser's own file picker opens (files already on the headset, or a cloud drive the browser can open), and the session resumes where you were. The columns arrive at once as facets in a New data group with their inferred kinds, plus a Load issues facet; each header has Use as (node id / source / target / attribute / skip) and Type (text, group, amount, time). Read as on the New data header picks the format when it was not detected, with that reader's options form below. For a join (Add data), the New data header's Match rows by asks for its key column, then for the graph facet to match: the key facet then reads "16 of 16 rows matched", or for a real expression table "1,912 of 2,104 matched" with an Unmatched value you can tap to see the 192. Wide tables of 40 columns are workable: they arrive as 40 facets you scroll and search, not as a 40-column mapping grid.

### How a new feature plugs in

- **A new algorithm with options.** Its descriptor puts it in Add facet under its family (or a new family heading, e.g. "Biology: enrichment"), searchable by plain and technical name and listed in the A-Z tab. The options form is generated: numbers become steppers with keypad, choices become chips, attribute options become facet picks, node options become A / B slots, a list of gene identifiers becomes a text field that also accepts "these" (the current matches' ids). Each declared result field becomes a facet of its kind (number to histogram, group to chips, order to stepped strip, graph-level values to the run's header), so it is immediately narrowable, paintable, comparable and re-runnable.
- **A new layout.** It appears in the Lay out list in its group with a generated form; if it declares a focus node, that is a slot.
- **A new object type** (a pattern match, a time slice, a group of groups). It becomes facets: a "Member of match" group facet, a "Matched by" relational facet whose sentence and slots come from a descriptor template (a verb phrase plus typed slots), and its own card when one is tapped or is the only match. Its verbs join its card and the More list when the query matches it; the result-set bar's seven verbs never grow. An object may declare a marker in the scene that opens its card; otherwise nothing new is drawn.
- **A third-party plugin.** Readers join Open and Read as and their columns arrive as facets; data services join Open with a generated form; writers join Export with their options form; palettes join Paint by; camera presets join the View menu; commands join the rail's search.
- **The practical limit.** The scheme is as good as the facets are. Anything that is not "narrow by a value" (drawing a pattern template, placing a freeform shape) has no natural facet and goes to the 2D page or a generated form. Facet counts are recomputed on every tap, off the main thread: cheap for attributes at 10,000 nodes, expensive for routes and relational facets on large graphs, which therefore count live only up to about 2,000 nodes and above that show "counts after release" (see "Live highlight and style layers"). A rail with 60 facets needs its search and the Pinned area to stay usable.

### Why it should work

- Faceted browsing beat keyword search for open-ended exploration in Flamenco (Yee, Swearingen, Li and Hearst, "Faceted metadata for image search and browsing", CHI 2003): people preferred it strongly and felt less lost, mainly because counts on every value tell them what each next step will give. The same pattern has shipped for two decades in shopping sites, library catalogs, Lightroom's library filter and Kibana.
- Dynamic queries (Ahlberg, Williamson and Shneiderman, CHI 1992) made people faster and more accurate than a typed query form, by updating the display as a slider moves. Spotfire commercialized it in the 1990s. Brushing a histogram with live counts is the same mechanism.
- PivotGraph (Wattenberg, CHI 2006) showed that rolling a multivariate graph up by attribute values reveals structure node-link drawings hide; it is the Roll up by verb here.
- PivotPaths (Dork, Henry Riche, Ramos and Dumais, IEEE TVCG 2012) and GraphTrail (Dunne, Henry Riche, Lee, Metoyer and Robertson, CHI 2012) showed that pivoting through facets and neighbors, with a visible history of the pivots, supports exploration of linked data without getting lost; the query arrows and the "Neighbors of [...]" chip are that history.
- Gephi's filter panel (Bastian, Heymann and Jacomy, ICWSM 2009) taught network analysts attribute and topology filters as stackable steps; Kept filters under the Within chip are that model, with live counts added.
- Panels with ray pointing are the most reliable menu technique in head-mounted displays for list-like choices (Bowman and Wingrave, "Design and evaluation of menu systems for immersive virtual environments", IEEE VR 2001), and they are what Quest and visionOS ship as their own system menus. The scheme puts nearly every choice on such panels and keeps gestures for the few spatial acts (grab, move a node, sweep a region).
- Selecting nodes at real graph sizes by pointing is slow and error-prone in headsets (the functionality checklist cites 12 to 21 s per node); here selection comes mostly from values, ranges and relations, which do not depend on target size.

### What it would teach us

- Can people who have never used faceted search understand AND across facets, OR within one, and NOT by long press, from counts alone? How often do they build the query they meant?
- Does a single query with a role switch beat separate select and filter tools, or do people lose track of which role is on (especially Filter, which hides things)?
- Do relational facets ("Within 2 hops of [Medici]", "On a route from [A] to [B]") feel like facets, or do people want to act on the graph directly for structural questions?
- Is the split between free query history and project undo understood, or do people press Undo expecting the last query back?
- Do people understand that a card's verbs act on its object while the right side of the result-set bar acts on the query, from the headings alone?
- How much head turning between the rail, the bar and the graph is tolerable, and is the rail at 25 degrees left right for seated use?
- Do the live counts stay fast enough on 10,000 nodes with 40 facets, and how do people react to relational facets that count only after release?
- Do people trust a recipe that asks for its inputs by name, and do they read a step's recorded scope in History, or only its verb?
- Do people notice and understand "rolling" and "+4, -2 since Oct 3" on a reopened set, and do they read a route chip's "2 pass outside your other chips" or assume the route respects every chip?
- How many acts does each of the six stress journeys take compared with the desktop app, against the estimates above?

### Known risks

- **Filter role hides things silently.** Mitigation: Highlight is the default role and Keep returns to it; Filter always shows "N hidden" on the bar; the role is named in words as well as color; Keep as filter is an explicit, named step.
- **Two histories confuse people.** Mitigation: Back and Undo sit side by side at eye level, each naming what it takes back ("Back: Neighbors of Medici", "Undo: Paint size by PageRank"); if Undo is pressed right after only query edits, the Back label pulses and a one-time hint explains the difference.
- **A used query could be lost.** Exploring stays off the Undo list, so the design records each query where it was used: in every step's scope, the Methods view, recipes and saved views. Risk left: a query that was looked at but never used by any step is only in the query arrows, and they are not saved past the session.
- **A kept query could drift between sessions.** A relative window or a rule set re-evaluated on reopen would change evidence, filters and the Methods view without a word. Mitigation: presets count from the data's newest time and print their dates; Keep stores dates and members; rolling is an explicit switch shown on the chip; a rolling object that changed says "+4, -2 since Oct 3" on reopen; recipes ask for each window and show each scope's size against the recorded one. Risk left: a rolling object the person chose on purpose still changes, by design, and only says so.
- **Relational facets break the facet rule on purpose.** Routes and hops are found in the whole graph, while every other facet counts inside the other chips. A person may expect a route chip to respect a Connections chip. Mitigation: the chip says "in the whole graph" and how many routes pass outside the other chips, and those nodes are marked "outside". Computing routes inside the chips would give a wrong shortest route silently, which is worse than an exception that is printed.
- **Two targets on one bar.** The card's verbs and the query's verbs share the result-set bar. Mitigation: each group is headed by its target in words ("Medici:", "6 of 16 families:"), and with one match both are the same element.
- **Destructive verbs next to common ones.** Mitigation: Hide and Remove sit after a divider at the end of the More list and of every card; Remove previews and asks; Hide is one named Undo away.
- **Reading load.** Counts on every value are a lot of small text in a headset. Mitigation: large type, pinned facets on top and the rest folded by kind, values sorted by count, and the graph itself lit by pointing at a value so reading is backed by seeing.
- **Head turns between surfaces.** Mitigation: the bar and the result-set bar frame the graph above and below; the constraint bar is two fixed rows no wider than the graph, with the recovery cluster within 20 degrees of center and chips that wrap and fold instead of pushing it aside; only the rail and the right-hand panels are off to the side, they can be pulled closer or mirrored, and none sits above 10 degrees over eye level.
- **Expensive counts and highlighting on large graphs.** Mitigation: attribute counts computed incrementally off the main thread; relational and route facets above about 2,000 nodes count after release; a spinner on the chip, never a frozen panel. The graph's lighting goes through a dedicated highlight channel that graphty-element has to gain (one per-node state buffer filled from the worker's mask), updated at most every 100 ms while a brush moves. This is real engineering in graphty-element, not in the app, and without it the design's main feedback fails at 10,000 nodes.
- **Grab and node move on one pinch.** Removed: a pinch on the graph always holds the graph, and a node moves only through Move on its card, shown on the pointer. Cost: moving a node is two acts instead of one.
- **Spatial tasks feel indirect.** Picking "that cluster over there" is easier by hand. Mitigation: Draw a region and Pick nodes; a community result makes clusters tappable values.
- **Hard compound rules.** One OR bracket covers the checklist's hardest case; deeper nesting is slow. Mitigation: the assistant writes chips; deep rules are edited on the 2D page.
- **Rail overload with 40+ columns and many results.** Mitigation: search over facets and values, Pinned area, result facets grouped under their run, Hide facet.
- **Text entry.** Names, finds, formulas and notes need text. Mitigation: suggested names everywhere (from the chips: "PageRank at least 0.070"), formulas built from chips, the in-scene keyboard with a caret on every device, dictation where available, paired keyboard, laptop pairing for long text.
- **The laptop pairing needs a server graphty does not have.** A static site cannot pair two devices alone: the pairing is a WebRTC data channel introduced by a signaling endpoint graphty must host, a required build item. This cannot be fixed inside the design: until it exists, files, long report text, the provider key and clipboard copies have no laptop path, files come by URL or the headset's own file picker (the session paused), and the file hard case stays weak.
- **Vision Pro has no hover.** Mitigation: counts and names are always visible on the panels; tapping a node opens its card without changing the query.
- **Not memorable as a metaphor.** It is a plain idea. Mitigation: the vocabulary is nine inputs; Help lists them; the Tour and the first hints teach tap, back, pivot, the header menu, the range handle and keep.
- **Repetitive per-group work.** Labeling or exporting each of 12 clusters is now one For each value step with a preview; work that differs per group in ways a preview cannot express still means Step through and one loop per group.
