# Style fidelity reference extractors

Each script here writes reference scenes: what a program drew for a file, as `../scenes/<sample>/<route>.ref.json`
(`../scene.ts` describes a scene; `../routes.ts` lists the routes). The tools they drive, their versions and licenses
are in `../TOOLS.md`.

## Regenerating the scenes

The corpus samples (`../corpus-samples.ts`), from the repository root:

```bash
node graph-io/test/fidelity/references/regenerate-corpus.mjs                     # every sample and route
node graph-io/test/fidelity/references/regenerate-corpus.mjs json-vis-synth      # one sample
node graph-io/test/fidelity/references/regenerate-corpus.mjs --route gexf-file   # one route
node graph-io/test/fidelity/references/regenerate-corpus.mjs --check             # compare, write nothing
```

It overwrites the committed scenes (a scene committed on one line stays on one line), or with `--check` writes into a
temporary directory and reports each scene as `SAME` (the committed scene, apart from `provenance.generatedAt`),
`REORDERED` (the same once its nodes, edges, groups and annotations are sorted; Cytoscape lists them in another order
from one load to the next) or `DIFFERENT`. A route whose tool is not installed is reported `SKIPPED` with what it
needs. The hand-picked samples (`../samples.ts`) are regenerated by `../regenerate.sh`.

The tools are read from `$STYLE_FIDELITY_TOOLS`, by default `<main checkout>/tmp/style-fidelity/tools`, laid out as
`regenerate-corpus.mjs`'s header says. Scripts that drive a browser run under `tools/with-browser.sh`, the machine's
shared browser slots (`WITH_BROWSER` names another).

### Scenes a run does not reproduce

Every other corpus scene regenerates as `SAME` or `REORDERED`. These come out `DIFFERENT`, each for a reason in the
program or the file, not in the script:

| Scene                                                                                                  | Why                                                                                                                            |
| ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `json-vis-unix`, `-siblings`, `-transparency`, `-world`, `-lesmiserables`, `-nodelegend` (vis-network) | the files store no positions and no edge ids: vis-network lays them out with its unseeded physics and gives edges random ids   |
| `json-cyjs-synth-edges`, `json-cyjs-synth-edges-saved` (cyjs-computed)                                 | Cytoscape.js places a `haystack` edge's ends at random (edge `e8`)                                                             |
| `json-gephi-worldcup` (sigma)                                                                          | drawn by an earlier reading that took the file's own positions and sizes; `json-library.mjs` reads where sigma drew each node  |
| `gexf-hsk-chars` (gephi-noscale)                                                                       | the file stores no positions, so Gephi places the nodes at random                                                              |
| `cx-radiation-bibliography`, `cx-repro-unplaced-boxes` (cytoscape-desktop)                             | the files store no positions; Cytoscape's layout moves from one load to the next (the second's position gap was added by hand) |
| `cx2-imatinib-smpdb` (cytoscape-desktop)                                                               | its nodes carry no names, so their ids are the session's SUIDs, which change from one load to the next                         |
| `cys-luad-vest-v2` (cytoscape-desktop)                                                                 | its position gap lists the session's ten views in the order Cytoscape returns them, which changes from one load to the next    |
| `graphml-synthetic-edges` (yed-file)                                                                   | three points fall on a rounding boundary (`x.8125`) and come out 0.001 apart                                                   |

### Cytoscape desktop

Start it under servherd, with its own display, and pass its port:

```jsonc
servherd_start({ name: "cytoscape-desktop", cwd: "<repository root>",
  command: "bash graph-io/test/fidelity/references/run-cytoscape.sh {{port}} 88" })
```

```bash
CYREST_PORT=<its port> node graph-io/test/fidelity/references/regenerate-corpus.mjs --route cytoscape-desktop
```

Only one script may drive a Cytoscape at a time. `cytoscape-corpus.mjs` waits for the file's own style to reach the
view before reading it, since Cytoscape applies a CX or CX2 file's style a moment after the load returns, and reads a
session at the view of the network graph-io reads from it (build graph-io first). Two corpus files Cytoscape cannot
load are read from the same network's other encoding, kept in `cytoscape-loads/` (its `SOURCES.md` says where each
comes from).

## One file by hand

Every script takes the file as stored (a `.gz` file is read decompressed and hashed as stored):

```bash
cd graph-io/test/fidelity/references
../../../../tools/with-browser.sh node json-library.mjs vis ../../corpus/styles/json/fidelity/vis-synth.json out.ref.json
../../../../tools/with-browser.sh node json-library.mjs sigma <file> out.ref.json --canvas 800x600
node cytoscape-corpus.mjs <rest port> <file> out.ref.json
python3 gexf_file.py <file.gexf[.gz]> | node common.mjs finish out.ref.json
python3 yfiles_html_facts.py <file.graphml> | node common.mjs finish --drop-group-edges out.ref.json
PYTHONPATH=<dir holding networkx> python3 yed_gml_ext.py <file.gml> | node common.mjs finish --drop-group-edges out.ref.json
```

A Python extractor prints the scene in its program's own names; `node common.mjs finish` maps them to the scene's
names, stamps what the route can carry from `../routes.ts`, validates the scene and writes it. `--drop-group-edges`
leaves out the edges yEd draws to a group box, which a scene cannot carry (`drawio.mjs` leaves them out itself).
